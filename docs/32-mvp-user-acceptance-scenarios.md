# TimeFit MVP 사용자 테스트 시나리오

대상: `https://timefit-omega.vercel.app/`  
범위: 총관리자, 초대 직원, 직접 등록 직원, 태블릿 출퇴근·휴가, 관리자 운영 화면

> 서브 관리자 초대·권한 분리는 MVP 범위에서 제외한다. 관리자 권한은 총관리자 1인 운영을 기준으로 검증한다.

## 1. MVP 사용자와 목표

| 사용자 | 핵심 목표 |
| --- | --- |
| 총관리자 | 사업장 설정, 직원 등록, 근태·휴가 확인 및 승인, 운영 현황 확인 |
| 초대 직원 | 가입 후 초대 수락, 본인 스케줄·휴가 확인 및 신청 |
| 직접 등록 직원 | 앱 계정 없이 태블릿에서 출퇴근·휴가 신청 |
| 태블릿 운영자 | PIN과 전화번호로 빠르게 직원 근태 처리 |

## 2. 시나리오 A — 총관리자의 최초 도입

### 목적

매장 대표가 TimeFit에 가입하고 매장 근태 운영을 시작한다.

### 흐름

1. 로그인 화면에서 `회원가입`을 누른다.
2. `관리자`를 선택하고 이름, 사업장명, 이메일, 비밀번호를 입력한다.
3. 가입 후 관리자 홈에서 사업장명과 관리자 메뉴를 확인한다.
4. `운영 설정`에서 주소, 기본 휴게시간, 태블릿 PIN, 태블릿 활성화 상태를 저장한다.
5. 태블릿 URL을 복사해 매장 태블릿 브라우저에서 연다.
6. 관리자 화면을 새로고침한다.

### 기대 결과

- 사업장과 총관리자 계정이 생성된다.
- 운영 설정과 태블릿 URL이 해당 사업장에 저장된다.
- 새로고침 뒤에도 로그인·사업장 정보가 유지되고 콘솔 오류가 없다.

## 3. 시나리오 B — 앱 계정 없는 현장 직원 등록·출퇴근

### 목적

관리자가 새 아르바이트 직원을 즉시 등록하고 태블릿에서 출근을 기록한다.

### 흐름

1. 총관리자가 홈 `직원 등록하기`를 누른다.
2. 직원 이름, 전화번호, 부서, 직책, 급여 형태, 시급 또는 월급, 입사일을 입력한다.
3. `직원 등록 완료`를 누른다.
4. 직원 관리 목록에서 등록한 직원의 이름·부서·직책·급여 형태를 확인한다.
5. 태블릿 출퇴근 탭에서 PIN 필드를 누른다.
6. 자체 숫자 키패드로 PIN 4자리를 입력하고 완료한다.
7. 전화번호 끝 4자리를 동일 방식으로 입력한다.
8. `직원 확인` 후 표시된 실명을 확인하고 `출근하기`를 누른다.
9. 관리자 `출퇴근` 화면과 직원 상세를 새로고침해 상태·출근 시각을 확인한다.
10. 퇴근 시 동일 흐름으로 `퇴근하기`를 누른다.

### 기대 결과

- 직원 정보가 Supabase에 저장되고 재접속 후에도 유지된다.
- 기기 기본 키보드 대신 자체 숫자 키패드 모달을 사용한다.
- 출근·퇴근 기록이 중복 없이 저장된다.
- 관리자 목록, 출퇴근 관리, 직원 상세의 데이터가 일치한다.

## 4. 시나리오 C — 초대 수락형 직원 온보딩

### 목적

직원이 개인 계정으로 가입해 사업장에 연결된다.

### 흐름

1. 직원이 `회원가입`에서 `직원`을 선택해 이름, 이메일, 비밀번호로 가입한다.
2. 직원 홈에서 직원 고유번호를 확인한다.
3. 총관리자가 `직원 관리 → 직원 초대`에서 고유번호, 부서, 직책을 입력한다.
4. 직원이 다시 로그인하고 초대 수락 카드를 확인한다.
5. `초대 수락하기`를 누른다.
6. 직원이 내 홈, 내 스케줄, 출퇴근, 휴가 메뉴를 확인한다.

### 기대 결과

- 초대 수락 후 해당 사업장 직원으로 연결된다.
- 직원에게는 본인 메뉴만 표시되고 관리자 메뉴는 보이지 않는다.
- 관리자는 직원 목록에서 초대 수락 직원을 확인할 수 있다.

## 5. 시나리오 D — 휴가 신청과 승인

### 목적

직원 휴가 요청이 관리자 검토를 거쳐 결과로 반영된다.

### 흐름

1. 직접 등록 직원은 태블릿 `휴가 신청` 탭을 연다.
2. PIN, 전화번호 끝 8자리, 미래 날짜를 입력하고 연차/오전 반차/오후 반차 중 하나를 선택한다.
3. `휴가 신청하기`를 누른다.
4. 총관리자가 홈 또는 `휴가 · 연차`에서 새 요청의 직원명, 날짜, 종류, 일수를 확인한다.
5. 요청을 열고 관리자 메모를 남긴 뒤 승인한다.
6. 별도 요청은 반려 사유와 함께 반려한다.
7. 초대 직원은 본인 휴가 메뉴에서 자신의 결과만 확인한다.

### 기대 결과

- 연차는 1일, 반차는 0.5일로 저장된다.
- 요청 상태는 pending → approved/rejected로 변경된다.
- 승인 대기 건수와 관리자 목록이 새로고침 후 갱신된다.
- 카카오 알림톡은 현재 대기열 기록까지만 검증한다.

## 6. 시나리오 E — 관리자 운영 데이터 확인

### 목적

총관리자가 실제 데이터만으로 당일 운영 현황을 판단한다.

### 흐름

1. 관리자 홈에서 오늘 출근, 현재 근무 중, 확인 필요, 이번 달 인건비를 확인한다.
2. 출퇴근 관리에서 직원별 상태·출근/퇴근 시각·근무시간을 확인한다.
3. 직원 상세에서 입사일, 등록 급여, 실제 출퇴근 기록을 확인한다.
4. 급여 관리에서 직원별 급여 형태, 실근무시간, 예상 급여를 확인한다.
5. CSV를 다운로드해 화면의 직원명·급여·근무시간과 비교한다.

### 기대 결과

- 홈·출퇴근·직원 상세·급여 화면은 Supabase 데이터와 일치한다.
- 고정된 샘플 인원·급여·근무시간은 운영 지표에 표시되지 않는다.
- 급여는 정책 확정 전 `예상` 값으로 명확히 표시된다.

## 7. 시나리오 F — 보안과 데이터 격리

### 목적

직원 및 다른 사업장이 운영 데이터를 보지 못하게 한다.

### 흐름

1. 직원 A로 로그인해 다른 직원의 근태·휴가·전화번호를 확인하려 시도한다.
2. 다른 사업장 관리자 B로 로그인해 사업장 A의 직원·휴가·출퇴근·설정을 확인한다.
3. 사업장 B 태블릿에서 사업장 A 직접 등록 직원의 전화번호를 입력한다.
4. 태블릿에서 잘못된 PIN과 존재하지 않는 전화번호를 입력한다.

### 기대 결과

- 직원은 본인 데이터 외에 접근할 수 없다.
- 사업장 B에는 사업장 A 데이터가 노출되지 않는다.
- 잘못된 태블릿 인증은 직원 실명·근태를 노출하지 않고 저장을 차단한다.

| MVP-03 | 태블릿 숫자 키패드·출퇴근 | P0 | PASS/FAIL |

## 9. MVP 범위 제외 및 출시 보류 항목

- 서브 관리자 초대·권한 분리
- 직접 등록 직원을 앱 계정과 연결하는 UI
- 카카오 알림톡 실제 발송
- QR 카메라 실기기 인증
- 법정 수당·4대보험·세금 포함 확정 급여 계산

출시 판단: MVP-01~MVP-09가 모두 PASS일 때 총관리자 1인 운영 MVP로 출시 가능하다.
