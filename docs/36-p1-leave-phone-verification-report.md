## 상세 결과

### 1. 변경 전화번호 태블릿 인증

1. 직원 상세의 개인정보 수정에서 테스트 전화번호로 저장했다.
2. 태블릿에서 매장 PIN과 변경 전화번호 뒤 4자리를 입력했다.
3. 직원 실명 확인 화면이 표시됐다.
4. 테스트 뒤 기존 전화번호로 복구하고, 직원 상세 표시값을 확인했다.

결과: PASS. 개인정보 수정 RPC가 태블릿 인증용 `phone_last4`/`phone_last8`까지 정상 반영한다.

### 2. 휴가 승인·반려 전체 흐름

1. 태블릿에서 8/17 오전 반차를 신청했다.
2. 관리자 휴가 관리에 승인 대기 1건으로 표시됨을 확인했다.
3. 관리자 메모 `P1 승인 테스트`로 승인했다.
4. 상태가 승인 완료, 승인된 휴가 사용 합계가 1일로 변경됨을 확인했다.
5. 태블릿에서 8/18 오후 반차를 추가 신청했다.
6. 관리자 메모 `P1 반려 테스트`로 반려했다.
7. 상태가 반려로 변경되고 승인된 휴가 사용 합계가 증가하지 않음을 확인했다.

결과: PASS.

### 3. 정기휴일 차단

1. 운영 설정의 정기 휴일 기본값(일요일) 유지 상태에서 태블릿 휴가 신청을 시도했다.
2. 미래 일요일인 8/16에 연차를 신청했다.
3. 요청은 생성되지 않고 오류 알림이 표시됐다.

결과: PASS. 다만 현재 문구는 `휴가 신청 정보를 확인해 주세요.`로 일반적이므로, `정기휴일 또는 공휴일에는 휴가를 신청할 수 없어요.`로 구체화가 필요하다.

### 4. 공휴일 직접 등록 실패

1. 운영 설정 → 공휴일 직접 등록에 2026-08-19를 입력했다.
2. `+ 날짜 추가`를 클릭했다.
3. 공휴일 칩이 생성되지 않았고, 입력값도 남아 있었다.

결과: FAIL (P1). 공휴일 저장 전 단계가 실패하여 공휴일 차단 계산까지 검증할 수 없다.

## 출시 판단

- 출근·퇴근·태블릿 휴가·승인·반려·전화번호 변경 인증은 MVP 범위에서 사용 가능하다.
- **공휴일 직접 등록과 공휴일 휴가 차단은 출시 전 수정 및 재검증이 필요하다.**
- 휴일 신청 오류 문구는 기능상 차단되지만, 사용자 이해를 위해 개선이 권장된다.
