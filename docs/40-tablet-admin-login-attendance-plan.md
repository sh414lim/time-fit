# 태블릿 관리자 로그인 기반 출퇴근 전환 기획

## 목표

현재 태블릿 출퇴근의 `사업장 URL + 4자리 태블릿 PIN` 방식을 제거하고, **관리자가 로그인한 사업장으로 태블릿을 인증**한 뒤 직원이 전화번호 뒷자리만으로 출퇴근·휴가 신청을 처리하도록 전환한다.

## 결론: 권장 방식

관리자 계정을 공용 태블릿에 계속 로그인 상태로 유지하지 않는다. 대신 관리자가 한 번 로그인해 해당 사업장의 태블릿을 **기기 활성화**하고, 이후에는 태블릿 전용 기기 인증 토큰만 유지한다.

이 방식은 다음을 만족한다.

- 태블릿 PIN 입력을 없앤다.
- 태블릿이 어느 사업장 소속인지 명확하다.
- 직원은 관리자 계정이나 사업장 선택 화면에 접근하지 못한다.
- 관리자는 운영 설정에서 기기를 즉시 해제·재인증할 수 있다.
- 태블릿 분실·퇴사·매장 이동 시 권한을 회수할 수 있다.

---

## 사용자 흐름

### A. 최초 태블릿 활성화 - 관리자

1. 태블릿에서 `/tablet`을 연다.
2. “관리자 로그인으로 태블릿 연결”을 선택한다.
3. 관리자가 TimeFit 계정으로 로그인한다.
4. 관리자가 자신이 권한을 가진 사업장을 확인하거나 선택한다.
5. 기기 이름을 입력한다. 예: `성수점 카운터 태블릿`.
6. “이 사업장 태블릿으로 활성화”를 누른다.
7. 서버가 해당 사업장에 연결된 태블릿 기기 토큰을 발급한다.
8. 관리자 로그인 세션은 태블릿에서 제거하고, 태블릿 전용 기기 인증만 남긴다.
9. 태블릿은 출퇴근·휴가 신청 첫 화면으로 이동한다.

### B. 일상 출퇴근 - 직원

1. 태블릿은 이미 연결된 사업장 이름과 현재 시간을 표시한다.
2. 직원이 전화번호 뒷 4자리를 누른다.
3. 시스템이 해당 사업장의 직원을 조회한다.
4. 직원 이름 확인 모달에서 `출근` 또는 `퇴근`을 누른다.
5. 출퇴근 기록이 저장되고 완료 모달을 표시한다.

### C. 휴가 신청 - 직원

1. 태블릿에서 `휴가 신청`을 선택한다.
2. 직원이 전화번호 뒷 8자리를 누른다.
3. 날짜와 연차·오전 반차·오후 반차를 선택한다.
4. 휴일·공휴일·잔여일 기준을 검증한다.
5. 신청을 저장하고 관리자 알림 대기열에 등록한다.

### D. 기기 관리 - 관리자

1. 웹 관리자 `운영 설정 > 태블릿 출퇴근`에 진입한다.
2. 연결된 기기 목록(기기명, 마지막 사용, 활성 상태)을 확인한다.
3. 필요 시 기기 이름 변경, 연결 해제, 모든 기기 로그아웃을 실행한다.
4. 연결 해제 즉시 해당 태블릿은 출퇴근·휴가 신청을 할 수 없고 관리자 재로그인이 필요하다.

## 화면 설계

### 태블릿 미연결 화면

- 브랜드 및 안내: `이 태블릿을 사업장에 연결해 주세요.`
- CTA: `관리자 로그인으로 연결`
- 보조 안내: `연결 후에는 직원이 전화번호 뒷자리만으로 출퇴근합니다.`
- 보안 안내: `관리자 계정은 태블릿에 유지되지 않습니다.`

### 태블릿 연결 완료 화면

- 사업장 이름, 기기 이름, 현재 시간.
- 출퇴근 / 휴가 신청 탭.
- 하단 관리 메뉴: `태블릿 연결 정보` → 관리자 재인증 후 연결 해제.
- 기존 PIN 입력 UI는 완전히 제거.

### 관리자 웹 운영 설정

- 기존 `태블릿 PIN` 입력 필드를 제거.
- `태블릿 출퇴근 활성화` 토글은 유지.
- `연결된 태블릿` 목록 추가.
- `새 태블릿 연결 안내` 및 `/tablet` 접속 버튼 추가.
- `모든 태블릿 연결 해제` 위험 작업 추가.

## 권한 및 보안 설계

### 핵심 원칙

- 직원 요청은 관리자 Supabase 로그인 세션이 아니라 **태블릿 기기 토큰**으로 인증한다.
- 기기 토큰은 원문 저장 금지. DB에는 해시만 저장한다.
- 기기 토큰은 해당 사업장 출퇴근·휴가 신청 RPC에만 사용할 수 있다.
- 관리자 웹의 급여·직원 정보·운영 설정 권한으로 확장될 수 없다.

### 권한 매트릭스

| 주체 | 출퇴근 기록 | 휴가 신청 | 직원·급여 조회 | 태블릿 연결·해제 |
| --- | --- | --- | --- | --- |
| 태블릿 기기 토큰 | 가능, 연결 사업장 한정 | 가능, 연결 사업장 한정 | 불가 | 불가 |
| 전체 관리자 | 가능 | 가능 | 전체 가능 | 가능 |
| 파트 관리자 | 정책에 따라 | 정책에 따라 | 담당 범위만 | 선택적으로 가능 |
| 직원 계정 | 본인 기능만 | 본인 기능만 | 본인 정보만 | 불가 |

### 추가 보호 장치

- 기기별 만료일 또는 정기 재인증 기간 설정. 기본 90일 권장.
- 마지막 사용 시각·IP·브라우저 정보·기기 이름 감사 로그.
- 짧은 시간 내 전화번호 반복 실패 시 일정 시간 제한.
- 직원 전화번호 뒤 4자리 중복 시 이름 일부 마스킹 또는 추가 확인 절차.
- 태블릿 화면이 장시간 미사용 상태가 되어도 사업장 연결은 유지하되, 관리자 메뉴는 재로그인을 요구.

## 데이터베이스 설계

### 신규 테이블: `timefit_user_tablet_devices`

| 컬럼 | 설명 |
| --- | --- |
| `id` | 태블릿 기기 ID |
| `organization_id` | 연결 사업장 ID |
| `display_name` | 관리자가 지정한 기기 이름 |
| `token_hash` | 기기 토큰 해시 |
| `status` | `active`, `revoked`, `expired` |
| `activated_by` | 활성화한 관리자 계정 ID |
| `activated_at` | 활성화 시각 |
| `last_used_at` | 마지막 출퇴근·휴가 요청 시각 |
| `expires_at` | 기기 토큰 만료 시각 |
| `revoked_at`, `revoked_by` | 연결 해제 이력 |
| `metadata` | 브라우저·기기 식별용 최소 메타데이터 |

### 기존 테이블 변경

- `timefit_user_organization_settings.tablet_pin`: 신규 흐름 적용 후 더 이상 인증에 사용하지 않음.
- 초기 전환 기간에는 호환성을 위해 컬럼을 유지할 수 있으나, UI·RPC에서는 사용하지 않는다.
- 전환 안정화 후 별도 마이그레이션으로 제거 여부를 결정한다.

### 감사 로그 권장

`timefit_user_tablet_device_events`

- 활성화, 재인증, 사용, 실패, 연결 해제, 만료 이벤트를 기록한다.

## API / RPC 설계

### 1. `timefit_user_activate_tablet_device`

- 호출자: 로그인한 관리자.
- 입력: `organization_id`, `display_name`, `device_metadata`.
- 검증: 호출자가 해당 사업장의 관리자 권한을 가지는지.
- 결과: 원문 기기 토큰을 **한 번만** 반환.
- 후처리: 관리자 로그인 세션은 태블릿 화면에서 로그아웃 처리.

### 2. `timefit_user_get_tablet_context`

- 호출자: 기기 토큰.
- 결과: 사업장 표시 이름, 태블릿 활성 상태, 기기 이름, 공지 등 최소 정보.
- 제한: 직원·급여·관리자 개인정보 반환 금지.

### 3. `timefit_user_tablet_attendance_v2`

- 입력: `device_token`, `phone_last4`, `action`.
- 기존 `p_pin` 제거.
- 검증: 토큰 활성 상태, 사업장 연결, 만료 여부, 요청 제한, 직원 존재 여부.
- 결과: 직원명, 다음 가능 행동, 출퇴근 기록.

### 4. `timefit_user_tablet_leave_request_v2`

- 입력: `device_token`, `phone_last8`, `starts_on`, `ends_on`, `leave_type`.
- 기존 `p_pin` 제거.
- 기존 휴일·공휴일·잔여일 검증을 유지.

### 5. `timefit_user_revoke_tablet_device`

- 호출자: 해당 사업장 관리자.
- 입력: `device_id`.
- 결과: 즉시 토큰 폐기 및 태블릿 접근 차단.

## 프론트엔드 구현 범위

### 태블릿 라우트 `/tablet`

- URL의 `organization` 쿼리 파라미터 의존성 제거.
- 로컬 기기 저장소에는 사업장 UUID 대신 기기 토큰만 보관.
- 기기 토큰이 없거나 폐기된 경우 관리자 연결 화면 표시.
- PIN 상태·숫자 입력 UI 제거.
- 출퇴근과 휴가 신청 API를 v2 RPC로 교체.

### 관리자 웹

- 운영 설정에서 PIN UI·PIN 저장 로직 제거.
- 기기 목록과 연결 해제 기능 추가.
- 태블릿 URL은 공용 `https://timefit-omega.vercel.app/tablet`로 단순화.
- 새 기기 연결은 태블릿에서 관리자 로그인 후 진행한다.

## 마이그레이션 및 전환 계획

### 1단계 - 병행 도입

- 기기 테이블·v2 RPC·새 태블릿 연결 UI를 추가한다.
- 기존 PIN 기반 흐름은 제한된 기간 동안만 유지한다.
- 관리자에게 새 태블릿 연결을 안내한다.

### 2단계 - 실제 사업장 전환

- 각 사업장이 태블릿을 새 방식으로 1회 활성화한다.
- 관리자 웹에서 연결 상태와 마지막 사용 시각을 확인한다.
- 출퇴근·휴가 신청 시나리오를 실제 기기에서 확인한다.

### 3단계 - PIN 방식 종료

- PIN 기반 RPC 호출을 차단한다.
- 운영 설정과 DB에서 `tablet_pin`을 비활성화 또는 제거한다.
- 전환 완료 공지를 남긴다.

## 테스트 시나리오

| ID | 시나리오 | 기대 결과 |
| --- | --- | --- |
| T1 | 관리자가 태블릿에서 로그인·사업장 연결 | 기기 토큰 발급, 관리자 세션 제거, 출퇴근 홈 표시 |
| T2 | 연결된 태블릿에서 직원 출근·퇴근 | PIN 없이 해당 사업장에만 기록 저장 |
| T3 | 다른 사업장 직원 번호 입력 | 직원 미발견, 데이터 노출 없음 |
| T4 | 관리자 웹에서 기기 연결 해제 | 태블릿 즉시 재인증 화면으로 전환 |
| T5 | 폐기·만료 토큰으로 출퇴근 요청 | 요청 거부, 기록 생성 없음 |
| T6 | 태블릿 휴가 신청 | PIN 없이 휴가 규칙 검증·신청 저장 |
| T7 | 태블릿에서 관리자 화면 경로 접근 시도 | 관리자 정보 접근 불가 또는 관리자 로그인 요구 |
| T8 | 전화번호 반복 실패 | 요청 제한과 안전한 오류 안내 |

## 완료 기준

- [ ] 태블릿 출퇴근·휴가 신청에서 PIN을 전혀 입력하지 않는다.
- [ ] 태블릿은 관리자 활성화한 사업장에만 연결된다.
- [ ] 관리자 계정 세션은 태블릿의 일상 출퇴근 화면에 남지 않는다.
- [ ] 관리자가 웹에서 기기 상태를 보고 즉시 연결 해제할 수 있다.
- [ ] 폐기된 기기로는 출퇴근·휴가 신청 데이터가 생성되지 않는다.
- [ ] 기존 실제 사업장 데이터를 훼손하지 않는 전환·회귀 테스트를 통과한다.
