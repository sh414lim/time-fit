# TimeFit 출시 전 보완 사항 체크리스트

기준: 2026-08-19 실제 관리자·태블릿·Supabase 사용자 흐름 실행 결과

## P0 — 출시 전 반드시 보완

| 항목 | 확인 근거 | 보완 방향 | 완료 기준 |
| --- | --- | --- | --- |
| 휴가 신청 확인 모달 복원 | 태블릿에서 날짜·유형 선택 후 `휴가 신청하기`를 누르면 직원·날짜·유형을 재확인하는 단계 없이 바로 저장 성공 모달이 노출됨 | 저장 전 `임성환 / 2026-08-26 / 연차 1일`처럼 신청 내용을 보여 주고 `신청 완료`를 눌러야 실제 RPC를 호출하도록 분리 | 취소 시 요청 미생성, 완료 시에만 승인 대기 요청 생성 |
| 일급제 전용 단가·계산 | 일급제는 선택·저장은 가능하나 예상 급여 계산이 구현되지 않음 | `daily_wage` 필드, 근무 완료일 수 집계, `일급 × 실제 근무일` 예상액, CSV 반영 추가 | 시급·일급·월급 직원의 예상 급여가 각각 올바른 기준으로 표시 |
| 실제 태블릿 기기 분리 검증 | 이번 연결 테스트는 같은 Chrome 프로필에서 수행되어 관리자 웹 로그인 상태가 태블릿 연결 흐름에 영향을 받을 수 있음 | 별도 Android 태블릿/APK 또는 별도 브라우저 프로필에서 관리자 연결 후 웹 관리자 세션 유지 여부 검증 | 태블릿 연결 후 관리자 웹 세션이 유지되고, 태블릿에는 관리자 세션이 남지 않음 |
| 휴가·공휴일 정책 회귀 테스트 | 공휴일·정기휴일·보상 설정은 존재하지만 실제 신청 차단/차감/보상 적립 조합 전체를 이번 실행에서 다루지 않음 | 공휴일 휴가 신청, 정기휴일, 공휴일 근무 후 퇴근, 대체휴무/추가 유급휴가 적립을 테스트 데이터로 검증 | 운영 설정과 실제 잔여 연차·적립 이력이 일치 |

## P1 — MVP 운영 직후 보완

| 항목 | 내용 | 완료 기준 |
| --- | --- | --- |
| 관리자 요청 검토 UX | `요청 확인하기` 버튼과 개별 요청 상세에서 어떤 요청을 검토하는지 더 명확한 식별 정보(직원 전화번호 일부, 신청 시각, 근무 충돌)를 제공 | 관리자 실수 승인 가능성 감소 |
| 휴가 승인 후 스케줄 충돌 표시 | 승인된 휴가일에 근무가 이미 등록된 경우 관리자에게 충돌 배지와 조치 선택 제공 | 승인 전후 스케줄 상태를 명확히 확인 |
| 출퇴근 중복 방지 안내 | 출근/퇴근 요청 재시도 시 서버 오류 코드별 안내와 마지막 기록 시각 표시 | 중복 클릭·네트워크 재시도에도 혼란 없는 UX |
| 태블릿 연결 관리 | 기기 이름 변경, 연결 만료 기준, 마지막 사용 시각, 원격 연결 해제 UI 강화 | 분실·교체 태블릿 관리 가능 |
| 급여 화면 상세화 | 시급제는 근무시간·단가·예상액, 월급제는 등록월급·입퇴사 일할 여부, 일급제는 근무일 수·일급을 행별로 분해 표시 | 관리자 검산 가능 |

## P2 — 정식 운영 확장

| 항목 | 내용 |
| --- | --- |
| 세금·4대보험·퇴직금 | 급여 확정 후 별도 계산 엔진·세무 정책·전문가 검토 기반으로 도입 |

| 다중 관리자 역할 | 매장 관리자·본사 관리자·조회 전용 역할 및 사업장 범위 권한 분리 |
| 감사 로그 | 직원 정보, 급여, 휴가 승인, 운영 설정의 변경 주체·시각·이전값 기록 |

## 운영 데이터 정리

이번 실제 테스트로 아래 데이터가 생성·변경되었다.

- `매장 태블릿` 연결 기기 1건
- 임성환 출근·퇴근 기록 1건 (2026-08-19)
- 임성환 연차 1일 신청 및 승인 1건 (2026-08-26)

테스트 데이터를 운영 기준으로 유지할지, 관리자 화면에서 개별 정정·삭제할지는 사업장 담당자가 결정한다. 삭제·정정은 근태·휴가 이력에 영향을 주므로 사전 확인 후 처리한다.
