# 사용자 시나리오 브라우저 테스트 및 피드백

> 테스트 일시: 2026-08-09 · 대상: Vercel 프로덕션 TimeFit · 테스트 환경: 데스크톱 및 390 × 844 모바일 뷰포트

## 1. 테스트 범위

`03-user-scenarios.md`의 관리자·직원 핵심 흐름 중 현재 테스트 버전에서 실행 가능한 UI 흐름을 점검했다.

| 시나리오 | 결과 | 확인 내용 |
|---|---|---|
| 관리자: 직원 목록 → 직원 상세 | 통과 | 직원 관리의 `상세` 버튼으로 김민지 상세 화면 진입 |
| 관리자: 스케줄 → 직원 상세 | 통과 | 스케줄의 이준호 행을 눌러 이준호 상세 화면 진입 |
| 관리자: 모바일 스케줄 조회 | 부분 통과 | 날짜 스트립, 근무·휴무·연차 요약, 직원별 근무 행 표시 |
| 직원: 모바일 내 스케줄 조회 | 통과 | 월간 캘린더와 등록된 개인 일정 목록 표시 |
| 직원: 휴가 신청 진입 | 통과 | 휴가 유형·기간·사유를 입력하는 바텀시트 표시 |
| 직원: QR 출퇴근 진입 | 통과 | QR 출근 화면과 카메라 호출 행동 표시 |
| 브라우저 오류 점검 | 통과 | 확인된 콘솔 오류·경고 없음 |

## 2. 통과한 경험

### 관리자

- 직원 목록, 출퇴근 목록, 스케줄 행, 급여 행, 휴가 내역 행을 누르면 직원 상세로 연결되는 정보 구조가 일관적이다.
- 직원 상세에서 근무 상태, 월 근무시간, 연차 잔여, 예상 급여, 최근 스케줄과 출퇴근 기록을 한 번에 파악할 수 있다.
- 스케줄 모바일 화면은 날짜 선택 → 당일 요약 → 직원별 근무 카드 순서라, 관리자가 필요한 인력을 빠르게 훑기 좋다.

### 직원

- 직원 홈과 `내 스케줄`에서 오늘/이번 달 개인 일정만 노출돼 정보 범위가 명확하다.
- 휴가 신청은 잔여 연차와 승인 대기 수를 먼저 보여 준 뒤 신청 폼을 열어, 신청 전 판단에 필요한 정보가 충분하다.
- 출퇴근 화면은 QR 행동과 이번 주 근무기록을 함께 보여 줘 기록 후 결과를 확인할 수 있다.

## 3. 개선 피드백

### P1. 관리자 모바일 하단 탭 수 조정

**관찰:** 관리자 모드에는 홈, 출퇴근, 스케줄, 휴가, 급여, 직원 관리의 6개 하단 탭이 있으나, 현재 모바일 하단 영역은 5열 기준이다. 작은 화면에서 탭 폭이 줄거나 배치가 불안정해질 수 있다.

**권장안:** 하단 탭은 `홈 / 출퇴근 / 스케줄 / 더보기` 4개로 축소하고, `더보기` 안에 휴가·연차, 급여 관리, 직원 관리를 넣는다. 직원 모드는 현재처럼 4개 탭을 유지한다.

**완료 기준:** 390px 너비에서 모든 탭이 한 줄에 안정적으로 표시되고, 최소 터치 영역 44px 이상을 확보한다.

### P1. 스케줄 날짜 선택을 실제 상태와 연결

**관찰:** 모바일 날짜 스트립은 표시되지만, 날짜를 누른 뒤 선택 상태 및 직원 목록·요약 수치가 바뀌는 데이터 흐름은 아직 목업이다.

**권장안:** `selectedDate` 상태를 두고 날짜별 `WorkSchedule` 데이터를 조회한다. 날짜 선택 시 활성 스타일, 근무 인원, 휴무/연차 수, 직원 행을 함께 갱신한다.

**완료 기준:** 다른 날짜를 선택하면 날짜 헤더와 스케줄 목록이 300ms 이내에 일관되게 갱신된다.

### P2. QR 실제 인식 검증 필요

**관찰:** QR 출근 화면과 카메라 진입 버튼은 확인했지만, 이번 브라우저 테스트에서는 카메라 권한을 승인하지 않아 실제 QR 인식·출퇴근 기록 완료까지는 검증하지 않았다.

**권장안:** 실제 모바일 기기 또는 HTTPS 테스트 환경에서 유효/만료/다른 근무지 QR 세 종류를 스캔한다. 인식 미지원 브라우저의 사진 인증 흐름도 함께 점검한다.

**완료 기준:** 유효 QR은 한 번만 출근·퇴근 처리되고, 중복 및 만료 QR은 명확한 오류 메시지를 보여 준다.

### P2. 테스트 데이터와 실제 API 연결

**관찰:** 화면 전환·폼 진입은 가능하지만 현재 프론트 상태 기반 목업이므로 새로고침 뒤 직원 등록, 휴가 신청, 출퇴근 상태가 유지되지 않는다.

**권장안:** 구현된 Express/Prisma API를 연결하고, 조직·직원·스케줄·근태·휴가 데이터부터 PostgreSQL로 저장한다.

**완료 기준:** 직원 등록, 휴가 신청, 스케줄 변경, 출퇴근 결과가 새로고침 뒤에도 유지되며 관리자·직원 화면에 같은 데이터가 반영된다.

### P3. 직원 상세의 근거 데이터 표시

**관찰:** 직원 상세의 근무시간·연차·예상 급여 정보가 유용하지만, 계산 기준이나 마지막 갱신 시각을 바로 알 수 없다.

**권장안:** 각 요약 카드에 `집계 기간`, `마지막 갱신`, `상세 보기`를 제공한다. 급여는 확정 전 `예상 금액` 표기를 유지한다.

## 4. 다음 테스트 우선순위

1. 관리자 모바일 탭을 `더보기` 구조로 개편하고 390px/360px에서 재검증한다.
2. 스케줄 날짜 선택과 실제 데이터 필터링을 연결한다.
3. 실기기 카메라로 QR 출퇴근 정상·오류 시나리오를 점검한다.
4. PostgreSQL 연결 뒤 관리자 승인 → 직원 화면 반영의 종단 간 테스트를 수행한다.
