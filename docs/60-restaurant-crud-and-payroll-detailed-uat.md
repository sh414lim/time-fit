# 레스토랑 운영 CRUD·급여 계산 상세 UAT 시나리오

목적: 관리자 웹과 매장 태블릿에서 생성·수정·삭제되는 모든 핵심 정보가 동일 사업장 데이터로 저장되고, 출퇴근·휴가·급여 계산에 일관되게 반영되는지 검증한다.

## 1. 공통 테스트 기준

| --- | --- |
| 사업장 | 테스트 레스토랑 |
| 구분 | 홀(파랑), 주방(주황), 바(보라) |

| 급여 시간 단위 | 30분, 올림 |

### 공통 확인 규칙

- 모든 저장 버튼은 처리 중 비활성화되고 연속 클릭해도 한 건만 저장된다.
- 성공·오류 모달은 최상위에 표시되고, 확인 후 현재 페이지·모달·스크롤 위치를 유지한다.
- 저장 후 목록/대시보드/상세/스케줄에 즉시 반영되고 새로고침 뒤에도 유지된다.
- 삭제는 최종 확인 뒤에만 실행하며, 테스트 전용 데이터만 삭제한다.
- 계좌번호·주민등록번호는 테스트용 가상값만 사용한다. 저장 후 원문이 다시 노출되면 실패다.

## 2. 관리자 운영 설정 CRUD

운영 설정은 모든 직원·스케줄·태블릿·급여 계산의 기준값이다. 각 케이스는 **값 변경 → 저장 → 화면 이동 → 복귀 → 새로고침 → 실제 업무 데이터 반영** 순서까지 확인한다.

### O-00. 사업장 기본 정보와 저장 범위

1. 사업장 표시 이름, 주소, 기본 휴게시간을 수정하고 저장한다.
2. 홈 헤더, 태블릿 좌측 배너, 운영 설정 입력값에 같은 사업장명이 표시되는지 확인한다.
3. 다른 사업장 관리자 계정으로 로그인해 위 변경값이 보이지 않는지 확인한다.
4. 사업장 주소를 빈 값으로 저장할 때 허용/검증 기준이 명확한지 확인한다.
5. 휴게시간을 0, 60, 90, 비정상값(-1/과도한 값)으로 입력해 검증 메시지를 확인한다.

기대 결과: 설정은 현재 사업장에만 저장되며, 유효하지 않은 값은 저장되지 않고 현재 입력 화면을 유지한다.

### O-01. 직원 구분 생성·수정·삭제

1. 운영 설정 > 직원 구분 관리에서 `홀`, `주방`, `바`를 각기 다른 색상으로 생성한다.
2. 직원 등록 화면과 직원 상세 수정 화면을 열어 세 구분이 선택지에 나타나는지 확인한다.
3. `바`를 선택한 직원 B-01을 저장한다.
4. 직원 목록, 실시간 출퇴근, 스케줄 행에서 이름 이니셜 대신 구분명/색상 아이콘이 표시되는지 확인한다.
5. 사용 중인 `바` 구분을 삭제하려고 시도한다.
6. 확인 후 B-01이 `미분류`로 안전하게 이동하는지, 스케줄 집계도 미분류로 변경되는지 확인한다.

기대 결과: 구분별 데이터가 사업장 단위로만 유지되며, 기존 직원 수정 화면도 현재 등록된 구분을 초기 선택값으로 정확히 표시한다.

### O-02. 근무 형태·휴게시간 설정

1. `브런치 근무 10:00~19:00`를 추가한다.
2. 스케줄 등록 화면을 열어 새 근무 형태가 즉시 선택 가능한지 확인한다.
3. 기본 휴게시간을 60분에서 90분으로 수정해 저장한다.
4. 시급제 직원의 예상 실근무시간 및 급여 계산에 변경값이 반영되는지 확인한다.
5. 테스트용 근무 형태를 삭제하고 기존 스케줄의 표시/수정 가능 여부를 확인한다.

기대 결과: 삭제된 근무 형태가 이미 배정된 일정 자체를 깨뜨리지 않으며, 신규 등록 선택지에서만 제거된다.

### O-03. 연차·월차·휴일·보상 정책

1. 1년 미만 월차 자동 발생을 켜고 `월 1일`, `1일 이상 근무` 조건을 저장한다.
2. 정기휴일을 일요일로 지정하고, 공휴일 날짜를 1개 추가한다.
3. 공휴일 근무 보상을 `대체휴무 적립`, 정기휴일 근무 보상을 `추가 유급휴가 적립`으로 저장한다.
4. 해당 날짜에 테스트 직원의 근무·출퇴근을 만들고 정책에 맞는 잔여 휴무/휴가가 부여되는지 확인한다.
5. 공휴일과 정기휴일이 겹치는 날은 공휴일 정책이 우선 적용되는지 확인한다.

기대 결과: 정책 저장 뒤 공휴일 칩이 즉시 생성되며, 휴가 신청 가능일과 보상 잔여일이 서버 계산 결과와 일치한다.

### O-04. 연차 부여 정책 상세

| 케이스 | 설정/입력 | 검증 결과 |
| --- | --- | --- |
| 기본 연차 | 12개월 재직, 연차 15일 | 입사 1년을 충족한 직원에게 연차 정책 기준이 표시됨 |
| 입사 1년 미만 월차 | 자동 발생 ON, 매월 1일 | 조건 충족 월마다 월차 발생 이력과 잔여 일수에 반영됨 |
| 월차 근무 조건 미충족 | 월 근무일 0일 | 월차가 발생하지 않음 |
| 수동 연차 | 직원 상세에서 +3일 부여, 사유 입력 | 자동 발생과 분리된 추가 부여 이력이 남음 |
| 반차 사용 | 오전/오후 반차 승인 | 잔여 연차가 0.5일만 차감됨 |
| 반려 | 휴가 요청 반려 | 잔여 연차·스케줄·급여 계산에 차감 반영되지 않음 |

실행 절차:

1. 연차 부여 일수(예: 15), 재직 조건(예: 12개월), 월차 자동 발생 여부와 조건을 저장한다.
2. 입사일이 서로 다른 테스트 직원을 기준으로 예상 발생일을 계산한다.
3. 직원 상세의 `발생 / 사용 / 대기 / 잔여` 값, 연차 이력, 휴가 신청 화면을 비교한다.
4. 연차 정책을 변경한 뒤 기존 부여분이 소급 변경되는지 또는 이후 발생분에만 적용되는지 정책 문구와 실제 결과를 확인한다.

### O-05. 정기휴일·공휴일 설정 상세

1. 정기휴일로 일요일과 월요일을 각각 선택/해제하고 저장한다.
2. 다음 달 공휴일을 날짜 입력 후 `+ 날짜 추가`로 등록한다.
3. 같은 날짜를 중복 추가해 중복 칩·중복 보상이 생기지 않는지 확인한다.
4. 등록한 공휴일 칩을 삭제하고 저장한 뒤 달력과 휴가 신청 가능일에서 제거되는지 확인한다.
5. `휴가 일수 계산에서 정기휴일·공휴일 제외`를 ON/OFF로 바꾸고, 휴가 기간에 공휴일/정기휴일이 포함된 요청의 차감 일수를 비교한다.

| 휴가 요청 예시 | 제외 ON 기대값 | 제외 OFF 기대값 |
| --- | --- | --- |
| 금~일(토·일 중 일요일 정기휴일) 3일 범위 | 2일 차감 | 3일 차감 |
| 공휴일 1일 단독 | 0일 차감 또는 신청 차단 정책 안내 | 1일 차감 |
| 공휴일+정기휴일 중첩 | 공휴일 우선으로 1회만 제외 | 실제 날짜 수 기준 차감 |

기대 결과: 공휴일은 저장 직후 칩·달력·계산 기준에 나타나며, 중복 등록·삭제·정책 반영이 모두 서버 데이터 기준으로 일관된다.

### O-06. 휴일 근무 보상 정책 상세

1. 공휴일 근무 보상을 `보상 없음`으로 저장하고, 공휴일 출근/퇴근 완료 뒤 출퇴근 기록만 남는지 확인한다.
2. 공휴일 근무 보상을 `대체휴무 적립`으로 바꾸고 동일 조건에서 직원별 대체휴무 잔여일과 이력을 확인한다.
3. 공휴일 근무 보상을 `추가 유급휴가 적립`으로 바꾸고 휴가 잔여·이력을 확인한다.
4. 정기휴일 근무도 위 세 옵션으로 같은 검증을 반복한다.
5. 공휴일과 정기휴일이 겹치는 날 근무 후 공휴일 기준만 한 번 적용되는지 확인한다.
6. 동일 출퇴근 기록의 재저장/재동기화 뒤 보상이 중복 적립되지 않는지 확인한다.

기대 결과: 퇴근 완료 시점에만 보상이 한 번 적립되며, 직원 상세와 휴가 관리의 이력이 일치한다.

### O-07. 태블릿 출퇴근 설정

1. 태블릿 출퇴근 활성화를 OFF로 저장하고 `/tablet`에서 출퇴근/휴가 제출이 차단되는지 확인한다.
2. ON으로 복구한 뒤 태블릿 전용 주소와 현재 연결된 사업장명을 확인한다.
3. 관리자 로그인으로 태블릿을 연결하고, 연결 태블릿 목록에 기기명·마지막 사용·만료일이 표시되는지 확인한다.
4. 특정 기기의 연결 해제를 실행하고 해당 태블릿에서 재인증 화면으로 이동하는지 확인한다.
5. 직원 전화번호를 변경한 뒤 기존/신규 끝자리 인증 결과를 확인한다.

### O-08. 출퇴근 기반 급여 계산 설정

1. 계산 단위를 1/5/10/15/30/60분으로 각각 저장한다.
2. 처리 방식을 올림/반올림/버림으로 각각 저장한다.
3. 같은 실제 근무 기록(예: 7시간 10분)에 대해 보정 시간이 아래와 같은지 확인한다.

| 설정 | 기대 보정 시간 |
| --- | --- |
| 30분 올림 | 7시간 30분 |
| 30분 반올림 | 7시간 |
| 30분 버림 | 7시간 |
| 15분 올림 | 7시간 15분 |

4. 시급제 예상 급여, 월별 집계, 직원 상세 근무시간이 동시에 갱신되는지 확인한다.
5. 설정을 변경해도 이미 확정된 급여 지급 이력은 임의로 변경되지 않는지 확인한다.

### O-09. 급여일 및 알림 채널 설정

1. 급여일을 1일, 25일, 31일로 저장한다.
2. 이메일, 카카오 알림톡, 푸시 알림 채널을 각각 ON/OFF로 저장한다.
3. 채널별 발송 설정 미완료 상태에서 `설정 필요` 안내가 보이는지 확인한다.
4. 테스트용 급여일에 발송 대기열을 생성하고, 대상 직원·사업장·급여 월·채널이 정확한지 확인한다.
5. 동일 급여일 재실행 시 동일 직원·채널의 대기열이 중복 생성되지 않는지 확인한다.
6. 31일 설정인 달(30일/2월)에는 월말 발송으로 보정되는 정책이 적용/안내되는지 확인한다.

### O-10. Toss Place·매출 동기화 설정

1. 표시 이름, 서비스 ID, 서비스 코드, 판매점 ID를 입력해 저장한다.
2. Access Key/Secret은 입력 후 원문이 다시 노출되지 않는지 확인한다.
3. 자동 동기화를 ON/OFF하고 현재 상태가 매출 분석 화면에 표시되는지 확인한다.
4. `지금 동기화` 실행 후 동기화 상태(대기/진행/성공/실패), 마지막 성공 시각, 실패 원인이 기록되는지 확인한다.
5. 동기화된 주문·매출 데이터는 DB에서 조회되고 화면 재방문 시 외부 API를 매번 직접 호출하지 않는지 확인한다.
6. 다른 사업장에는 해당 매출 연결 정보와 주문 데이터가 노출되지 않는지 확인한다.

## 3. 직원 등록·수정·삭제 및 개인정보

### E-01. 직접 등록

1. 직원 관리 > 직원 등록을 연다.
2. H-01의 이름, 전화번호, 홀, 서버, 입사일, 시급제/12,000원을 입력한다.
3. 등록 버튼을 두 번 빠르게 누른다.
4. 성공 모달을 닫고 목록을 새로고침한다.
5. 이름·전화번호·구분·직책·급여형태가 한 건만 보이는지 확인한다.

기대 결과: 로딩 상태 중 버튼이 비활성화되고 중복 직원이 생성되지 않는다.

### E-02. 초대 등록과 직접 등록 연동

1. 동일 전화번호 또는 고유 번호를 가진 미연결 직원을 초대한다.
2. 직원이 회원가입/초대를 수락한다.
3. 관리자 목록에서 별도 직원 행이 생기지 않고 기존 직원이 계정과 연결되는지 확인한다.
4. 역할, 구분, 급여, 입사일이 보존되는지 확인한다.

### E-03. 직원 정보 수정

1. H-01 상세 모달을 열고 정보 수정을 누른다.
2. 홀 → 주방, 서버 → 보조 셰프, 전화번호 끝자리 1234 → 4321로 수정한다.
3. 저장 후 상세 모달을 닫았다가 다시 연다.
4. 목록, 출퇴근, 스케줄에 `주방 · 보조 셰프`가 표시되는지 확인한다.
5. 태블릿에서 기존 1234 인증은 실패하고 4321 인증이 가능해야 한다.

기대 결과: 저장 시 구분값이 미분류로 초기화되지 않으며, 관련 화면에 즉시 동기화된다.

### E-04. 급여 지급 정보

1. 은행명 `테스트은행`, 계좌번호 `1234567890`, 주민등록번호 형식의 가상값을 입력한다.
2. 지급 정보 저장을 누르고 성공 모달이 직원 상세 모달보다 위에 표시되는지 확인한다.
3. 모달을 닫은 뒤 다시 수정 화면을 연다.
4. 계좌번호/주민번호 원문은 보이지 않고 등록 상태만 표시되는지 확인한다.
5. 빈 값으로 다시 저장해 기존 민감 정보가 의도치 않게 삭제되지 않는지 확인한다.

### E-05. 직원 삭제/비활성화

1. 테스트 전용 H-01을 비활성화 또는 삭제한다.
2. 직원 목록, 태블릿 인증, 신규 스케줄 선택지에서 제외되는지 확인한다.
3. 과거 출퇴근·휴가·급여 기록은 감사 목적으로 유지되는지 확인한다.

## 4. 스케줄 CRUD·구분별 인원 집계

### S-01. 복수 직원·복수 날짜 등록

1. H-01과 K-01, 오늘+2일과 오늘+3일을 함께 선택한다.
2. H-01은 오픈, K-01은 마감으로 각각 등록한다.
3. 저장 전 생성 예정 건수가 `직원 수 × 날짜 수`와 일치하는지 확인한다.
4. 저장 후 일간, 주간, 월간 보기를 순서대로 연다.

기대 결과: 실제 생성 건수와 화면 표기가 일치한다.

### S-02. 구분별 집계

1. 오늘+2일에 홀 2명, 주방 1명, 휴무 1명, 연차 1명을 배정한다.
2. 일간 상단에서 `홀 2명`, `주방 1명`이 색상별 칩으로 보이는지 확인한다.
3. 휴무·연차는 근무 인원 집계에서 제외되는지 확인한다.
4. 주간 카드와 월간 달력의 같은 날짜도 동일한 합계를 보이는지 확인한다.

### S-03. 수정·중복·삭제

1. H-01 오픈 근무를 마감 근무로 수정한다.
2. 동일 직원·동일 날짜에 다시 등록을 시도한다.
3. 중복 덮어쓰기/차단 안내가 명확한지 확인한다.
4. 테스트 일정 한 건을 삭제한다.
5. 삭제 직후 현재 날짜/주/월 화면을 유지한 채 집계와 행이 갱신되는지 확인한다.

## 5. 출퇴근·급여 계산 상세 검증

### P-01. 시급제 30분 올림 계산

전제: 시급 12,000원, 오픈 09:00~18:00, 휴게 60분, 30분 단위 올림.

| 케이스 | 실제 기록 | 계산 대상 시간 | 기대 급여 |
| --- | --- | --- | --- |
| 정상 | 09:00~18:00 | 8시간 | 96,000원 |
| 조기 퇴근 | 09:00~17:10 | 7시간 10분 → 7시간 30분 | 90,000원 |
| 지각+정상 퇴근 | 09:20~18:00 | 7시간 40분 → 8시간 | 96,000원 |
| 연장 근무 | 09:00~18:20 | 8시간 20분 → 8시간 30분 | 102,000원 |

실행 절차:

1. 각 케이스에 맞는 출근·퇴근 기록을 태블릿에서 생성한다.
2. 관리자 출퇴근 관리에서 원시 출근/퇴근 시각을 확인한다.
3. 급여 관리에서 보정 근무시간, 시간당 단가, 예상 금액을 확인한다.
4. 계산 단위를 15분·반올림으로 바꾼 뒤 동일 기록의 결과가 정책에 맞게 달라지는지 확인한다.

### P-02. 일급제·월급제·연봉제

| 형태 | 검증 기준 | 기대 결과 |
| --- | --- | --- |
| 일급제 | K-01이 출근·퇴근을 모두 완료 | 근무 완료일 1일당 등록 일급이 반영되고 미출근일은 반영되지 않음 |
| 월급제 | B-01 월급 3,000,000원 | 등록 월급 기준 예상 금액과 실제 출퇴근 정보가 함께 표시됨 |
| 연봉제 | M-01 연봉 42,000,000원 | 월 환산 기준(3,500,000원)이 명확히 표시되고 연봉 원금은 유지됨 |

### P-03. 휴가·휴일의 급여 영향

1. 승인 연차 1일, 오전 반차 0.5일, 무급 휴무 1일을 각각 만든다.
2. 급여 화면에서 각 상태가 실제 근무시간/예상 금액에 어떻게 반영되는지 확인한다.
3. 공휴일 근무·정기휴일 근무의 대체휴무/추가 유급휴가 적립을 확인한다.
4. 근로계약별 수당 규칙은 MVP 자동 계산 범위 외임을 안내하는 문구가 있는지 확인한다.

## 6. 태블릿 출퇴근·휴가 제출 시나리오

### T-01. 출근·퇴근

1. 관리자 연결이 된 태블릿에서 출퇴근 탭을 연다.
2. 4자리 번호 패드를 열고 H-01의 끝자리 1234를 입력한다.
3. 입력 완료 후 입력 칸에 값이 즉시 표시되는지 확인한다.
4. 직원 확인 모달의 직원명·구분·오늘 일정을 확인한다.
5. 출근 최종 확인 → 완료 모달을 확인한다.
6. 같은 번호 재출근은 `이미 출근 처리됨`으로 안내되는지 확인한다.
7. 퇴근도 동일 절차로 실행하고 P-01의 원시 시간이 관리자에 보이는지 확인한다.

### T-02. 휴가 신청

1. 휴가 탭으로 전환했을 때 출퇴근 4자리 입력값이 재사용되지 않는지 확인한다.
2. 휴가용 번호 입력, 달력 모달의 날짜 선택, 연차/오전 반차/오후 반차 선택을 수행한다.
3. 최종 확인 모달에서 직원명, 날짜, 유형, 차감 일수를 확인한다.
4. 제출 후 입력 초기화와 성공 모달을 확인한다.
5. 관리자 웹의 승인 대기 → 승인 → 직원 잔여 연차·스케줄·급여 반영 순서를 확인한다.

## 7. 급여 알림·화면 유지·오류 복구

### N-01. 급여일 알림

1. 운영 설정에서 알림일 25일 및 이메일/카카오/푸시 채널을 선택해 저장한다.
2. 발송 대기열이 대상 직원·급여 월·채널 단위로 생성되는지 확인한다.
3. 같은 날짜에 재실행해 중복 발송 대기열이 생성되지 않는지 확인한다.
4. 채널 설정 미완료 상태는 발송 실패가 아니라 `설정 필요` 상태로 기록되는지 확인한다.

### N-02. 화면 전환·비동기 처리

1. 직원 저장, 일정 저장, 휴가 승인, 급여 설정 저장 직후 각각의 성공 모달을 닫는다.
2. 홈으로 강제 이동하지 않고 현재 작업 화면·스크롤·필터가 유지되는지 확인한다.
3. 다른 브라우저 탭으로 10초 이동 후 돌아온다.
4. 데이터가 다시 로드되더라도 빈 화면/무한 로딩 없이 마지막 정상 화면을 유지하는지 확인한다.
5. 네트워크 오류를 유발해 재시도 후 중복 생성이 없는지 확인한다.

## 최종 통과 기준

- 등록·수정·삭제 각각이 Supabase에 1회만 반영된다.
- 구분, 스케줄, 출퇴근, 휴가, 급여의 연쇄 데이터가 동일 사업장 기준으로 일치한다.
- P-01의 계산 결과가 표의 기대 금액과 모두 일치한다.
- 민감 정보 원문은 저장 이후 표시되지 않는다.
- 운영 데이터 테스트는 반드시 테스트 전용 직원과 일정으로 마친 뒤 삭제/비활성화한다.
