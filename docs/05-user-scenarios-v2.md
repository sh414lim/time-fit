# TimeFit 2차 사용자 시나리오

> 기준 버전: 현재 Vercel 프로덕션 배포본 · 작성일: 2026-08-09
> 목적: 모바일 관리자 흐름과 역할별 업무 연결을 구체화하고, API 연동 전후의 완료 기준을 정의한다.

## 1. 2차 시나리오의 변경점

| 항목 | 1차 | 2차 반영 |
|---|---|---|
| 관리자 모바일 탐색 | 주요 메뉴가 하단에 모두 노출 | `홈 / 출퇴근 / 스케줄 / 더보기` 4개 탭으로 단순화 |
| 스케줄 조회 | 고정된 당일 목록 | 날짜 선택에 따라 근무·휴무·연차 집계와 직원 목록 변경 |
| 직원 상세 진입 | 직원 관리 중심 | 출퇴근·스케줄·휴가·급여 목록의 직원 행에서 공통 진입 |
| 역할 구분 | 화면별 기능 범위 정의 | 상단 모드 전환과 모바일 하단 메뉴까지 역할별로 분리 |

## 2. 관리자 모바일 시나리오

### M-01. 출근 직후 이슈 파악 → 직원 상세 확인

**목표:** 관리자가 1분 안에 오늘 확인이 필요한 직원을 찾고, 필요한 조치를 결정한다.

1. 관리자는 모바일에서 `관리자` 모드로 진입한다.
2. 홈의 `확인 필요` 카드에서 지각·미출근 수를 확인한다.
3. 실시간 출퇴근 목록에서 박서연 또는 최도윤 행을 누른다.
4. 직원 상세에서 오늘 상태, 출근 시각, 이번 달 근무시간, 연차 잔여, 최근 기록을 확인한다.
5. 다음 행동을 선택한다.
   - 출근 시각이 맞지 않음: 출퇴근 수정 요청 확인
   - 근무 배정이 잘못됨: 이번 주 근무 일정 수정
   - 휴가 충돌: 최근 연차 요청 열기

**화면 상태 변화**

```text
관리자 홈 → 실시간 출퇴근 직원 행 → 직원 상세 → 일정 수정/휴가 요청 검토
```

**완료 기준**

- 직원 행 전체가 터치 대상이며, 별도의 작은 상세 버튼을 정확히 누르지 않아도 된다.
- 직원 상세에서 돌아가기를 누르면 직원 관리 목록으로 복귀한다.
- 관리자에게만 급여 예상액이 노출된다.

### M-02. 날짜별 인력 배치 점검 → 근무 추가

**목표:** 특정 날짜의 인력 부족을 확인하고 근무를 추가한다.

1. 하단의 `스케줄`을 누른다.
2. 날짜 스트립에서 대상 일자를 누른다.
3. 상단 요약의 `근무 / 휴무 / 연차` 인원을 확인한다.
4. 직원별 카드에서 근무 시간과 근무 유형을 확인한다.
5. 인력이 부족하면 `근무 추가`를 누른다.
6. 직원, 시작·종료 시간 등을 입력하고 저장한다.
7. 직원 상세 또는 해당 날짜 목록에서 새 일정을 재확인한다.

**분기**

| 조건 | 관리자 행동 | 시스템 반응 |
|---|---|---|
| 연차자가 있는 날 | 연차 요약 확인 후 대체 인력 선택 | 연차 휴가가 근무와 다르게 표기 |
| 휴무만 있는 날 | 근무 추가로 인력 배정 | 빈 일정 안내 대신 추가 흐름 제공 |
| 다른 날짜 확인 필요 | 좌우 화살표 또는 날짜 스트립 사용 | 선택 날짜·집계·직원 목록 동시 변경 |

**완료 기준**

- 날짜를 바꾸면 기존 날짜의 직원 행이 남지 않는다.
- 선택된 날짜는 파란색 활성 상태로 명확히 표시된다.
- 390px 화면에서 날짜 7개와 스케줄 카드가 겹치지 않는다.

### M-03. 더보기에서 관리 업무 이동

**목표:** 모바일 하단 탐색을 복잡하게 만들지 않으면서 모든 관리자 기능에 도달한다.

1. 관리자는 하단의 `더보기`를 누른다.
2. 바텀시트에서 `휴가 · 연차`, `급여 관리`, `직원 관리` 중 하나를 선택한다.
3. 선택한 화면에서 직원 행을 누르면 직원 상세로 이동한다.

**완료 기준**

- 더보기 메뉴는 손가락으로 누르기 쉬운 큰 행으로 제공한다.
- 메뉴 선택 뒤 바텀시트는 자동으로 닫힌다.
- 현재 선택한 관리 메뉴는 하단 탐색과 충돌하지 않는다.

### M-04. 휴가 요청 검토 → 직원 정보 맥락 확인

**목표:** 관리자가 휴가 요청만 보고 승인하지 않고, 근무 및 잔여 연차 맥락을 확인한다.

1. 더보기 → `휴가 · 연차`로 이동한다.
2. 휴가 사용 내역에서 요청 직원 행을 누른다.
3. 직원 상세에서 주간 근무 일정과 연차 잔여를 확인한다.
4. `최근 연차 · 요청` 영역을 열어 신청일·유형·상태를 검토한다.
5. 승인 대기 요청에서 승인 또는 반려를 선택한다.

**완료 기준**

- 승인 전에는 연차 잔여와 해당 날짜 근무를 모두 확인할 수 있다.
- 승인·반려 결과는 직원 휴가 화면에 동일한 상태로 표시된다. *(API 연동 후 검증)*

## 3. 직원 모바일 시나리오

### E-05. 오늘 근무 확인 → QR 출근

**목표:** 직원이 출근에 필요한 정보와 행동을 한 화면 흐름에서 완료한다.

1. 직원은 `직원` 모드로 전환한다.
2. 내 홈의 오늘 근무 카드에서 근무지, 시작·종료 시각, 휴게시간을 확인한다.
3. `출퇴근` 탭으로 이동한다.
4. `QR 출근`을 누르고 카메라 권한을 허용한다.
5. 매장 QR을 스캔한다.
6. 성공 시 버튼은 `QR 퇴근`으로 변경되고, 주간 기록에 출근 시각이 표시된다.

**오류 시나리오**

| 상황 | 안내 및 행동 |
|---|---|
| 카메라 권한 미허용 | 브라우저 권한 설정 안내와 수정 요청 경로 제공 |
| QR을 찾지 못함 | 스캔 프레임 안내, 재시도, 테스트용 사진 인증 |
| 이미 출근함 | 기존 출근 시각과 퇴근 버튼 표시 |
| 오늘 스케줄 없음 | 예외 근무 요청 또는 관리자 문의 표시 |

### E-06. 스케줄 변경 확인 → 휴가 신청

**목표:** 직원이 개인 일정 충돌을 발견했을 때 관리자에게 일관된 요청을 보낸다.

1. `내 스케줄`에서 월간 캘린더와 등록된 근무 일정을 확인한다.
2. 근무가 어려운 날짜를 확인하고 `휴가` 탭으로 이동한다.
3. 현재 연차 잔여일과 승인 대기 건을 확인한다.
4. `휴가 신청`을 눌러 휴가 유형, 시작일, 종료일, 사유를 작성한다.
5. 신청을 전송하고 상태가 `승인 대기`로 표시되는지 확인한다.
6. 관리자가 처리하면 내 휴가 내역과 내 스케줄에서 결과를 확인한다.

**완료 기준**

- 직원에게 다른 직원의 근무·연차·급여 정보가 노출되지 않는다.
- 신청 화면에서 휴가 유형과 날짜가 명확히 구분된다.
- 승인 상태가 바뀌면 잔여 연차와 캘린더가 함께 갱신된다. *(API 연동 후 검증)*

## 4. 관리자-직원 연결 시나리오

### C-01. 휴가 승인 반영

```text
직원: 휴가 신청
  → 관리자: 승인 대기 확인
  → 관리자: 일정/잔여 연차 검토
  → 관리자: 승인
  → 시스템: 연차 사용량과 해당일 스케줄 갱신
  → 직원: 휴가 상태 및 내 캘린더 확인
```

**데이터 검증**

- `LeaveRequest.status`가 `PENDING → APPROVED`로 한 번만 전이된다.
- 승인 트랜잭션에서 `LeaveBalance.usedAmount`가 함께 갱신된다.
- 승인 이벤트는 `ApprovalLog`에 기록된다.

### C-02. 스케줄과 출퇴근의 연결

```text
관리자: 스케줄 게시
  → 직원: 내 스케줄 확인
  → 직원: QR 출근/퇴근
  → 시스템: 실제 근무시간 계산
  → 관리자: 출퇴근·직원 상세·급여 예상에 반영
```

**데이터 검증**

- 한 직원·한 근무일의 `WorkSchedule`과 `AttendanceRecord`는 각각 하나만 존재한다.
- 지각 판정은 정책의 유예 시간과 예정 출근 시각을 사용한다.
- 급여 예상액은 마감되지 않은 근태 기록을 별도 상태로 표시한다.
