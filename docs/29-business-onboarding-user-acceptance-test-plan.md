# TimeFit 실제 사업장 온보딩 사용자 수용 테스트 기획

목적: 실제 매장이 TimeFit를 처음 도입할 때, 총관리자 가입부터 서브 관리자·직원 등록, 태블릿 출퇴근, 휴가 승인, 운영 데이터 확인까지의 전 과정을 사용자 관점에서 검증한다.

대상: Production `https://timefit-omega.vercel.app/`

## 1. 역할 정의와 현재 범위

| 역할 | 실제 업무 권한 | 현재 제품 상태 |
| --- | --- | --- |
| 총관리자 | 사업장 생성, 운영 설정, 관리자/직원 관리, 급여, 승인, 태블릿 관리 | `manager` 역할로 구현됨 |
| 서브 관리자 | 직원·스케줄·출퇴근·휴가 승인 관리, 사업장 핵심 설정/급여는 제한 | **별도 역할 미구현**. 현재는 `manager`와 동일 권한만 가능 |
| 직원 | 본인 일정·근태·휴가 조회/신청 | `employee` 역할로 구현됨 |
| 직접 등록 직원 | 계정 없이 태블릿 출퇴근·휴가 신청 | 구현됨 |

테스트 원칙:

- 서브 관리자 권한 분리 기능이 배포되기 전에는, 총관리자와 동일 `manager` 권한을 부여하는 운영 대체 절차만 검증한다.
- 실제 역할 분리 후에는 `SUB-*` 케이스를 P0 승인 기준으로 전환한다.

## 2. 테스트 사업장 구성

| 식별자 | 계정/데이터 | 목적 |
| --- | --- | --- |
| 사업장 A | 실제 도입 테스트 사업장 | 메인 온보딩·운영 테스트 |
| 총관리자 O1 | 새 이메일로 가입 | 사업장 생성과 모든 관리 기능 |
| 서브 관리자 M1 | 새 이메일로 가입 | 관리자 위임/권한 검증 |
| 초대 직원 E1 | 새 이메일로 가입 | 초대 수락형 직원 흐름 |
| 직접 등록 직원 D1 | 전화번호만 등록 | 태블릿 중심 현장 직원 흐름 |
| 사업장 B / 총관리자 O2 | 별도 테스트 사업장 | 사업장 간 격리 |

권장 테스트 데이터:

- 사업장명: `테스트 매장 A-실행일`
- 서브 관리자/직원 전화번호: 서로 다른 실제 형식 11자리
- 태블릿 PIN: 테스트 전용 4자리
- 휴가: 오늘 이후 서로 다른 3개 날짜

## 3. 사용자 시나리오

### S-01. 총관리자의 최초 사업장 생성

**사용자 목표:** 매장 대표가 가입 즉시 자기 사업장을 열고 운영 준비를 끝낸다.

1. O1이 `회원가입`에서 관리자 선택
2. 이름, 사업장명, 이메일, 비밀번호 입력 후 가입
3. 홈에서 사업장명·관리자 전용 메뉴 확인
4. 운영 설정에서 주소, 휴게시간, 태블릿 PIN, 태블릿 활성화 저장
5. 새로고침 후 설정과 로그인 상태 유지 확인

성공 기준: 사업장·관리자 멤버십·태블릿 설정이 생성되고, 다른 사업장 데이터가 보이지 않는다.

### S-02. 총관리자의 서브 관리자 등록/위임

**사용자 목표:** 대표가 매장 책임자에게 일상 운영 권한을 위임한다.

현재 대체 절차:

1. M1이 관리자 유형으로 가입해 별도 테스트 사업장을 생성한다.
2. 총관리자 O1이 M1을 사업장 A에 연결하는 관리자 초대/역할 선택 UI가 존재하는지 확인한다.
3. UI가 없다면 현재 기능 제약으로 `BLOCKED` 처리한다.

향후 구현 수용 기준:

- 총관리자가 직원 관리에서 M1 이메일/고유번호를 선택하고 `서브 관리자` 역할을 부여할 수 있다.
- M1은 사업장 A만 접근한다.
- M1은 직원·스케줄·출퇴근·휴가를 관리할 수 있다.
- M1은 사업장 소유권, 총관리자 변경, 결제·급여 마감, 다른 관리자 삭제를 수행할 수 없다.

### S-03. 초대 수락형 직원 등록

**사용자 목표:** 앱을 쓰는 직원이 고유번호로 자기 사업장에 연결된다.

1. E1이 직원 유형으로 가입하고 고유번호 확인
2. O1 또는 M1이 직원 관리에서 고유번호·부서·직책 입력 후 초대
3. E1이 로그인해 초대 수락
4. E1이 내 홈에서 자기 사업장·스케줄·휴가 메뉴 확인

성공 기준: E1은 본인 데이터만 보고, 관리자는 E1을 직원 목록에서 조회한다.

### S-04. 직접 등록 직원과 태블릿 설정

**사용자 목표:** 앱 계정이 없는 현장 직원도 바로 근태를 기록한다.

1. O1/M1이 D1의 이름, 전화번호, 부서, 직책, 급여, 입사일 등록
2. 태블릿 URL을 별도 태블릿/브라우저에서 열기
3. PIN·전화번호 끝 4자리를 자체 숫자 키패드로 입력
4. D1 이름 확인 후 출근 기록

성공 기준: D1의 출근 기록이 저장되고 관리자 출퇴근 화면과 직원 상세에 보인다.

### S-05. 일일 근태 운영

**사용자 목표:** 총관리자/서브 관리자가 당일 인력 상태를 보고 대응한다.

1. D1과 E1의 출근·퇴근 기록 생성
2. O1/M1이 홈과 출퇴근 관리 확인
3. 근무 중/퇴근 완료/미출근 필터 확인
4. 직원 행 클릭 → 상세에서 실제 기록 확인

성공 기준: 홈 요약·출퇴근 목록·직원 상세 데이터가 서로 일치한다.

### S-06. 휴가 신청과 승인

**사용자 목표:** 직원이 휴가를 신청하고 관리자가 승인/반려한다.

1. D1이 태블릿에서 PIN·전화번호 끝 8자리·날짜·휴가 유형 입력
2. E1이 앱에서 휴가 신청
3. O1/M1이 휴가·연차에서 두 요청 확인
4. 하나는 승인 메모와 함께 승인, 하나는 반려 사유와 함께 반려
5. 직원별 화면에서 결과 확인

성공 기준: 상태, 날짜, 일수, 메모, 검토자가 저장되고 타 직원에게 노출되지 않는다.

### S-07. 급여·운영 데이터 확인

**사용자 목표:** 관리자가 실제 등록 급여와 근태를 바탕으로 월 운영 현황을 확인한다.

1. O1이 급여 관리 진입
2. D1/E1의 급여 형태, 실제 근무시간, 예상 급여 확인
3. CSV 다운로드 후 직원명·급여·근무시간 확인
4. 직원 상세와 홈 인건비 요약 비교

성공 기준: 화면과 CSV는 실제 Supabase 데이터만 사용하며, 예상값은 정책 미확정 상태임을 표시한다.

### S-08. 사업장과 권한 격리

**사용자 목표:** 다른 매장이나 일반 직원이 사업장 운영 정보를 볼 수 없다.

1. O2로 사업장 B 생성
2. O2/M1/E1 각각 사업장 A 데이터 접근 시도
3. 사업장 B 태블릿에 사업장 A 직원 번호 입력

성공 기준: 직원·휴가·근태·설정·전화번호·급여가 타 사업장에 노출되지 않는다.

## 5. 최종 승인 기준

출시 가능:

- P0 케이스 모두 PASS
- 총관리자 가입, 직원 초대, 직접 등록, 태블릿 출퇴근, 휴가 승인, 데이터 격리 완료
- 관리자 화면에 실제 데이터만 노출
- 새로고침 후 로그인·업무 데이터가 유지되고 콘솔 오류 없음

출시 보류:

- 태블릿 근태/휴가 저장 실패
- 직원·사업장 데이터가 노출됨
- 관리자 화면에 샘플 데이터를 운영 데이터처럼 표시함
- 서브 관리자 분리가 출시 필수 요구사항인데 역할 모델이 없는 상태

## 6. 서브 관리자 기능 구현 백로그

1. `timefit_user_role`에 `owner`, `manager`, `employee` 또는 별도 권한 테이블 도입
2. 총관리자 전용: 사업장 소유권, 결제, 관리자 권한 변경, 급여 마감
3. 서브 관리자: 직원·스케줄·근태·휴가 운영 권한
4. 관리자 초대 화면: 이메일/고유번호 입력, 역할 선택, 초대 취소
5. RLS와 Edge Function에서 역할별 권한 검증
6. SUB-01/SUB-02 자동·브라우저 통합 테스트 추가
