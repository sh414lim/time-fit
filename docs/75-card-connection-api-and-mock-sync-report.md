# 카드 자동 연결 API 및 Mock 동기화 1차 구현 보고서

## 구현 범위

이번 단계에서는 실제 카드사 중계사(Hyphen) 연동 전에 전체 연결 수명주기를 검증할 수 있도록 서버 API와 Mock Provider를 구현했다.

1. 카드 연결 생성
   - `POST /api/card-connections`
   - 사업장 소유자만 연결을 생성할 수 있다.
   - 실제 카드번호·비밀번호·인증서를 데이터베이스에 저장하지 않는다.
2. 카드 자산 조회 및 선택
   - `POST /api/card-connection-assets`의 `discover`, `select` 액션
   - Mock Provider에서 카드 목록을 조회하고 선택된 카드만 동기화 대상으로 연결한다.
3. 카드 사용내역 동기화
   - `POST /api/card-sync`
   - 동기화 실행 이력을 생성하고, 승인·부분취소·매입 이벤트를 원장 RPC로 전달한다.
   - 동일 연결·동기화 모드·시간 구간 요청은 멱등성 키로 중복 실행을 방지한다.
4. 연결 상태 조회
   - `GET /api/card-connections`
   - 연결 상태, 마지막 성공 시각, 마지막 오류 코드, 연결된 카드 수를 반환한다.

## 권한 및 보안

- 모든 API는 Supabase 사용자 Access Token을 요구한다.
- 카드 연결 생성과 카드 선택은 `owner` 권한만 허용한다.
- 동기화는 `owner`, `manager` 권한에 허용한다.
- 서버의 Service Role 키는 권한 확인과 서버 데이터 조작에만 사용한다.
- 카드 거래 원장 반영은 사용자 JWT로 보안 RPC를 호출하여 사업장 권한 검증을 다시 거친다.
- Hyphen 비밀키가 설정되지 않은 환경에서는 실제 Hyphen 연결 생성이 차단된다.

## Mock 검증 시나리오

Mock Provider는 다음 거래를 반환한다.

- 승인: 120,000원
- 부분취소: 20,000원
- 매입: 120,000원

원장 RPC는 세 이벤트를 하나의 거래 그룹으로 묶고 최종 순액을 100,000원, 상태를 `partially_cancelled`로 계산한다. 동일 이벤트를 다시 가져와도 원장에는 중복 적재하지 않는다.

- API 인증 거부 테스트 통과

- 중복 백필 요청의 기존 실행 반환 테스트 통과

- `vercel.json` 구문 검사 통과

## 현재 제한과 다음 단계

- 현재 `/api/card-sync`는 동기화 실행 레코드를 만들지만 Mock 처리는 요청 안에서 수행한다. 장시간 카드 조회를 위한 실제 비동기 워커와 예약 실행은 다음 단계에서 구현한다.
- Hyphen 실서비스 어댑터는 계약 후 발급되는 API 명세·테스트 키·허용 IP 정책을 확보한 뒤 Mock Provider와 동일한 인터페이스로 추가한다.
- 자동 연결 화면에서 연결 생성 → 카드 선택 → 최초 백필 → 진행 상태 확인 흐름을 연결해야 한다.
- 운영 배포 전에 Supabase 마이그레이션 3개를 원격 DB에 먼저 적용해야 한다.

## 배포 순서

1. 원격 Supabase 백업 및 마이그레이션 적용
2. 원격 RPC 및 RLS 스모크 테스트
3. Vercel 환경변수 등록
4. Preview 배포에서 Mock/샌드박스 연결 검증
5. Hyphen 샌드박스 승인 후 실서비스 어댑터 활성화
6. Production 배포 및 승인·취소·부분취소·중복수집 회귀 테스트
