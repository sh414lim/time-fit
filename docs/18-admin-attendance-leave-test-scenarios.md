# TimeFit 관리자 · 출퇴근 · 연차 신청 플로우 테스트 시나리오

## 1. 목적과 범위

관리자 웹 설정부터 태블릿 출퇴근, 태블릿 휴가 신청, 관리자 확인·승인까지 한 사업장 범위 안에서 검증한다.

- 운영 URL: `https://timefit-omega.vercel.app/`
- 태블릿 URL: `https://timefit-omega.vercel.app/tablet?organization={organizationId}`
- 검증 역할: 관리자 1명, 직원 1명 이상
- DB 대상: Supabase `timefit_user_*` 테이블
- 실제 알림톡은 연동 전이므로 `queued` 알림 로그 생성까지를 통과 기준으로 한다.

## 2. 테스트 데이터

| 구분 | 값 | 용도 |
| --- | --- | --- |
| 태블릿 PIN | 4자리 테스트 PIN | 출퇴근·휴가 신청 인증 |
| 직원 전화번호 | 서로 다른 뒷 4자리·뒷 8자리 | 직원 식별 |
| 관리자 전화번호 | 전체 번호 등록 | 휴가 알림 대기열 수신 대상 |
| 휴가 날짜 | 오늘 이후 날짜 | 연차/반차 신청 |

테스트 종료 후에는 운영 데이터와 혼동되지 않도록 테스트 휴가·근태 기록을 별도 표시하거나 정리한다.

## 3. 시나리오 A — 관리자 운영 환경 준비

### A-01. 관리자 로그인과 권한

1. 관리자 계정으로 로그인한다.
2. `홈`, `출퇴근`, `스케줄`, `휴가 · 연차`, `급여 관리`, `직원 관리`, `운영 설정` 메뉴를 확인한다.
3. 직원 계정으로 재로그인해 관리자 전용 메뉴가 노출되지 않는지 확인한다.

기대 결과: 관리자만 운영·급여·직원 관리 기능에 접근한다.

### A-02. 태블릿 설정 저장

1. `운영 설정`을 연다.
2. 사업장 표시명, 주소, 기본 휴게시간, 태블릿 PIN을 입력한다.
3. `태블릿 출퇴근 활성화`를 켜고 저장한다.
4. 새로고침 후 값이 유지되는지 확인한다.
5. 표시된 태블릿 URL을 새 탭에서 연다.

기대 결과: `timefit_user_organization_settings`에 사업장별 설정이 저장되고 로그인 없는 태블릿 화면이 표시된다.

### A-03. 직원·관리자 전화번호 등록

1. `직원 관리`에서 직원 상세를 연다.
2. `전화번호 등록`에서 전체 번호를 저장한다.
3. 관리자 본인 직원 상세에서도 수신용 전체 번호를 저장한다.

기대 결과:

- 직원: `phone_last4`, `phone_last8`이 출퇴근/휴가 인증에 사용 가능해진다.
- 관리자: 휴가 신청 시 알림 로그가 `queued` 대상이 된다.

## 4. 시나리오 B — 태블릿 출퇴근

### B-01. 직원 확인과 출근

1. 태블릿의 `출퇴근` 탭을 연다.
2. 태블릿 PIN과 직원 전화번호 뒷 4자리를 입력한다.
3. `직원 확인`을 누른다.
4. 직원 이름과 `출근하기` 버튼이 표시되는지 확인한다.
5. `출근하기`를 누른다.

기대 결과: 성공 메시지가 보이며 `timefit_user_attendance_records`에 당일 `checked_in_at`, `source=tablet_phone_last4` 기록이 생성된다.

### B-02. 관리자 출근 기록 확인

1. 관리자 웹의 `출퇴근` 화면을 연다.
2. 새로고침 후 해당 직원의 상태와 출근 시각을 확인한다.
3. 직원 상세의 최근 출퇴근 기록도 확인한다.

기대 결과: 당일 기록이 해당 사업장과 해당 직원에만 표시된다.

### B-03. 퇴근

1. 태블릿에서 같은 PIN·전화번호 뒷 4자리로 다시 직원 확인을 한다.
2. 버튼이 `퇴근하기`로 바뀌었는지 확인한다.
3. 퇴근 처리 후 관리자 화면을 새로고침한다.

기대 결과: 기존 당일 기록의 `checked_out_at`만 갱신되며 중복 출근 기록은 생성되지 않는다.

### B-04. 출퇴근 실패 케이스

| 케이스 | 입력/행동 | 기대 결과 |
| --- | --- | --- |
| PIN 오류 | 잘못된 4자리 PIN | 인증 거부 메시지, 기록 미생성 |
| 직원 번호 오류 | 존재하지 않는 뒷 4자리 | 직원 미확인 메시지, 기록 미생성 |
| 태블릿 비활성화 | 관리자가 설정에서 비활성화 | 인증 거부 |
| 중복 퇴근 | 퇴근 완료 뒤 재시도 | 중복 처리 차단 |

## 5. 시나리오 C — 태블릿 연차·반차 신청

### C-01. 연차 신청

1. 태블릿에서 `휴가 신청` 탭을 연다.
2. PIN, 직원 전화번호 뒷 8자리, 미래 날짜를 입력한다.
3. 휴가 종류를 `연차`로 선택하고 신청한다.

기대 결과:

- `timefit_user_leave_requests`에 `status=pending`, `source=tablet`, `amount=1`로 저장된다.
- `timefit_user_notification_logs`가 관리자 번호 등록 시 `queued`, 미등록 시 `disabled`로 생성된다.
- 화면은 실제 알림 상태에 맞는 안내를 보여 준다.

### C-02. 오전/오후 반차 신청

1. C-01과 다른 미래 날짜를 선택한다.
2. `오전 반차`, `오후 반차`를 각각 신청한다.

기대 결과: 각 요청의 `amount`가 `0.5`로 저장된다.

### C-03. 휴가 신청 실패 케이스

| 케이스 | 입력/행동 | 기대 결과 |
| --- | --- | --- |
| 과거 날짜 | 오늘 이전 날짜 선택 | 입력/서버 검증에서 차단 |
| PIN 오류 | 잘못된 태블릿 PIN | 신청 미생성 |
| 번호 오류 | 존재하지 않는 뒷 8자리 | 신청 미생성 |
| 비활성 태블릿 | 태블릿 기능 끔 | 신청 미생성 |

## 6. 시나리오 D — 관리자 휴가 확인·승인

### D-01. 승인 대기 목록 확인

1. C-01 또는 C-02 완료 직후 관리자 웹에서 `휴가 · 연차`를 연다.
2. 새로고침하고 신청 직원, 날짜, 유형, 일수, 상태를 확인한다.
3. 신청 상세를 연다.

기대 결과: 태블릿 신청이 `승인 대기`로 보이며 다른 사업장 데이터는 노출되지 않는다.

### D-02. 승인

1. 승인 메모를 입력한다.
2. `승인하기`를 누른다.
3. 목록과 직원 휴가 내역을 새로고침해 상태를 확인한다.

기대 결과: 요청이 `approved`가 되고 검토자·검토 시각·메모가 영속화된다.

### D-03. 반려

1. 새 휴가 신청을 하나 만든다.
2. 관리자 상세에서 반려 사유를 입력하고 `반려`한다.
3. 목록과 직원 화면에서 결과를 확인한다.

기대 결과: 요청이 `rejected`가 되고 승인 대기 목록에서 제외된다.
