# TimeFit 네이티브 태블릿 UI/UX 개편 설계

## 1. 개편 목표

웹 `/tablet` 화면의 시각적 방향을 유지하되, 네이티브 태블릿에서 더 빠르고 안정적으로 사용할 수 있는 전용 경험을 구축한다.

- 반복 문구 제거 및 화면 정보 계층 단순화
- 10~13인치 태블릿 가로 화면에 최적화
- 직원이 3초 안에 출퇴근·휴가 흐름을 이해하도록 설계
- 물리 키보드 없이도 사용할 수 있는 대형 터치 인터랙션 제공
- 토스 스타일의 여백, 명확한 상태, 낮은 인지 부하 적용

## 2. 핵심 UX 원칙

1. 한 화면에는 하나의 핵심 행동만 둔다.
2. 같은 의미의 제목과 안내 문구를 반복하지 않는다.
3. 모든 터치 대상은 최소 56dp, 주요 버튼은 64dp 이상으로 제공한다.
4. 입력 중에는 시스템 키보드 대신 앱 전용 숫자 키패드를 사용한다.
5. 성공·실패·처리 중 상태를 동일한 위치의 모달 또는 인라인 알림으로 표시한다.
6. 입력 완료 후 전화번호·직원 정보는 즉시 초기화한다.
7. 출퇴근과 휴가 신청은 동일한 레이아웃 규칙을 공유한다.

## 3. 화면 구조

### 3.1 공통 레이아웃

- 바깥 배경: `#F4F8FC` 계열의 밝은 블루 그라데이션
- 중앙 컨테이너: 최대 1,440×860px, radius 32px, 흰색 카드
- 좌측 브랜딩 패널: 전체 폭의 35~38%, TimeFit 블루 그라데이션
- 우측 기능 패널: 전체 폭의 62~65%, 콘텐츠 최대 폭 760px
- 태블릿 세로 모드에서는 좌측 패널을 숨기고 기능 패널을 전체 화면으로 전환

### 3.2 좌측 브랜딩 패널

반복되는 제목을 제거하고 다음 정보만 노출한다.

- TimeFit 로고
- `레오핏테크 · 버터블라 태블릿` 사업장/기기명
- 화면별 한 줄 핵심 문구
  - 출퇴근: `빠르고 정확한 직원 출퇴근`
  - 휴가: `간편한 휴가 신청`
- 보조 설명: `관리자 연결이 완료된 사업장 전용 태블릿입니다.`

### 3.3 우측 헤더

- 작은 라벨: `TIMEFIT TABLET`
- 대제목: 출퇴근 화면은 `출퇴근 기록`, 휴가 화면은 `휴가 신청`
- 우측 상태 배지: `● 연결됨`
- 본문에 동일한 대제목을 다시 표시하지 않는다.

## 4. 출퇴근 화면 설계

### 4.1 탭

- 출퇴근 / 휴가 신청 2개 탭을 하나의 pill 컨테이너 안에 배치
- 활성 탭: 흰색 배경, TimeFit blue 텍스트, 약한 shadow
- 비활성 탭: 투명 배경, 회색 텍스트
- 아이콘과 텍스트 사이 간격 8px

### 4.2 입력 영역

- 섹션 제목: `전화번호 뒷 4자리로 확인하세요`
- 보조 문구: `확인 후 출근 또는 퇴근 버튼이 표시됩니다.`
- 라벨: `전화번호 뒷 4자리`
- 입력 카드: 높이 76px 이상, radius 16px, 키패드 아이콘 우측 배치
- placeholder: `숫자를 입력해 주세요`
- 하단 보조 문구: `직원 본인의 전화번호 끝 4자리`

### 4.3 직원 확인 상태

- 직원 확인 전: `직원 확인` 버튼 비활성화
- 직원 확인 중: 버튼 내부 spinner + `확인 중`
- 확인 성공: 직원명, 현재 상태, 다음 행동을 한 카드에서 표시
- 주요 CTA: `출근하기` 또는 `퇴근하기`
- 보조 CTA: `다시 입력`

## 5. 휴가 신청 화면 설계

### 5.1 입력 순서

1. 전화번호 뒷 8자리
2. 휴가 날짜
3. 휴가 종류
4. 휴가 신청하기

### 5.2 휴가 날짜

- 날짜 입력 카드는 높이 68~76px
- 캘린더 아이콘은 우측 고정
- 오늘 이전 날짜 선택 불가
- 선택 전: `연도 · 월 · 일`
- 선택 후: `2026년 8월 25일`

### 5.3 휴가 종류 카드

3개 카드를 동일 폭으로 배치한다.

- 연차: `1일`
- 오전 반차: `0.5일`
- 오후 반차: `0.5일`

활성 카드:

- 배경 `#EAF3FF`
- 테두리 `#3182F6` 2px
- 텍스트 `#2877DC`

### 5.4 제출 상태

- 입력 부족: CTA 비활성화
- 제출 중: `신청 중` + spinner
- 성공: `휴가 신청이 완료됐어요.` 모달
- 실패: 원인별 안내 문구와 `다시 확인` 버튼

## 6. 전용 숫자 키패드 설계

### 6.1 호출 방식

- 전화번호 입력 카드를 탭하면 bottom sheet 또는 중앙 modal 표시
- 시스템 키보드는 호출하지 않음
- 키패드가 열린 동안 배경은 40% dim 처리

### 6.2 키패드 구성

```
┌──────────────────────┐
│ 전화번호 뒷 4자리     │
│      4724             │
├──────┬──────┬──────┤
│  1   │  2   │  3   │
│  4   │  5   │  6   │
│  7   │  8   │  9   │
│ 취소 │  0   │  ⌫   │
├──────────────────────┤
│       입력 완료       │
└──────────────────────┘
```

- 버튼 최소 크기 72×64dp
- 버튼 간격 10~12dp
- 숫자 font 24~28sp, weight 700
- 삭제는 아이콘 중심, 텍스트와 혼용하지 않음
- 입력 길이 초과 시 버튼 비활성화
- 입력 완료 후 원래 입력 카드에 값 반영

## 7. 중복 문구 제거 기준

- 화면 대제목은 헤더에 한 번만 표시
- 좌측 패널의 핵심 문구와 우측 기능 제목은 서로 다른 의미로 작성
- `휴가 신청`이 헤더·본문·버튼에 연속 반복되지 않도록 문구를 다음처럼 분리
  - 헤더: `휴가 신청`
  - 안내: `전화번호와 날짜를 입력해 주세요.`
  - CTA: `신청하기`
- 동일한 설명 문구는 한 화면에서 한 번만 노출

## 10. 시각 디자인 기획

### 10.1 디자인 방향

현재 화면은 큰 파란 영역과 기본 Material 입력 컨트롤이 혼합되어 있어, 정보는 보이지만 제품 완성도가 낮고 오래된 인상을 준다. 개편 버전은 **밝은 금융 앱의 신뢰감**, **매장 태블릿의 빠른 조작성**, **한 번에 한 행동만 보이는 단순함**을 결합한다.

- 키워드: `Clear`, `Confident`, `Calm`, `Tactile`
- 참고 감성: 토스의 넉넉한 여백과 명확한 상태 표현
- 피해야 할 요소: 과도한 그라데이션, 진한 테두리 남용, 작은 회색 안내문 반복, 기본 시스템 버튼의 혼용

### 10.2 컬러 시스템

파란색은 브랜드와 주요 행동에만 사용한다. 넓은 화면 전체를 강한 파랑으로 채우지 않고, 브랜드 패널과 CTA·선택 상태에 집중한다.

| 역할 | 색상 | 사용처 |
|---|---|---|
| Brand blue | `#3182F6` | 주요 CTA, 선택 상태, 로고 |
| Deep blue | `#1B64DA` | 눌림 상태, 강조 아이콘 |
| Blue surface | `#EFF6FF` | 선택 카드, 입력 포커스 배경 |
| Canvas | `#F6F9FC` | 화면 바깥 배경 |
| Surface | `#FFFFFF` | 콘텐츠 카드 |
| Text primary | `#171A21` | 제목, 수치 |
| Text secondary | `#6B7684` | 설명, 보조 정보 |
| Border | `#E6EBF1` | 비활성 입력·카드 |
| Success | `#16A56A` | 연결·저장 완료 |
| Danger | `#E5484D` | 인증·저장 오류 |

### 10.3 타이포그래피와 밀도

- 폰트: Android에서는 Pretendard 또는 Noto Sans KR 계열을 번들 적용한다.
- 화면 제목: 38sp / 700 / 자간 -1.2
- 섹션 제목: 24sp / 700 / 자간 -0.6
- 본문: 16sp / 500
- 입력 값: 26sp / 700
- 보조 안내: 14sp / 500 / line-height 1.5
- 대문자 라벨 `TIMEFIT TABLET`은 12sp / 800 / tracking 1.4만 사용한다.
- 한 화면의 정보 묶음은 3개 이내로 제한하고, 묶음 간 간격은 28~36dp로 통일한다.

### 10.4 레이아웃과 카드

- 외부 캔버스에는 아주 약한 블루 그라데이션만 사용한다.
- 메인 셸: radius 36dp, border 1dp `#E7EEF7`, shadow는 아래 방향 24dp·8% opacity로 제한한다.
- 좌측 패널: 단색에 가까운 blue를 기본으로 하고, 하단으로 갈수록 8%만 밝아지는 미세한 gradient를 사용한다.
- 우측 콘텐츠는 카드 안에 다시 카드가 겹쳐 보이지 않도록 한다. 탭·입력·선택 카드만 표면을 구분한다.
- 입력 필드는 기본 상태에서 그림자를 쓰지 않고, 포커스 상태에만 blue ring 3dp를 적용한다.

### 10.5 컴포넌트 디자인 규칙

#### 헤더

- 제목은 한 번만 노출한다.
- 연결 상태는 작은 green pill로 표현한다.
- 상태 pill은 아이콘 8dp + 텍스트로 구성하고, 의미 없는 테두리를 넣지 않는다.

#### 세그먼트 탭

- 연한 회색 트레이 위에 활성 탭만 흰색 표면으로 띄운다.
- 활성 탭은 blue 텍스트와 2dp 미만의 부드러운 shadow를 적용한다.
- 탭 높이 68dp, 아이콘·텍스트 중앙 정렬을 유지한다.

#### 입력 필드

- 라벨은 필드 위에 고정한다. placeholder와 라벨을 같은 문구로 반복하지 않는다.
- 입력 값이 없을 때: `숫자를 입력해 주세요`
- 입력 값이 있을 때: 숫자를 크게 표시하고 우측에 keypad 아이콘을 둔다.
- 입력 필드 전체가 버튼처럼 작동한다.

#### CTA

- 한 화면에 primary CTA는 한 개만 둔다.
- 기본: Brand blue 배경, 흰 글자, 높이 64dp, radius 16dp
- 비활성: `#D9E8FC`, 텍스트 `#90A4C3`
- 로딩: 텍스트 대신 작은 spinner와 상태 문구를 표시한다.

#### 선택 카드

- 휴가 종류는 3개의 동일 폭 카드로 구성한다.
- 카드 내부는 `1일`/`0.5일`을 크게, 종류를 작게 계층화한다.
- 선택 전에는 얇은 border만, 선택 후에는 blue surface + blue border를 적용한다.

### 10.6 숫자 키패드 시각 설계

- 키패드는 중앙 AlertDialog 대신 화면 하단에서 올라오는 반투명 bottom sheet로 제공한다.
- sheet 상단에는 drag handle과 현재 입력 값만 표시한다.
- 숫자 버튼은 정사각형에 가까운 76dp 높이, radius 18dp, 흰색 표면으로 구성한다.
- 버튼 누름은 90ms scale-down + blue surface 변화로 즉시 반응한다.
- `입력 완료` 버튼은 키패드 전체 폭을 사용하고, 삭제 버튼은 아이콘만 사용한다.
- 키패드 배경과 숫자 버튼의 대비는 WCAG AA 이상을 만족한다.

### 10.7 모션과 피드백

- 탭 전환: 160ms fade + 8dp slide
- 버튼 눌림: 90ms scale 0.98
- 성공: check icon scale-in + 220ms, 짧은 햅틱
- 오류: red icon과 한 줄 원인, 재시도 행동 제공
- 로딩은 화면 전체를 막지 않는다. 현재 행동 버튼만 loading 상태로 바꾼다.

### 10.8 접근성 및 운영 환경

- 모든 버튼은 최소 56dp, 숫자 키패드 버튼은 최소 72dp
- 색상만으로 선택·오류를 구분하지 않고 아이콘·텍스트를 함께 제공
- 200% 글자 크기에서도 주요 CTA가 화면 밖으로 밀리지 않도록 scroll 대응
- 밝은 매장 조명에서도 보이도록 텍스트 대비 4.5:1 이상 유지
- 처리 완료 후 8초 내 자동 초기화, 단 오류 메시지는 사용자가 닫을 때까지 유지

## 11. 출시 전 품질 기준

- 반복 문구 0건
- 모든 주요 버튼 터치 성공률 100%
- 숫자 키패드 입력 오류 0건
- 시스템 키보드가 주요 플로우를 가리지 않음
- 휴가 날짜와 종류가 모든 지원 해상도에서 표시됨
- 로딩·성공·실패 상태가 1초 이내 표시됨
- 출퇴근 및 휴가 신청 완료 후 개인정보 초기화
- Android Pixel Tablet 에뮬레이터와 실기기에서 가로 화면 검증
