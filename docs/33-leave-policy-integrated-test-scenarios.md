# TimeFit 연차·월차·휴일 계산 종합 테스트 시나리오

대상: [TimeFit 프로덕션](https://timefit-omega.vercel.app)  
범위: 운영 설정, 직원별 연차 발생/잔여, 태블릿 휴가 신청, 관리자 승인, 사업장 데이터 격리  
기준일: 실행일의 한국 표준시(Asia/Seoul)

> 이 기능은 사업장별 운영 계산 기준을 설정하는 MVP입니다. 법정 연차·월차 기준의 최종 적용 전에는 노무 검토가 필요합니다.

## 1. 테스트 준비

| 항목 | 값 |
| --- | --- |
| 관리자 | 테스트 사업장의 관리자 계정 |
| 직원 M1 | 직접 등록 직원, 전화번호와 입사일 등록 필요 |
| 직원 M2 | 비교용 직접 등록 직원 |
| 태블릿 | `https://timefit-omega.vercel.app/tablet?organization={사업장 UUID}` |
| 초기 정책 | 연차 15일 / 12개월 재직, 월차 사용 / 매월 1일 / 월 최소 1일 근무, 일요일 휴일 제외 |

실행 규칙:

- 각 저장 뒤 새로고침 또는 재로그인하여 Supabase 영속성을 확인한다.
- 테스트 직원 이름과 공휴일 이름에는 실행일을 붙인다.
- 실제 운영 직원으로 테스트하지 않는다. 휴가 요청·승인 데이터는 종료 뒤 반려 또는 별도 테스트 사업장에서 정리한다.
- `PASS`: 기대 결과와 DB 기반 화면 결과가 일치, `FAIL`: 데이터/계산/권한이 불일치, `BLOCKED`: 접근권한 또는 사전 데이터 부재.

## 2. 기본 정책·저장 검증

| ID | 우선순위 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| POLICY-01 | P0 | 관리자 로그인 → 운영 설정 → **연차·월차·휴일 계산** 카드 확인 | 연차 일수/재직 개월, 월차 토글·일수·최소 근무일, 정기 휴일 요일, 공휴일 등록 UI가 표시된다. |
| POLICY-02 | P0 | 기본값 확인 후 저장 | 기본값은 15일, 12개월, 월차 사용, 1일/월, 최소 1일, 일요일 제외다. 성공 안내가 표시된다. |
| POLICY-03 | P0 | 새로고침 → 운영 설정 재진입 | 방금 저장한 값이 모든 항목에 동일하게 복원된다. |
| POLICY-04 | P1 | 연차 18일, 재직 10개월로 변경 후 저장·새로고침 | 숫자값이 영속되고 해당 사업장 직원의 발생 연차가 새 기준으로 재계산된다. |
| POLICY-05 | P1 | 월차 자동 발생 해제 → 저장 | 월차 입력 영역이 숨겨지고 1년 미만 직원의 발생 연차에 월차가 포함되지 않는다. |
| POLICY-06 | P1 | 월차 자동 발생 활성화 → 0.5일/월, 최소 2일 근무로 저장 | 조건이 저장되고 직원 상세 계산에 적용된다. |
| POLICY-07 | P1 | 연차/월차 숫자 필드에 음수·최대치 초과·빈 값 입력 시도 | 브라우저 검증 또는 DB 제약으로 잘못된 값이 저장되지 않으며 오류 안내가 표시된다. |

## 3. 정기 휴일·공휴일 설정

| ID | 우선순위 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| HOLIDAY-01 | P0 | 정기 휴일에서 `일` 선택 상태 확인 → `토` 추가 → 저장·새로고침 | 일·토가 파란 선택 상태로 유지된다. |
| HOLIDAY-02 | P0 | 공휴일 직접 등록에 미래 평일 날짜 입력 → 날짜 추가 → 저장 | 날짜 칩이 표시되고 재진입 후에도 유지된다. |
| HOLIDAY-03 | P1 | 동일 공휴일 날짜를 다시 추가 | 중복 등록되지 않고 안내가 표시된다. |
| HOLIDAY-04 | P1 | 공휴일 칩 삭제 → 저장·새로고침 | 해당 날짜가 목록과 계산 대상에서 제거된다. |
| HOLIDAY-05 | P0 | `휴가 일수 계산에서 정기휴일·공휴일 제외`를 해제 → 저장 | 요일·공휴일 입력 영역이 숨겨지고 이후 휴가 일수 계산에서 제외하지 않는다. |
| HOLIDAY-06 | P1 | 토·일을 정기휴일로 다시 설정 후 저장 | 주말이 포함된 연차 요청에서 토·일은 차감 일수에서 제외된다. |

## 4. 직원별 연차·월차 발생 계산

사전 데이터:

- M1: 입사일이 12개월 이상 전인 직원, 승인 휴가 1일 보유
- M2: 입사일이 2개월 전인 직원, 각 완료 월에 설정한 최소 근무일 이상 스케줄 보유

| ID | 우선순위 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| ACCRUAL-01 | P0 | M1 직원 상세 진입 | `발생 {연차 정책 일수}일`, 승인 사용·대기·잔여가 표시된다. 잔여 = 발생 - 승인 사용이다. |
| ACCRUAL-02 | P0 | M2 직원 상세 진입 | 1년 미만이면 완료된 월 중 최소 등록 근무일 조건을 충족한 월 수 × 월차 일수가 발생 연차로 표시된다. |
| ACCRUAL-03 | P1 | M2의 한 완료 월 스케줄을 최소 근무일 미만으로 변경 → 새로고침 | 해당 월의 월차가 발생 연차에서 제외된다. |
| ACCRUAL-04 | P1 | M2 스케줄을 최소 근무일 이상으로 복구 → 새로고침 | 해당 월의 월차가 다시 포함된다. |
| ACCRUAL-05 | P1 | M1의 승인 휴가 0.5일 생성·승인 | 승인 사용이 0.5일 증가하고 잔여가 정확히 0.5일 감소한다. |
| ACCRUAL-06 | P1 | 대기 휴가 1건 생성 | 대기 일수는 별도 표시되며 잔여 연차는 승인 전에는 감소하지 않는다. |

## 5. 태블릿 휴가 일수 계산

각 케이스 전 태블릿 PIN과 M1 전화번호 끝 8자리를 입력한다.

| ID | 우선순위 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| TLEAVE-01 | P0 | 평일 하루에 `연차` 신청 | 요청이 1일로 저장되고 관리자 휴가 목록에 승인 대기로 표시된다. |
| TLEAVE-02 | P0 | 평일 하루에 오전 반차 신청 | 요청이 0.5일로 저장된다. 오후 반차도 동일하다. |
| TLEAVE-03 | P0 | 정기휴일 또는 등록 공휴일 날짜에 연차/반차 신청 | 요청이 저장되지 않고 휴무일에는 신청할 수 없다는 오류 안내가 표시된다. |
| TLEAVE-04 | P0 | 태블릿에서 공휴일 전후의 기간 연차 신청 | 공휴일·정기휴일을 제외한 실제 근무일 수만 차감 일수로 저장된다. |
| TLEAVE-05 | P1 | 휴일 제외 토글 해제 후 동일 기간으로 다시 신청 | 휴일도 포함한 전체 날짜 수가 저장된다. 테스트 종료 뒤 요청을 반려한다. |
| TLEAVE-06 | P1 | 반차에 여러 날짜 범위를 요청하는 API/화면 입력 시도 | 반차는 단일 날짜만 허용되며 저장되지 않는다. |
| TLEAVE-07 | P0 | 존재하지 않는 번호 또는 잘못된 PIN으로 신청 | 직원 정보가 노출되지 않고 요청이 생성되지 않는다. |

## 6. 관리자 승인·화면 반영

| ID | 우선순위 | 절차 | 기대 결과 |
| --- | --- | --- | --- |
| ADMIN-LEAVE-01 | P0 | 태블릿에서 만든 요청 확인 → 관리자 홈 | 승인 대기 카드에 신청자·유형·정확한 계산 일수가 표시된다. |
| ADMIN-LEAVE-02 | P0 | 휴가·연차 관리 → 요청 검토 → 승인 | 상태가 승인 완료로 변경되고 대기 건수가 감소한다. |
| ADMIN-LEAVE-03 | P0 | 해당 직원 상세 새로고침 | 승인 사용·잔여 연차가 승인된 정확한 일수만큼 갱신된다. |
| ADMIN-LEAVE-04 | P1 | 새 요청에 메모 입력 후 반려 | 상태와 관리자 메모가 저장되며 연차 사용/잔여는 변하지 않는다. |
| ADMIN-LEAVE-05 | P1 | 운영 정책을 변경한 뒤 직원 상세·휴가 목록 다시 진입 | 샘플 수치가 아닌 현재 사업장 정책 및 실제 신청 데이터가 보인다. |
