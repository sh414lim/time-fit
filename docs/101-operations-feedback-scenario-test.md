# 운영 피드백 시나리오 테스트

실행일: 2026-09-17. 대상: `codex/operations-feedback`.

## 환경과 판정 범위

실제 `src/main.jsx` 앱을 Vite로 실행하고, 인증·Supabase·운영 요약 연결만 격리된 테스트 데이터로 교체했다. 화면, 내비게이션, React 상태와 입력 검증 코드는 제품 코드를 사용했다. 데이터 대역의 응답 형식 오류는 테스트 환경에서 수정한 뒤 재실행했다.

저장·권한은 실제 PostgreSQL의 정정 RPC 통합 테스트와 HTTP 핸들러 자동 테스트로 별도 검증했다. 운영 로그인 세션/운영 DB에 쓰는 전체 E2E, 실제 POS 수집 또는 외부 발송을 수행한 것은 아니다. 테스트 데이터는 가상의 직원·거래처이며 공개 문서에 실제 사업장 실적을 포함하지 않는다.

## 자동 및 DB 테스트

- `npm test`: 53개 통과, 실패 0개.
- `npm run build`: 통과. 단일 번들 크기 경고는 남아 있으며 실행 오류는 없다.
- `git diff --check`: 통과.
- 격리 PostgreSQL에 정정 마이그레이션 적용 후 `test/sql/attendance-correction-integration.sql`: 통과, 테스트 트랜잭션 롤백 완료.

주요 자동 시나리오: KST 주 경계, 진행 중 야간 근무, 반려 일정, 전일 휴가와 반차 구분, 중복 근태 유형, 완료 주문만 집계, 무료 옵션 제외, 수집 누락/불완전 페이지 비교 차단, 1,000행 초과 조회, 비로그인/비소유자 차단, 조직·가맹점 동시 필터, 미마감 주 차단, 조회 실패 시 오류 반환, 미래/역전/48시간 초과 정정 시각 차단.

DB 시나리오: 신규 기록 저장, 기존 기록 변경, 전후 값·사유 감사 이력, 오래된 입력 충돌, 잘못된 시각 차단, 비소유자 차단, 실패한 요청의 감사 이력 미생성.

## 발견 및 조치

주문 수를 분모로 쓰는 지표가 ‘객단가’로 표시되어 방문객당 금액으로 오인될 수 있었다. ‘주문당 금액’으로 수정하고 관련 안내 문구도 함께 정리했다.

테스트 범위 내 PR을 차단할 실패는 발견되지 않았다. 운영 배포 시 새 DB 마이그레이션을 먼저 적용하고 프런트/API를 배포해야 한다. 배포 후 실제 세션으로 조회·정정 및 기존 정책과의 통합을 다시 확인해야 하며, PR 생성은 운영 배포를 뜻하지 않는다.
