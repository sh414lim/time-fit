# TimeFit 최종 QA 테스트 케이스

기준 문서: [최종 출시 점검 시나리오](./23-final-acceptance-test-scenarios.md)  
대상 환경: `https://timefit-omega.vercel.app/`

## 1. 공통 테스트 데이터

| 구분 | 데이터 |
| --- | --- |
| 관리자 A | 기존 E2E 테스트 사업장 관리자 |
| 직원 A1/A2 | 같은 사업장의 초대 수락형 직원 |
| 직접 등록 직원 M1 | 이름·전화번호·직책·급여·입사일을 관리자 A가 직접 입력한 직원 |
| 관리자 B | 관리자 A와 다른 사업장 관리자 |
| 신규 관리자 C | 이 문서 실행 시 새로 가입할 관리자 |
| 태블릿 | `tablet?organization={관리자 A 사업장 ID}` |

실행 규칙:

- 각 저장 테스트는 성공 안내 확인 후 페이지를 새로고침하여 영속성을 확인한다.
- 생성한 데이터 이름에는 실행일을 붙인다. 예: `QA 직원 2026-08-12`.
- P0 실패는 출시 차단, P1 실패는 출시 전 수정 권장, P2는 개선 항목으로 기록한다.

## 2. 관리자 가입·사업장

| ID | 우선순위 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| AUTH-01 | P0 | 로그아웃 상태 | 회원가입 → 관리자 선택 → 이름/사업장명/이메일/8자 이상 비밀번호 입력 → 가입 | 즉시 로그인되고 관리자 홈으로 이동한다. |
| AUTH-02 | P0 | AUTH-01 성공 | 상단 사업장명·사용자명 확인 → 운영 설정 이동 | 입력한 사업장명과 관리자 이름, 관리자 전용 메뉴가 표시된다. |
| AUTH-03 | P0 | AUTH-01 성공 | 로그아웃 → 같은 계정으로 로그인 | 같은 사업장과 관리자 권한이 복구된다. |
| AUTH-04 | P1 | AUTH-01 성공 | 관리자 B와 신규 관리자 C의 직원 관리 비교 | 서로의 직원과 근태·휴가 데이터가 노출되지 않는다. |

## 3. 운영 설정

| ID | 우선순위 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| SET-01 | P0 | 관리자 A 로그인 | 사업장명/주소/휴게시간/PIN/활성화 저장 | 성공 안내가 표시된다. |
| SET-02 | P0 | SET-01 성공 | 새로고침 → 운영 설정 재진입 | 마지막 저장값이 모두 유지된다. |
| SET-03 | P0 | SET-01 성공 | 태블릿 URL을 새 탭에서 열기 | 해당 사업장의 태블릿 화면이 열린다. |
| SET-04 | P0 | SET-01 성공 | 태블릿 활성화 해제 저장 → 태블릿 출퇴근·휴가 요청 | 두 기능이 차단된다. 재활성화 후 다시 동작한다. |

## 4. 직접 직원 등록·관리자 데이터 노출

| ID | 우선순위 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| STAFF-01 | P0 | 관리자 A 로그인 | 직원 등록하기 → 이름/전화번호/부서/직책/시급/입사일 입력 → 저장 | 성공 안내 후 직원 목록에 새 직원이 표시된다. |
| STAFF-02 | P0 | STAFF-01 성공 | 목록에서 생성 직원 검색 | 이름·부서·직책·급여 형태·재직 상태가 입력값과 일치한다. |
| STAFF-03 | P1 | STAFF-01 성공 | 해당 직원 상세 진입 | 이름, 근태, 휴가 내역은 실제 데이터이며 샘플 값이 섞이지 않는다. |
| STAFF-04 | P0 | STAFF-01 성공 | 동일 전화번호로 태블릿 직원 확인 | 전화번호 끝 4자리·8자리로 해당 직원만 확인된다. |
| STAFF-05 | P1 | STAFF-01 성공 | 목록 새로고침 및 재로그인 | 직접 등록 직원이 유지되고 중복 생성되지 않는다. |

## 5. 태블릿 숫자 키패드·출퇴근

| ID | 우선순위 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| TAB-01 | P0 | 태블릿 URL, 활성화 상태 | 출퇴근 탭 진입 | PIN, 전화번호 끝 4자리, 직원 확인 버튼이 표시된다. |
| TAB-02 | P0 | TAB-01 | PIN 입력칸 누르기 | 자체 숫자 키패드 모달(0~9, 삭제, 입력 완료)이 열린다. 기기 기본 키보드는 열리지 않는다. |
| TAB-03 | P0 | TAB-02 | PIN 숫자 입력 → 삭제 → 입력 완료 | 입력값이 필드에 반영되고 모달이 닫힌다. |
| TAB-04 | P0 | TAB-01 | 전화번호 끝 4자리 입력칸 누르기 | 동일한 숫자 키패드 모달이 열린다. |
| TAB-05 | P0 | 올바른 PIN·M1 번호 | 직원 확인 → 실명 확인 → 출근하기 | 직원 실명과 출근 버튼이 보이고 출근 1건이 저장된다. |
| TAB-06 | P0 | TAB-05 성공 | 동일 직원 재인증 → 퇴근하기 | 기존 출근 건에 퇴근 시각이 기록되고 중복 출근 건이 생기지 않는다. |
| TAB-07 | P0 | 태블릿 URL | 잘못된 PIN 또는 없는 번호 입력 → 직원 확인 | 직원 정보는 노출되지 않고 오류 안내가 표시된다. |
| TAB-08 | P0 | 사업장 A/B 존재 | 사업장 B 태블릿에 사업장 A 직원 번호 입력 | 인증 실패하며 근태가 생성되지 않는다. |

## 6. 휴가 신청·승인

| ID | 우선순위 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| LEAVE-01 | P0 | 활성 태블릿, M1 번호 | 휴가 신청 → PIN/전화번호 끝 8자리 입력 → 미래 날짜·연차 선택 → 신청 | 성공 안내와 관리자 알림 대기열 안내가 표시된다. |
| LEAVE-02 | P0 | LEAVE-01 성공 | 관리자 A 홈 또는 휴가 관리에서 요청 확인 | 신청자명·날짜·종류·일수·대기 상태가 일치한다. |
| LEAVE-03 | P0 | LEAVE-02 성공 | 메모 입력 → 승인하기 | 상태가 승인 완료로 변경되고 대기 건수가 감소한다. |
| LEAVE-04 | P0 | 새 대기 요청 | 반려 사유 입력 → 반려 | 상태가 반려로 변경되고 사유가 저장된다. |
| LEAVE-05 | P1 | 직원 계정 연결 상태 | 해당 직원 로그인 → 휴가 메뉴 | 본인 요청의 승인/반려 결과만 보인다. |
| LEAVE-06 | P1 | 태블릿 | 오전·오후 반차 각각 신청 | 각각 0.5일로 저장된다. |

## 7. 관리자 화면별 실제 데이터 확인

| ID | 우선순위 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| ADMIN-01 | P0 | TAB-05 성공 | 관리자 A 홈 진입 | 오늘 출근/근무 중 요약과 최신 근태 목록에 M1 기록이 반영된다. |
| ADMIN-02 | P0 | TAB-05 성공 | 관리자 A → 출퇴근 관리 | M1 이름, 근무 상태, 출근 시각, 퇴근 시각이 실제 기록과 일치한다. |
| ADMIN-03 | P0 | LEAVE-03 성공 | 관리자 A → 휴가·연차 | M1 요청과 승인 상태·메모가 실제 저장값과 일치한다. |
| ADMIN-04 | P1 | STAFF-01, TAB-06, LEAVE-03 성공 | M1 직원 상세 확인 | 입사일·출퇴근·휴가·근무시간·급여가 실제 CRUD 데이터와 일치한다. 샘플 값이면 FAIL이다. |
| ADMIN-05 | P1 | 관리자 A 설정 저장 | 운영 설정 재진입 | 해당 사업장 설정만 표시된다. |
| ADMIN-06 | P1 | 급여 데이터 존재 | 급여 관리 진입 | 직원별 급여 형태·기초 금액과 실제 집계 기준이 명확히 표시된다. 정책 미확정이면 준비 중으로 표시한다. |

## 8. 권한·데이터 격리

| ID | 우선순위 | 사전조건 | 절차 | 기대 결과 |
| --- | --- | --- | --- | --- |
| ACL-01 | P0 | A1이 휴가/출퇴근 기록 보유 | A2 로그인 → 휴가·출퇴근·스케줄 확인 | A1의 이름, 전화번호, 근태, 휴가 사유/결과가 노출되지 않는다. |
| ACL-02 | P0 | 사업장 A/B 존재 | 관리자 B 로그인 → 모든 관리자 메뉴 확인 | 사업장 A의 직원, 근태, 휴가, 설정이 전혀 보이지 않는다. |
| ACL-03 | P0 | A1 로그인 | URL 또는 UI로 관리자 메뉴 접근 시도 | 관리자 메뉴와 다른 직원 데이터에 접근할 수 없다. |
