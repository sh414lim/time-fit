# 레스토랑 운영 관리자·태블릿 UAT 실행 기록

실행일: 2026-08-30  
환경: `https://timefit-omega.vercel.app` 프로덕션  
사업장: 테스트 사업 / 테스트1  
방식: 실제 브라우저의 로그인 유지 세션으로 읽기·화면 전환 중심 점검

## 통과

| 영역 | 검증 결과 |
| --- | --- |
| 관리자 세션 | 프로덕션 진입 후 계정·사업장 정보를 정상적으로 불러왔고, 대시보드가 표시됨 |
| 화면 전환 | 홈 → 스케줄 → 직원 관리 → 출퇴근 → 휴가·연차 → 홈 전환이 정상 동작. 홈 복귀 뒤 5초 대기에도 로딩 화면에 고정되지 않음 |
| 스케줄 구분 표기 | 월간 보드에서 `주방`, `요리`, `홀`별 배정 인원과 날짜별 `주방 1`, `요리 1`, `홀 1` 표기가 실제 등록 일정 기준으로 표시됨 |
| 직원 목록 | 직원별 구분명 기반 아바타, 구분·직책·급여형태가 표시됨 |
| 직원 상세 모달 | 상세 → 정보 수정 → 닫기 → 상세 닫기 순서에서 기존 직원 목록 화면으로 복귀함 |
| 직원 구분 선택 | 수정 화면의 선택 목록에 미분류, ㅁㅁ, ㅇㅇ, 요리, 주방, 홀이 실제 운영 설정 값으로 표시됨 |
| 급여 형태 | 시급제·일급제·월급제·연봉제 옵션이 확인됨 |
| 운영 설정 | 근무 형태, 직원 구분, 태블릿 주소, 연차·월차·휴일 보상, 30분 단위 급여 계산, 급여일 알림 설정 UI가 정상 표시됨 |
| 출퇴근 관리자 | 실제 직원 목록별 상태와 출근·근무시간 관리 영역이 표시됨 |
| 휴가·연차 관리자 | 실제 휴가 신청 이력과 승인/반려 상태가 표시됨 |
| 태블릿 연결 | `/tablet`에서 연결된 사업장과 출퇴근/휴가 신청 탭이 정상 표시됨 |
| 태블릿 휴가 UI | 전화번호 8자리, 날짜, 연차·오전 반차·오후 반차, 최종 확인 버튼이 표시됨 |
| 태블릿 입력 분리 | 휴가 탭과 출퇴근 탭이 별도 입력 폼(휴가 8자리 / 출퇴근 4자리)으로 렌더링됨 |

## 이번 회차에서 제출하지 않은 항목

실제 운영 데이터의 중복 생성·변경을 방지하기 위해 아래 행위는 제출 직전 UI까지만 확인했습니다.

- 직원 신규 등록·수정 저장 및 삭제
- 스케줄 신규 등록·수정·삭제
- 태블릿 출근/퇴근 저장
- 태블릿 휴가 신청 제출, 관리자 승인·반려
- 계좌번호·주민등록번호 저장

## 확인된 보완 항목

- **P1 — 직원 구분 초기 선택값:** `최병주(주방)`의 정보 수정 모달을 열었을 때, 구분 선택 상자의 초기 표시값은 `미분류`였습니다. 목록에는 주방을 포함한 모든 등록 구분이 정상적으로 표시됩니다. 다른 기본 정보를 수정한 뒤 저장할 때 구분이 의도치 않게 변경될 수 있으므로, 저장 전 기존 구분의 ID를 선택값으로 매핑하는 수정과 회귀 테스트가 필요합니다.

## 후속 실데이터 UAT 권고

별도 테스트 직원 한 명을 지정한 뒤, 다음 한 번의 연속 흐름을 실행합니다.

1. 태블릿에서 출근 저장 → 관리자 출퇴근 관리에 반영 확인
2. 태블릿에서 휴가 신청 저장 → 관리자 휴가·연차에서 승인 → 잔여 연차 변동 확인
3. 테스트 일정 수정/삭제 → 월간 및 주간 구분별 인원 합계의 즉시 반영 확인
4. 지급 정보 저장 → 최상위 완료 모달 노출과 민감정보 비재노출 확인
