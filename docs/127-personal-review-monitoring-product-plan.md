# 개인용 외부 리뷰 통합 모니터링 기획

## 1. 목표

네이버 플레이스, 캐치테이블 등 여러 채널에 흩어진 버터빌라 리뷰를 TimeFit의 `리뷰 · 컴플레인`에서 한 번에 확인한다. 단순 원문 보관보다 아래 질문에 빠르게 답하는 것을 목표로 한다.

- 오늘 새로 들어온 리뷰는 무엇인가?
- 낮은 평점이나 긴급 대응이 필요한 리뷰가 있는가?
- 음식·서비스·가격·분위기 중 무엇이 좋아지거나 나빠지고 있는가?
- 동일 리뷰가 여러 번 수집되지 않았는가?
- 조치가 필요한 리뷰를 누가 언제 확인했는가?

개인용이더라도 플랫폼의 이용약관, robots 정책, 저작권과 개인정보 원칙은 동일하게 적용한다.

## 2. 사전 조사 결론

### 네이버

- 네이버 이용약관은 사전 허락 없이 매크로·봇·스파이더·스크래퍼 등 자동화 수단으로 검색하거나 게시물을 수집하는 행위를 제한한다.
- 네이버 지역 검색 API는 업체 기본 검색용이며 방문자 리뷰 원문 전체를 제공하는 리뷰 API가 아니다.
- 스마트플레이스 사업자 화면에는 방문자 리뷰 확인·답글 및 AI 리뷰 통계 기능이 있다. 음식점용 AI 리뷰 통계는 음식, 메뉴, 가격, 분위기, 매장, 시설, 좌석, 서비스, 운영 등 9개 테마와 긍·부정 추이를 제공한다.

### 캐치테이블

- `https://app.catchtable.co.kr/robots.txt`는 일반 User-agent에 대해 전체 경로를 `Disallow: /`로 설정한다.
- 따라서 캐치테이블 공개 페이지를 서버에서 정기 크롤링하는 기능은 기본 설계에서 제외한다.
- 제휴 API, 사업자용 내보내기, 명시적 수집 허가가 확보될 때만 자동 어댑터를 활성화한다.

## 3. 제품 원칙

1. **공식 경로 우선**: 공식 API → 사업자 화면 내보내기 → 사용자가 직접 붙여넣기/파일 업로드 순으로 사용한다.
2. **차단 회피 금지**: 로그인 세션 탈취, CAPTCHA 우회, 프록시·IP 순환, 비공개 API 역공학을 하지 않는다.
3. **최소 수집**: 리뷰 본문, 평점, 작성일, 공개 닉네임, 원문 링크만 저장한다. 프로필 사진·회원 ID·불필요한 개인정보는 저장하지 않는다.
4. **원문 출처 유지**: 분석 결과와 원문을 구분하고 채널·작성일·가져온 시각·원문 링크를 표시한다.
5. **삭제 대응**: 원문이 삭제되거나 사용자가 제거하면 로컬 보관본도 숨김 또는 삭제할 수 있게 한다.
6. **분석은 보조 수단**: AI 감성·테마 분석은 확정 판정이 아니라 관리자 검토용 제안으로 표시한다.

## 4. 권장 수집 방식

| 우선순위 | 방식 | 네이버 | 캐치테이블 | 자동화 수준 | 적용 조건 |
|---|---|---|---|---|---|
| 1 | 공식·제휴 API | API 제공 범위 내 | 제휴 API 확인 후 | 높음 | 정식 권한 및 약관 준수 |
| 2 | 사업자 화면 CSV/엑셀 내보내기 | 지원 시 사용 | 지원 시 사용 | 중간 | 사용자가 파일 다운로드 |
| 3 | 리뷰 텍스트 붙여넣기 | 가능 | 가능 | 낮음 | 사용자가 직접 선택·복사 |
| 4 | 리뷰 화면 캡처 OCR | 가능 | 가능 | 낮음 | 개인용 보조, 원문 재확인 필수 |
| 5 | 공개 페이지 서버 크롤링 | 사용하지 않음 | 사용하지 않음 | 높음 | 플랫폼의 서면 허가가 있을 때만 |

### MVP 수집 흐름

1. 사용자가 `리뷰 가져오기`를 누른다.
2. 채널을 네이버 또는 캐치테이블로 선택한다.
3. CSV 업로드, 텍스트 붙여넣기, 화면 캡처 중 하나를 선택한다.
4. 미리보기에서 작성일·평점·본문·닉네임 매핑을 확인한다.
5. 중복 후보와 새 리뷰 건수를 표시한다.
6. 사용자가 확정하면 DB에 반영한다.
7. 분석 작업이 테마·감성·긴급도를 생성한다.

## 5. 사용자 화면 설계

### 5.1 리뷰 대시보드

상단 요약 카드:

- 신규 리뷰: 오늘/최근 7일
- 평균 평점 및 이전 기간 대비 변화
- 긍정·중립·부정 비중
- 확인 필요 리뷰 수
- 채널별 수집 최신 시각

차트:

- 주간 리뷰 수와 평균 평점 추이
- 테마별 긍정·부정 언급량
- 채널별 리뷰 비중
- 최근 4주 부정 키워드 변화

### 5.2 통합 리뷰 목록

필터:

- 기간, 채널, 평점, 감성, 테마, 처리 상태
- `신규`, `부정`, `답변 필요`, `재방문 언급`, `메뉴 언급`

카드 정보:

- 채널 아이콘, 작성일, 평점, 공개 닉네임
- 리뷰 원문과 AI 한 줄 요약
- 음식·서비스·가격·분위기·시설·운영 테마 칩
- 긍정/중립/부정 및 분석 신뢰도
- 원문 열기, 확인 완료, 조치 메모

### 5.3 가져오기 센터

- 네이버·캐치테이블 채널 카드
- 최근 가져오기 일시와 결과
- `CSV`, `텍스트`, `화면 캡처` 버튼
- 미리보기 표와 오류 행 표시
- 중복 리뷰는 `건너뜀`, 내용이 변경된 리뷰는 `갱신`으로 구분

## 6. 분류 및 분석 기준

### 테마

- 음식 맛
- 메뉴·제품
- 가격·가성비
- 서비스·응대
- 대기·예약
- 분위기
- 청결·시설
- 포장·배달
- 운영·기타

### 긴급도 규칙

- **긴급**: 위생, 이물질, 식중독, 안전사고, 결제 분쟁, 직원 실명 비난
- **높음**: 1~2점, 강한 부정 표현, 재방문 거부, 동일 이슈 반복
- **보통**: 3점 또는 개선 제안
- **참고**: 4~5점 긍정 리뷰

AI 결과에는 `sentiment`, `sentiment_score`, `themes`, `keywords`, `urgency`, `summary`, `model_version`을 저장한다. 원문은 수정하지 않는다.

## 7. 데이터 설계

기존 `timefit_user_feedback_items`를 유지하고 다음 필드를 확장한다.

### feedback_items 추가 필드

- `source_url`: 원문 링크
- `source_review_id`: 채널이 제공하는 리뷰 ID
- `source_updated_at`: 원문 수정 시각
- `import_method`: `api`, `csv`, `paste`, `ocr`
- `imported_at`: 가져온 시각
- `content_hash`: 정규화한 본문 해시
- `reviewer_hash`: 닉네임 원문 대신 중복 판별용 해시
- `deleted_at`: 원문 삭제·사용자 삭제 대응

### feedback_analyses 신규 테이블

- `feedback_item_id`
- `sentiment`, `sentiment_score`
- `themes jsonb`, `keywords jsonb`
- `urgency`, `summary`
- `model`, `model_version`, `analyzed_at`
- `needs_review`

### feedback_import_runs 신규 테이블

- `organization_id`, `source`, `method`
- `status`, `started_at`, `finished_at`
- `fetched_count`, `created_count`, `updated_count`, `skipped_count`, `failed_count`
- `error_code`, `error_message`
- 파일 원문은 장기 보관하지 않고 처리 후 제거한다.

## 8. 중복 제거 규칙

우선순위:

1. `(organization_id, source, source_review_id)` 정확 일치
2. `source + source_url` 일치
3. `source + 작성일 + 평점 + content_hash` 일치
4. 본문 유사도가 매우 높고 작성 시각이 가까우면 관리자에게 중복 후보 제안

동일 리뷰의 본문 또는 평점이 바뀌면 신규 생성하지 않고 기존 행을 갱신하며 변경 이력을 남긴다.

## 9. 시스템 구조

```text
[공식 API/CSV/붙여넣기/OCR]
              ↓
       Import Adapter
              ↓
   정규화 → 검증 → 중복 제거
              ↓
 timefit_user_feedback_items
              ↓
      감성·테마 분석 작업
              ↓
   대시보드 / 알림 / 처리 목록
```

자동 수집 어댑터는 `disabled`, `manual`, `official_api` 상태를 가진다. 네이버·캐치테이블은 초기값을 `manual`로 두고, 공식 권한이 확인되기 전에는 예약 실행과 Cron을 제공하지 않는다.

## 10. 알림 정책

- 긴급 리뷰: 가져오기 직후 관리자 화면 상단에 표시
- 1~2점 리뷰: 일일 요약에 포함
- 동일 부정 테마 3건 이상: 반복 이슈 알림
- 새 리뷰가 없거나 변화가 없으면 알림을 보내지 않음
- 외부 채널에 답글을 자동 게시하지 않음

## 11. 단계별 개발 범위

### 1차 — 안전한 개인용 MVP

- 기존 CSV 가져오기 코드를 별도 `ReviewImportCenter`로 분리
- 텍스트 붙여넣기 및 화면 캡처 OCR 추가
- 가져오기 미리보기·중복 표시·오류 행 수정
- 채널/기간/평점/상태 필터
- 요약 카드와 리뷰 추이 차트

### 2차 — 리뷰 분석

- 감성·테마·긴급도 분석
- 부정 키워드 추이 및 반복 이슈 감지
- 관리자 조치 메모와 처리 상태
- 리뷰별 분석 재실행 및 사람이 수정하는 기능

### 3차 — 승인된 연동

- 플랫폼 제휴 또는 공식 API 승인 여부 확인
- 승인된 채널에만 서버 측 동기화 어댑터 구현
- 증분 동기화, 재시도, 삭제 반영, 수집 상태 모니터링

## 12. 완료 기준

- 네이버·캐치테이블 리뷰 파일 또는 텍스트 100건을 가져와도 중복 생성되지 않는다.
- 가져오기 전에 신규/갱신/중복/오류 건수를 확인할 수 있다.
- 기간·채널·평점·테마별 집계와 원문 목록 합계가 일치한다.
- 1~2점 및 긴급 키워드 리뷰가 상단에 우선 표시된다.
- 원문 링크와 가져온 시각이 모든 외부 리뷰에 남는다.
- 플랫폼 허가가 없는 수집기는 실행할 수 없다.
- 사용자 데이터 삭제 시 원문·분석·수집 이력을 정책에 맞게 제거할 수 있다.

## 13. 권장 결론

현재는 크롤링 개발보다 기존 CSV 가져오기 기능을 강화하고, 텍스트 붙여넣기·OCR·통합 분석을 먼저 구현하는 것이 안전하고 빠르다. 네이버는 스마트플레이스의 공식 리뷰 관리 및 AI 리뷰 통계도 함께 활용한다. 캐치테이블은 사업자용 내보내기 또는 제휴 수단을 먼저 확인하고, 명시적 허가 전에는 자동 크롤러를 만들지 않는다.
