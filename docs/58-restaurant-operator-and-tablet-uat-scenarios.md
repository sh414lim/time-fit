# 레스토랑 운영자·태블릿 직원 통합 사용자 테스트 시나리오

## 목적과 범위

레스토랑 사업장이 TimeFit을 도입한 뒤 직원 등록, 구분별 스케줄 운영, 출퇴근, 휴가 승인, 급여 확인을 정상 수행하는지 검증한다.

- 관리자 웹: 사업장 설정, 직원·구분·스케줄·휴가·출퇴근·급여 관리
- 매장 태블릿: 관리자 연결 후 직원 출퇴근과 휴가 신청
- 직원 웹: 초대 수락, 개인 일정과 휴가 내역 확인
- 데이터 기준: Supabase에 실제 저장되고 화면 전환과 새로고침 뒤에도 동일 사업장 데이터만 보여야 한다.

## 공통 테스트 환경

- 사업장: 테스트 레스토랑
- 구분: 홀, 주방, 바
- 근무 형태: 오픈 근무 09:00~18:00, 마감 근무 12:00~21:00
- 출퇴근 단위: 30분 단위 급여 반영
- 급여일: 매월 25일

# A. 레스토랑 운영자(관리자 웹) 시나리오

## A-01. 로그인과 사업장 데이터 격리

1. 관리자 계정으로 로그인한다.
2. 홈 대시보드에서 사업장명, 직원 수, 출퇴근 현황을 확인한다.
3. 스케줄, 직원 관리, 휴가·연차, 급여 관리, 운영 설정으로 이동한다.
4. 각 화면에서 다른 사업장 또는 이전 세션의 직원 데이터가 보이지 않는지 확인한다.
5. 로그아웃 후 다시 로그인해 같은 사업장 데이터가 유지되는지 확인한다.

기대 결과: 로그인 직후 올바른 사업장 데이터만 보이며, 페이지 전환과 재방문 시 무한 로딩 또는 이전 사업장 정보 노출이 없다.

## A-02. 운영 설정과 직원 구분

1. 사업장 이름, 주소, 휴게시간, 출퇴근 반올림 단위를 저장한다.
2. 직원 구분으로 홀, 주방, 바를 만들고 색상을 지정한다.
3. 오픈 근무와 마감 근무를 등록한다.
4. 정기 휴일, 공휴일, 대체휴무 보상, 연차 발생 정책을 설정한다.
5. 다른 화면을 거쳐 다시 들어와 설정값이 유지되는지 확인한다.

기대 결과: 카테고리·색상·근무 형태가 직원 등록과 스케줄 등록 선택지에 즉시 반영되고, 설정은 현재 사업장에만 적용된다.

## A-03. 직원 등록과 개인정보 관리

1. 이름, 전화번호, 직원 구분, 직책, 입사일을 입력해 직원을 등록한다.
2. 시급제·일급제·월급제·연봉제를 각각 선택해 금액을 등록한다.
3. 등록 버튼을 연속 클릭해도 한 명만 생성되는지 확인한다.
4. 직원 목록에서 구분 배지와 사진 또는 기본 구분 아이콘을 확인한다.
5. 직원 상세 모달에서 전화번호, 구분, 직책, 급여 형태를 수정한다.
6. 은행명, 계좌번호, 주민등록번호를 저장하고 원문이 다시 표시되지 않는지 확인한다.
7. 모달 X를 눌러 직원 목록 화면으로 복귀하는지 확인한다.

기대 결과: 직원 구분은 운영 설정 카테고리만 선택 가능하며, 저장 완료 알림은 상세 모달보다 최상단에 표시되고 확인 뒤 상세 모달을 유지한다.

## A-04. 일간·주간·월간 스케줄 편성

1. 직원 여러 명과 여러 날짜를 선택해 일괄 근무를 등록한다.
2. 홀 직원에게 오픈 근무, 주방 직원에게 마감 근무를 등록한다.
3. 중복 일정이 있을 때 덮어쓰기 경고와 최종 확인을 검증한다.
4. 일간 보기에서 홀 2명, 주방 1명처럼 구분별 근무 수를 확인한다.
5. 주간·월간 보기에서 날짜별 구분별 근무 수와 카테고리 색상을 확인한다.
6. 일정 수정으로 시간과 근무 형태를 변경한 뒤 삭제도 수행한다.
7. 일정의 직원 행을 눌러 직원 상세 모달이 열리는지 확인한다.

기대 결과: 구분별 집계는 실제 배정 직원과 일치하며 휴무·연차는 근무 인원에 포함되지 않는다. 수정·삭제 후 해당 스케줄 화면에 머문 채 즉시 갱신된다.

## A-05. 휴가·연차 운영

1. 직원 상세에서 수동 연차 1일을 부여하고 사유를 기록한다.
2. 월차, 연차, 정기휴일, 공휴일, 대체휴무 설정을 적용한다.
3. 태블릿에서 제출한 휴가 요청의 잔여 연차와 차감 예정 일수를 확인한다.
4. 공휴일 근무의 대체휴무 또는 보상 정책을 확인한다.
5. 휴가를 승인한 뒤 직원 잔여 연차, 일정, 대시보드 승인 건수가 갱신되는지 확인한다.
6. 별도 요청은 반려하고 상태·사유가 남는지 확인한다.

## A-06. 출퇴근과 급여

1. 태블릿에서 직원 출근을 기록한다.
2. 관리자 출퇴근 관리에서 출근 시간, 상태, 퇴근 시간을 확인한다.
3. 30분 반올림 설정에 따라 실근무 시간이 급여에 반영되는지 확인한다.
4. 시급제, 일급제, 월급제, 연봉제별 예상 급여를 급여 관리에서 확인한다.
5. 급여일 알림 설정을 저장하고 예약 대상과 알림 채널 상태를 확인한다.

기대 결과: 태블릿 출퇴근 기록이 관리자 화면에 반영되고 급여는 등록 급여 형태 및 실근무 기준으로 계산된다.

## A-07. 오류 처리와 화면 유지

1. 대시보드 확인 필요 수치와 실제 미출근·승인 대기 항목을 비교한다.
2. 네트워크를 끊고 저장을 시도해 오류 안내를 확인한다.
3. 재시도 후 중복 직원·휴가·일정이 생성되지 않는지 확인한다.
4. 다른 브라우저 탭으로 5초 이상 이동한 뒤 복귀해 현재 화면과 데이터가 유지되는지 확인한다.

# B. 매장 태블릿 직원 사용 시나리오

## B-01. 태블릿 초기 연결

1. 태블릿 앱 또는 tablet 경로를 연다.
2. 초기 진입에서 관리자 로그인과 사업장 연결 화면이 보이는지 확인한다.
3. 관리자 계정으로 테스트 레스토랑을 연결한다.
4. 사업장명과 연결됨 상태가 나타나는지 확인한다.
5. 앱을 종료하고 다시 열어 연결 정보가 유지되는지 확인한다.
6. 로그아웃 또는 연결 해제 후 직원 화면 접근이 차단되는지 확인한다.

## B-02. 직원 출근

1. 출퇴근 탭을 선택한다.
2. 전화번호 뒤 4자리를 눌러 숫자 키패드를 연다.
3. 번호를 입력하고 입력 완료를 누른다.
4. 입력값이 출퇴근 입력란에 바로 표시되는지 확인한다.
5. 직원 확인을 눌러 이름, 구분, 오늘 일정을 확인한다.
6. 최종 확인 모달에서 출근을 누르고 완료 알림을 확인한다.
7. 같은 번호로 다시 출근을 시도해 중복 방지 메시지를 확인한다.

기대 결과: 키패드는 잘리지 않고, 확인·완료 모달은 최상단에 표시된다. 출근 기록은 관리자 웹 출퇴근 관리에 반영된다.

## B-03. 직원 퇴근

1. 출근한 직원의 전화번호 뒤 4자리를 다시 입력한다.
2. 직원 확인 후 퇴근을 선택한다.
3. 최종 확인 모달에서 직원명, 출근 시각, 퇴근 동작을 확인한다.
4. 완료 후 같은 번호로 재퇴근을 시도해 중복 방지 안내를 확인한다.

기대 결과: 퇴근은 같은 날짜의 출근 기록을 업데이트하며 관리자 웹에 퇴근 완료와 실근무 시간이 표시된다.

## B-04. 태블릿 휴가 신청

1. 휴가 신청 탭으로 전환한다.
2. 휴가 신청용 전화번호 입력값이 출퇴근 입력값과 분리되어 비어 있는지 확인한다.
3. 전화번호 뒤 4자리를 입력하고 입력 완료를 누른다.
4. 날짜 선택을 눌러 달력 모달에서 오늘 이후 날짜를 선택한다.
5. 연차, 오전 반차, 오후 반차 중 하나를 선택한다.
6. 신청하기 후 직원명, 날짜, 휴가 종류, 차감 일수가 표시되는 최종 확인 모달을 확인한다.
7. 완료를 눌러 신청한다.

기대 결과: 과거 날짜, 미등록 번호, 잔여 연차 부족, 휴일 정책 위반은 구체적 오류로 안내된다. 성공하면 입력값이 초기화되고 관리자 휴가·연차 승인 대기에 표시된다.

## B-05. 태블릿 사용성·복구

1. 가로·세로 태블릿에서 버튼, 키패드, 달력의 터치 영역을 확인한다.
2. 빠른 연속 입력과 삭제, 취소, 재열기를 반복한다.
3. 네트워크가 끊긴 상태에서 출퇴근·휴가 제출을 시도한다.
4. 연결 복구 후 재시도하고 중복 데이터가 생기지 않는지 확인한다.
5. 장시간 미사용 후 앱으로 돌아와 사업장 연결과 화면 반응을 확인한다.

# C. 교차 검증 체크리스트

1. 태블릿 출근 → 관리자 출퇴근 관리 → 급여 예상 금액이 일치한다.
2. 태블릿 휴가 신청 → 관리자 승인 또는 반려 → 직원 잔여 연차와 스케줄 표시가 일치한다.
3. 직원 구분 변경 → 직원 목록, 일간·주간·월간 스케줄 집계가 함께 갱신된다.
4. 전화번호 변경 → 태블릿 인증에 즉시 적용된다.
5. 사업장 전환·로그아웃·재로그인 후 다른 사업장 데이터가 노출되지 않는다.
6. 저장 시 로딩·성공·오류 모달은 최상단에 표시되고 확인 후 현재 화면을 유지한다.

## 통과 기준

- P0: 로그인, 직원 등록, 스케줄 저장, 출퇴근 저장, 휴가 신청·승인, 데이터 격리
- P1: 급여 계산, 연차·공휴일 정책, 급여 알림 예약, 파일·매출 연동
- 모든 P0 항목이 실제 Supabase 데이터 기준으로 통과해야 레스토랑 운영 배포 가능으로 판단한다.
