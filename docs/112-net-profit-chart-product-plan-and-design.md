# TimeFit 순수익 차트 기획·설계

버전: 1.0

작성일: 2026-09-12

상태: 독립 개발 기준안

## 1. 문서 목적

이 문서는 TimeFit의 순수익 지표와 차트만을 독립적으로 정의한다. 매출, 지출, 인건비, 카드 동기화, 영수증 증빙 및 결산 기능은 차트의 입력 데이터로만 다룬다.

현재 제품에서 사용자가 말하는 `순수익`은 세무·회계상 당기순이익이 아니라 매장 운영 관점의 `운영순익(추정)`이다. 화면의 공식 명칭은 `운영순익`으로 통일하고, 쉬운 설명이 필요한 위치에만 `순수익`을 보조 문구로 사용한다.

## 2. 사용자 목표

사업장 소유자와 비용관리자가 다음 질문에 즉시 답할 수 있어야 한다.

- 오늘과 이번 달에 실제로 얼마를 벌었는가?
- 매출은 늘었지만 지출이나 인건비 때문에 순익이 줄었는가?
- 어떤 날짜부터 적자가 발생했는가?
- 현재 숫자는 확정값인가, 아직 변할 수 있는 잠정값인가?
- 순익이 달라진 원인이 매출·지출·인건비 중 무엇인가?
- 차트의 숫자를 구성한 거래와 영수증까지 확인할 수 있는가?

## 3. 핵심 지표 정의

### 3.1 기본 산식

```text
순매출
= 완료 매출
- 매출 취소
- 할인
- 환불

운영지출
= 확정 일반지출
+ 카드수수료
+ 매출연동 임대료
+ 기타 운영비 조정

운영순익(추정)
= 순매출
- 운영지출
- 실제 인건비

운영순익률
= 운영순익 ÷ 순매출 × 100
```

순매출이 0원이면 순익률은 `-`로 표시한다. 음수 매출이나 환불 초과 상황에서도 금액은 표시하되 순익률은 정책상 의미가 없으므로 별도 경고를 표시한다.

### 3.2 포함·제외 기준

포함:

- Toss Place 등 연결된 매출 원천의 완료·취소·할인·환불
- 확정된 카드 및 수기 지출
- 카드수수료 설정값
- 매출연동 임대료 설정값
- 실제 근태를 반영한 급여 초안 또는 확정 급여
- 감사 이력이 있는 결산 조정

잠정 포함:

- 아직 매입되지 않은 카드 승인액
- 급여 확정 전 실제 근태 기반 예상 인건비

제외:

- 미확정 OCR 영수증
- 중복 의심 또는 매칭 검토 중인 지출
- 취소된 카드 거래의 취소 금액
- 내부 계좌이체처럼 비용이 아닌 자금 이동
- 법인세, 감가상각, 금융손익 등 아직 TimeFit이 수집하지 않는 항목

따라서 `당기순이익`, `세후순이익`이라는 명칭은 사용하지 않는다.

## 4. 잠정·확정 상태

차트의 각 점은 다음 상태 중 하나를 가진다.

| 상태 | 의미 | 표현 |
|---|---|---|
| 확정 | 매출·지출·인건비가 마감 기준을 충족 | 진한 실선·채움 |
| 잠정 | 카드 미매입, 급여 예상 등 변동 가능 | 점선·옅은 채움 |
| 불완전 | 연동 장애 또는 필수 데이터 누락 | 선 단절·경고 아이콘 |
| 마감 | 결산 snapshot으로 고정 | 자물쇠와 버전 표시 |

불완전한 날짜를 0원으로 간주해 정상 선으로 연결하지 않는다. 사용자가 `데이터 없음`과 `실제 0원`을 구분할 수 있어야 한다.

마감 이후 들어온 취소·지출은 기존 확정 차트를 조용히 변경하지 않는다. 재오픈하거나 다음 기간 조정 항목으로 반영한다.

## 5. 화면 구성

### 5.1 상단 제어영역

- 기간 탭: 일간, 주간, 월간, 연간
- 기준일/기준월/기준연도 선택
- 비교 기준: 이전 기간, 전년 동기간, 비교 안 함
- 데이터 상태 필터: 전체, 확정, 잠정
- 마지막 데이터 갱신 시각
- 결산 상태와 snapshot version

### 5.2 KPI 카드

1. 순매출
2. 운영지출
3. 인건비
4. 운영순익과 운영순익률

각 카드에는 현재 금액, 비교기간 금액, 증감액, 증감률을 표시한다. 이전 값이 0원이면 무한대 비율 대신 `비교 불가`와 증감액을 보여준다.

### 5.3 주 차트

기본 차트는 복합 차트다.

- 순매출: 파란색 선
- 운영지출: 주황색 선
- 인건비: 보라색 선
- 운영순익: 초록색 영역/선, 음수 구간은 빨간색
- 0원 기준선: 고정 표시
- 잠정 구간: 점선
- 불완전 구간: 선 단절

한 번에 너무 많은 선이 복잡하면 기본은 운영순익만 표시하고 범례 토글로 매출·지출·인건비를 켠다. 사용자가 선택한 상태는 사용자 preference로 저장한다.

### 5.4 보조 차트

- 운영순익률 추이
- 누적 운영순익
- 비용 구성: 식자재, 홀 구매, 카드수수료, 임대료, 기타
- 전 기간 대비 순익 변화 요인 waterfall

MVP는 `운영순익 추이`, `운영순익률`, `비용 구성`까지 구현하고 누적·waterfall은 2차로 분리한다.

### 5.5 Tooltip과 상세보기

차트 점을 선택하면 다음 정보를 표시한다.

- 날짜/기간
- 순매출, 운영지출, 인건비, 운영순익, 순익률
- 직전 비교기간 대비 증감
- 확정/잠정/불완전 상태와 원인
- 미증빙, 미대사 카드, 미확정 급여 건수
- `상세 원장 보기` 버튼

상세 drawer에서는 해당 점의 매출, 지출, 카드 거래, 영수증, 인건비 내역으로 drill-down한다.

## 6. 기간별 집계

| 화면 | 한 점의 단위 | 기본 비교 |
|---|---|---|
| 일간 | 시간대 또는 단일 일 합계 | 전일·최근 동일 요일 |
| 주간 | 일 | 직전 7일 |
| 월간 | 일 | 전월 동일 일수 |
| 연간 | 월 | 전년도 동월 |

주간의 시작 요일과 영업일 cutoff는 조직 설정을 사용한다. 자정을 넘겨 영업하는 사업장은 달력 날짜가 아니라 설정된 영업일 기준으로 매출·지출을 귀속한다.

월간 비교는 이전 달 전체가 아니라 현재 경과 일수와 동일한 일수 비교를 선택할 수 있어야 한다. 마감 보고서에서는 전체 기간끼리 비교한다.

## 8. 데이터 원천과 집계 순서

```text
POS 매출 이벤트
→ 영업일별 순매출

카드 이벤트 + 영수증 + 수기지출
→ 중복 제거·매칭
→ 확정/잠정 지출 원장

근태 + 급여 정책
→ 실제/예상 인건비

세 입력원
→ 일별 집계
→ 주·월·연 roll-up
→ snapshot
→ 차트·보고서
```

집계 우선순위:

1. 마감 기간은 저장된 snapshot
2. 미마감 기간은 최신 원장 집계
3. 카드 지출은 매입 확정액 우선, 없으면 승인 잠정액
4. 인건비는 확정 급여, 실제 근태 기반 초안, 달력 일할 추정 순
5. 데이터 원천 누락은 0원이 아니라 quality flag

## 9. 현재 구현 상태 점검

현재 구현됨:

- 일간·주간·월간·연간 기간 선택
- 순매출·운영지출·인건비·운영순익 KPI
- 운영순익과 순익률 산식
- 직전 기간 증감률
- 일별/월별 운영순익 단일 선 차트
- 0원 기준선과 양수/음수 좌표
- 증빙·카드 대사·카드 연결·인건비 누락 경고
- 결산 저장·확정·재오픈 이력
- CSV와 인쇄용 요약

보완 필요:

- 현재 `sales`가 완료 매출 중심이므로 취소·할인·환불을 명시적으로 분리
- 현재 지출은 `confirmed`만 집계하므로 카드 승인 잠정액 별도 series 추가
- 현재 인건비 fallback을 0원 또는 확정값처럼 보이지 않도록 상태 표시
- 매출·지출·인건비 복합 차트와 범례 토글
- 잠정 점선, 불완전 선 단절, 음수 영역 색상
- 개별 점 tooltip과 원장 drill-down
- 영업일 cutoff와 조직별 주 시작 요일
- 전년 동기간/동요일 비교
- 비용 구성·순익률 보조 차트
- snapshot 기반 화면·PDF·Excel 동일성
- 접근성, 모바일 가로 스크롤, 대량 데이터 downsampling 개선

## 10. 구현 단계

### 1단계 — 산식과 API 계약 고정

- 매출 취소·할인·환불 필드 분리
- confirmed/provisional/incomplete 상태 추가
- quality flag와 counts 추가
- 비교 불가와 0% 변화를 구분
- 영업일 cutoff 반영

완료 조건: 동일 fixture의 일·주·월·연 합계가 정확히 일치한다.

### 2단계 — 주 차트 개선

- 운영순익 중심 복합 차트
- 범례 토글, tooltip, 0원 기준선
- 잠정 점선·불완전 단절·음수 색상
- 기간별 축과 반응형 레이아웃

완료 조건: 사용자가 순익 변화와 데이터 확정 상태를 한 화면에서 구분한다.

### 3단계 — 상세 추적

- 점 선택 drawer
- 매출·지출·카드·영수증·인건비 구성내역
- 원장/원본 증빙 링크
- 조직·역할별 접근 통제

완료 조건: 모든 차트 금액을 원천 데이터까지 역추적할 수 있다.

### 4단계 — 보조 차트와 보고서

- 순익률, 비용 구성, 누적 순익
- PDF·Excel 차트 데이터 통일
- snapshot version과 확정 워터마크

완료 조건: 화면·CSV·PDF·Excel 합계와 버전이 동일하다.

## 11. 테스트 시나리오

필수 단위 테스트:

- 정상 흑자, 정확한 0원, 적자
- 순매출 0원일 때 순익률 null
- 이전 기간 0원일 때 증감률 비교 불가
- 승인 후 전체취소·부분취소
- 승인 잠정액이 매입 확정액으로 전환
- 영수증과 카드가 한 지출로 합쳐짐
- 급여 확정/예상/fallback
- 자정 이후 거래의 영업일 귀속
- 윤년·월말·연말·타임존
- 마감 후 후발 취소

필수 통합/E2E:

1. 매출·지출·근태 입력 후 운영순익 산식 확인
2. 카드 승인 수집 후 잠정 점선 표시
3. 매입 수집 후 확정 실선 전환
4. Provider 장애 날짜의 선 단절과 경고
5. 차트 점에서 원장·영수증까지 이동
6. 월마감 후 snapshot 불변 확인
7. 재오픈·조정 후 version 증가 확인
8. 화면·CSV·PDF·Excel 원 단위 합계 대사
9. 조직 A 사용자가 조직 B 차트·원장 접근 불가

## 12. 완료 기준

- 운영순익 산식과 포함 범위를 화면에서 확인할 수 있다.
- 잠정·확정·불완전·마감 상태가 시각적으로 구분된다.
- 승인·취소·매입·영수증 중복으로 순익이 왜곡되지 않는다.
- 매출·지출·인건비 중 순익 변화 원인을 찾을 수 있다.
- 모든 점에서 구성 원장과 증빙까지 추적할 수 있다.
- 일간 합계의 합이 주·월·연 집계와 일치한다.
- 화면·CSV·PDF·Excel의 금액과 snapshot version이 같다.
- 누락 데이터가 0원으로 표시되지 않는다.
- 다른 고객사의 재무 데이터에 접근할 수 없다.

## 13. 개발 우선순위 결론

현재 단일 운영순익 선 차트는 기본 동작 수준으로 구현되어 있다. 다음 개발은 디자인 확장보다 먼저 `순매출 원천 세분화`, `잠정/확정 상태`, `누락 데이터 quality flag`를 API에 추가해야 한다. 그 다음 복합 차트와 drill-down을 구현해야 숫자가 예뻐 보이지만 틀리는 문제를 방지할 수 있다.

최종 사용자 약속은 다음과 같다.

> TimeFit 순수익 차트의 모든 숫자는 매출·지출·인건비로 설명되고, 잠정과 확정이 구분되며, 원장과 증빙까지 추적할 수 있다.
