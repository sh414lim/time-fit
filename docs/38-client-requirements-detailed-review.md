# TimeFit 클라이언트 요구사항 상세 검토

## 결론

요구사항은 크게 **근태 원천 데이터 → 급여 마감 → 세무 협업 → 직원 알림** 흐름으로 구성된다. 현재 MVP의 스케줄·출퇴근·휴가 기능은 원천 데이터 단계에 해당하며, 급여·세무 자동화는 데이터 정합성과 승인 절차가 먼저 갖춰져야 한다.

권장 원칙은 다음과 같다.

- 시스템은 계산·자료생성·알림을 자동화한다.
- 급여 확정, 세금 신고, 4대보험 신고, 퇴직금 최종 지급은 관리자 또는 세무 담당자의 승인 후 처리한다.
- 법정 요율·양식·신고기한은 변경될 수 있으므로 코드 상수로 고정하지 않고 적용 기간이 있는 정책 데이터로 관리한다.

## 1. 급여 및 스케줄 정리

### 기능 정의

| 구분 | 상세 요구사항 | 완료 기준 |
| --- | --- | --- |
| 근태 집계 | 스케줄, 실제 출퇴근, 휴가, 휴무를 직원·일자 단위로 결합 | 한 직원의 특정 날짜에 예정/실제/휴가 상태를 함께 조회 |
| 급여 산정 | 시급·일급·월급별 기본급과 근무시간 기반 예상액 계산 | 산정 근거와 예상 금액을 직원별로 표시 |
| 예외 처리 | 지각, 조기퇴근, 결근, 휴게시간, 휴일근무를 별도 상태로 기록 | 관리자가 집계 전 수정·사유 기록 가능 |
| 마감 | 월별 초안 → 검토 → 확정 → 발송 상태 관리 | 확정 후 원천 근태 수정은 재마감 절차 필요 |

### 반드시 추가할 데이터

- 급여 계약: 급여 형태, 기준 단가, 계약 시작·종료일, 적용 파트.
- 근태 확정: 실제 출퇴근 수정 사유, 승인자, 승인 시각.
- 급여 항목: 기본급, 연장수당, 야간수당, 휴일수당, 식대·상여 등 지급 항목과 공제 항목.
- 급여 마감: 대상 월, 상태, 확정자, 확정 시각, 재마감 이력.

### 주요 검토 의견

- 현재 `예상 인건비`는 운영 대시보드 지표로 유지하고, 법정 급여 계산은 별도 급여 마감 모듈로 분리하는 것이 안전하다.
- “스케줄 기준 급여”와 “실제 출퇴근 기준 급여”를 동시에 표시해야 관리자가 차이를 검토할 수 있다.
- 급여 산정 로직 변경 후 과거 마감 월의 금액이 바뀌지 않도록, 마감 시점의 산정 규칙과 결과를 스냅샷으로 저장해야 한다.

## 2. 월말 정산 및 세무 서류 자동 정리

### 권장 업무 흐름

1. 관리자가 정산 월과 대상 직원을 확인한다.
2. 시스템이 근태 누락·미승인 휴가·미확정 출퇴근을 검증한다.
3. 급여 초안을 생성한다.
4. 관리자가 직원별 급여 항목을 검토·확정한다.
5. 세무사 전달용 파일과 요약 이메일 초안을 생성한다.
6. 관리자가 발송 승인 후 이메일을 보낸다.

### 자동 생성 대상

| 자료 | 대상 | 최소 포함 항목 |
| --- | --- | --- |
| 근태 집계표 | 관리자·세무사 | 예정/실근무 시간, 휴가, 휴무, 보정 이력 |
| 급여대장 | 관리자·세무사 | 지급·공제 항목, 총지급액, 실지급액 |
| 직원별 명세 데이터 | 관리자·직원 | 개인별 산정 근거와 지급 내역 |
| 세무 전달 요약 | 세무사 | 사업장 합계, 직원 수, 변경·예외 목록 |

### 검토 의견

- 초기 버전은 **CSV/XLSX 생성 + 세무사 이메일 발송**까지로 제한하고, 홈택스·4대보험 전자신고 직접 제출은 후순위로 권장한다.
- 국세청의 원천징수 및 지급명세서 제출 기한은 소득 유형과 납부 방식에 따라 다르므로, 서비스는 기한 알림과 자료 초안을 제공하되 최종 신고 기능으로 표현하면 안 된다. [국세청 신고 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7702&mi=2376)

## 3. 퇴직금·4대보험·세금 계산

### 기능을 세 단계로 분리

| 단계 | 제공 기능 | 결과 표현 |
| --- | --- | --- |
| 1차 | 예상 계산 | “예상액”, 산정 기준일·입력값 공개 |
| 2차 | 검토 보정 | 세무·노무 담당자 수정 및 메모 |
| 3차 | 확정 기록 | 확정자·확정일·적용 규칙 버전 저장 |

### 퇴직금

- 입사일, 퇴사일, 제외 기간, 최근 3개월 임금, 상여·연차수당, 평균임금·통상임금을 입력·검토할 수 있어야 한다.
- 퇴직금은 단순히 누적 월급으로 계산하면 안 된다. 고용노동부 계산기는 퇴직 전 3개월 임금, 상여금 및 연차수당 등을 입력 요소로 사용하며, 회사 내규 등에 따라 실제 지급액이 달라질 수 있음을 안내한다. [고용노동부 퇴직금 계산기](https://www.moel.go.kr/retirementpayCal.do)
- 따라서 1차 출시에서는 “퇴직금 예상 계산”만 제공하고, 확정·지급은 담당자 승인 기능으로 제한한다.

### 4대보험·세금

- 보험 가입 대상, 보수월액, 입·퇴사, 휴직, 보수 변경, 사업장별 예외를 입력값으로 분리한다.
- 근로소득 원천징수는 매월 급여 지급 시 간이세액표 등을 바탕으로 계산되므로, 가족 공제·선택 세율·비과세 등 개인별 입력이 없으면 정확한 확정 세액을 보장할 수 없다. [국세청 근로소득 안내](https://s.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7862&mi=6426)
- 요율 테이블은 `적용 시작일`, `적용 종료일`, `보험 종류`, `근로자 부담`, `사업주 부담`, `상·하한`을 갖는 버전형 테이블로 설계한다.

### 출시 전 필수 결정

1. 근로자·일용근로자·사업소득자 구분.
2. 비과세 수당과 상여금의 운영 여부.
3. 4대보험 취득·상실 신고를 누가 최종 수행하는지.
4. 퇴직금 계산 결과를 세무사·노무사 중 누가 승인하는지.

## 4. 세무사 이메일 발송

### 필수 기능

- 사업장별 수신자·참조자 관리.
- 기간, 첨부 파일, 이메일 제목·본문을 관리자에게 미리 보여 주기.
- `초안 → 발송 승인 → 발송 완료/실패` 상태.
- 발송자, 수신자, 첨부 파일 해시, 발송 시각, 실패 사유를 감사 로그로 저장.

### 보안·운영 기준

- 급여 파일은 민감 정보이므로 공개 URL이 아닌 만료 가능한 서명 URL 또는 암호화된 첨부 방식으로 전달한다.
- 이메일 재발송 시 같은 마감본인지 확인하기 위해 급여 마감 버전 번호를 제목과 첨부 파일명에 포함한다.
- 자동 발송이 아니라 관리자 최종 클릭 발송을 기본값으로 한다.

## 5. 카카오 알림톡

### 이벤트와 수신자

| 이벤트 | 수신자 | 메시지에 포함할 최소 정보 |
| --- | --- | --- |
| 휴가 신청 | 관리자 | 직원명, 날짜, 휴가 유형, 관리 화면 링크 |
| 휴가 승인·반려 | 직원 | 처리 결과, 날짜, 관리자 메모 |
| 스케줄 변경 | 직원 | 변경 날짜, 근무 시간, 근무 형태 |
| 급여 명세 준비 | 직원 | 대상 월, 앱 확인 링크 |
| 정산 자료 준비 | 관리자 | 대상 월, 검토·발송 링크 |

### 설계 원칙

- 이벤트 발생과 메시지 발송을 분리한다. 업무 DB 저장 성공 후 알림 발송 큐에 적재한다.
- 템플릿 승인 상태와 발송 실패 재시도 횟수를 관리한다.
- 직원의 수신 동의, 전화번호 변경, 퇴사 상태를 발송 직전에 검증한다.
- 알림톡은 카카오 승인 템플릿과 공식 발송 대행사 계약이 선행되어야 한다.

## 6. 스케줄표 작성 및 직관적 UI

### 관리자 UI 요구사항

- 일간: 직원별 상세 일정과 수정·삭제.
- 주간: 일자별 인원수와 근무 형태 분포.
- 월간: 전체 날짜의 근무·휴무·휴가 수와 일정 존재 여부.
- 일괄 등록: 복수 직원 × 복수 날짜 × 하나의 근무 형태를 한 번에 저장.
- 필터: 파트, 근무 형태, 직원 상태, 휴가 여부.
- 경고: 미배정 직원, 휴가와 근무 중복, 필수 인원 미달.

### 직원 UI 요구사항

- “오늘 근무”와 “다음 근무”를 최상단에 표시.
- 개인 월간 스케줄과 휴가 승인 상태를 간단히 조회.
- 스케줄 변경 시 변경 전·후 정보를 표시.

### 수용 기준

- 모바일 360px 폭에서 스케줄 카드의 시간·근무형태·상태가 잘리지 않는다.
- 모든 직원 행은 상세 화면으로 이동한다.
- 일정 수정·삭제는 확인 모달과 로딩 상태를 제공한다.
- 월간 보기의 모든 해당 월 날짜에서 집계 정보가 표시된다.

## 7. 직원 관리 및 파트별 분리

### 권한 모델 권장안

| 역할 | 직원 정보 | 스케줄 | 급여·세무 | 운영 설정 |
| --- | --- | --- | --- | --- |
| 전체 관리자 | 전체 조회·수정 | 전체 관리 | 조회·마감·발송 | 가능 |
| 파트 관리자 | 담당 파트만 | 담당 파트만 | 불가 또는 요약만 | 불가 |
| 직원 | 본인만 | 본인만 조회 | 본인 명세만 | 불가 |

### 데이터 모델 검토

- `timefit_user_parts`: 사업장별 파트 이름, 색상, 정렬 순서, 활성 상태.
- `timefit_user_staff_parts`: 직원과 파트의 다대다 연결, 기본 파트, 적용 기간.
- `timefit_user_work_schedules`: 필요 시 파트·근무 위치를 함께 저장.
- `timefit_user_role_assignments`: 역할, 범위(사업장/파트), 적용 기간.

### 주의할 점

- 현재 직원의 `department` 단일 필드만으로는 겸임, 파트 이동 이력, 파트 관리자 범위를 표현하기 어렵다.
- 파트별 권한 도입 시 Supabase RLS도 동일한 범위로 재설계해야 한다.

## 권장 로드맵

| 단계 | 범위 | 선행 조건 |
| --- | --- | --- |
| 1 | 파트 관리·스케줄 필터·근태 확정 | 직원/스케줄 CRUD 정합성 |
| 2 | 급여 항목·급여 초안·마감·CSV/XLSX | 근태 확정 및 급여 계약 데이터 |
| 3 | 세무사 이메일·알림톡 | 문서 생성, 템플릿·발송사 계약 |
| 4 | 4대보험·세금·퇴직금 예상 계산 | 세무·노무 계산 규칙 확정 |
| 5 | 외부 전자신고·회계 서비스 연동 | 운영 검증 및 책임 범위 확정 |

## 최종 확인 질문

1. 급여는 실제 지급까지 관리할지, 세무사 전달용 정산 초안까지만 관리할지.
2. 세무·노무 전문가는 이미 지정되어 있는지, 계산 규칙 검토를 누가 승인하는지.
3. 파트 관리자에게 직원 개인정보와 급여 정보 중 어디까지 공개할지.
4. 알림톡 발송 비용 부담 및 문자 대체 발송 정책.
5. 급여대장·명세서의 최종 파일 형식(CSV, XLSX, PDF)과 세무사 사용 프로그램.
