# 실제 매출·지출·인건비 통합 손익 현황 UI·UX 및 기능 설계

작성일: 2026-11-20  
대상: TimeFit 웹 관리자 `정산·매출` 영역  
목표: POS 실제 매출, Granter 장부 지출, TimeFit 실제 인건비를 중복 없이 결합해 일·주·월·연 단위 운영손익을 판단하게 한다.

## 1. 결론

화면 명칭은 `순수익`보다 **운영손익**을 사용한다.

```text
추정 운영순익 = 순매출 - 재료·상품 구매비 - 실제 인건비 - 운영지출
운영순익률 = 추정 운영순익 / 순매출 × 100
```

법인세, 감가상각, 금융손익, 재고 실사 차이가 모두 반영되기 전에는 회계상 `당기순이익` 또는 `순수익 확정`이라고 표기하지 않는다. 특히 재고의 기초·기말 수량이 연결되기 전에는 `매출원가`가 아니라 `재료·상품 구매비`라고 표기한다. 데이터 완결 상태에 따라 `잠정 운영순익`, `추정 운영순익`, `확정 운영순익`을 구분한다.

### 데이터 조회 방식 결론

외부 API를 화면 진입마다 직접 호출하지 않고 **DB 저장 + 백그라운드 배치 + 저장 스냅샷 조회**의 하이브리드 구조를 사용한다.

```text
Granter·POS 원천 API
  → 3시간 주기 배치 또는 사용자 수동 동기화
  → 원천 식별자를 보존한 finance_facts 저장
  → 기간별 profit_snapshots 재계산
  → 화면은 snapshot 즉시 조회
```

- Granter 원천 거래는 화면 표시 한도 4,000건과 분리해 해당 기간 전체를 사실 테이블에 저장한다.
- 페이지 이동·복귀는 외부 API를 호출하지 않는다.
- `저장 데이터 다시 계산`은 DB 자료만 재집계한다.
- `외부 데이터 동기화`만 Granter·POS API를 호출한다.
- 배치는 현재 월을 3시간마다 증분 갱신하고, 과거 기간은 사용자의 명시적 재동기화 때만 갱신한다.

## 2. 현재 기능과 보완점

### 이미 있는 기능

- Toss Place 완료 매출 기반 순매출 집계
- 급여 초안과 출퇴근 기록 기반 인건비 배분
- 타임핏 확정 지출과 미대사 카드 지출 집계
- 일·주·월·연 기간 전환
- 운영순익 카드, 추이 차트, 손익 브리지, PDF·Excel·CSV
- 결산 저장·확정·재오픈·버전 관리
- Granter 전체 기간 장부 수집, 계정과목·태그·자산·거래처·세금계산서 분석

### 현재 부족한 부분

- Granter 실제 장부가 기존 `finance-report` 손익 계산에 직접 연결되지 않음
- Granter 급여 이체와 TimeFit 인건비를 함께 더하면 이중 차감 가능
- POS 매출과 통장 입금·카드 정산을 함께 매출로 잡으면 이중 매출 가능
- 영수증, 법인카드, Granter 통장 거래가 같은 지출인지 판별하는 우선순위 부족
- 구매비, 운영비, 자산 취득, 대출, 세금, 계좌이체 구분이 손익 기준으로 완전히 정규화되지 않음
- 숫자별 원천·완결 상태를 대표가 즉시 판단하기 어려움

## 3. 메뉴와 정보 구조

`정산·매출`에 최상위 메뉴 **손익 현황**을 추가한다.

```text
정산·매출
├─ 매출 분석       POS 주문·메뉴·시간대 분석
├─ 손익 현황       매출·원가·인건비·지출·운영순익 통합
├─ 급여 관리       직원별 급여 계산과 확정
└─ 지출·증빙       Granter, 카드, 통장, 영수증, 결산 원장
```

손익 현황 내부 탭:

1. `경영 요약`: 대표가 가장 먼저 보는 기본 화면
2. `매출`: POS 매출, 취소, 할인, 주문
3. `비용`: 매출원가와 운영지출, 계정과목·거래처
4. `인건비`: 실제·예상 인건비, 부서별 인건비율
5. `결산`: 완결성, 스냅샷, 확정·재오픈, 출력

## 5. 데이터 원천과 우선순위

### 5.1 매출

| 우선순위 | 원천 | 손익 반영 | 비고 |
|---:|---|---|---|
| 1 | Toss Place 완료 매출 | 순매출 | 취소·할인 반영 후 발생일 기준 |
| 2 | Granter 가맹점 카드매출 | 보조 검증 | POS 미연결 시만 대체 원천 |
| 3 | Granter 가맹점 정산·통장 입금 | 현금흐름 전용 | POS 매출과 중복되므로 손익 매출 제외 |

원칙: POS가 연결된 사업장은 통장 입금이나 카드 정산액을 추가 매출로 합산하지 않는다.

### 5.2 인건비

| 우선순위 | 원천 | 화면 상태 |
|---:|---|---|
| 1 | 확정 급여·마감 스냅샷 | 실제 |
| 2 | 저장된 급여 초안 | 잠정 실제 |
| 3 | 출퇴근 × 계약 단가 | 추정 |
| 4 | 스케줄 × 계약 단가 | 예상 |

Granter의 `직원급여`, `일용직잡급`, 4대보험 계정은 현금 지급 확인에 사용하되 TimeFit 인건비와 다시 합산하지 않는다. 4대보험 사업주 부담분을 인건비에 포함할지는 조직 설정으로 분리한다.

### 5.3 지출

| 원천 | 처리 |
|---|---|
| Granter 출금·카드·세금계산서 | 실제 지출의 기본 원천 |
| TimeFit 영수증과 연결된 Granter 거래 | 하나의 지출로 병합 |
| 거래 미연결 영수증 | 잠정 지출, 거래 연결 시 교체 |
| Granter에 없는 수기 지출 | 타임핏 수기 지출로 반영 |
| 미대사 법인카드 | 잠정 지출 |

### 5.4 손익 제외 항목

- 내부 계좌이체
- 대출 실행·상환 원금
- 자본금·투자금
- 부가세 예수금·대급금
- 자산 취득 중 비용 처리하지 않는 항목
- 대표자 인출·가지급금
- POS 매출과 이미 대응되는 카드 정산·통장 입금
- TimeFit 인건비와 이미 대응되는 급여 이체

제외 항목은 사라지지 않고 `현금흐름` 탭에서 별도로 보여준다.

## 6. 중복 제거 규칙

각 원천은 다음 표준 키로 비교한다.

```text
organization_id
occurred_on
direction
amount
merchant/business_number
card_approval_number 또는 bank_transaction_id
source_system + source_id
```

매칭 우선순위:

1. Granter 고유 거래 ID가 같은 항목
2. 카드 승인번호가 같은 항목
3. 계좌 거래 ID가 같은 항목
4. 사업자번호 + 금액 + 거래일이 같은 항목
5. 업체명 + 금액 + 거래일 ± 1일인 항목은 자동 확정하지 않고 검토 후보

하나의 지출에 카드, 통장, 세금계산서, 영수증이 여러 개 연결될 수 있지만 손익 금액은 한 번만 반영한다.

## 7. 비용 분류 체계

Granter 계정과목을 다음 손익 버킷으로 매핑한다.

| 손익 버킷 | 예시 | 손익 처리 |
|---|---|---|
| 재료·상품 구매비 | 식자재, 주류, 포장재 | 구매비 차감 |
| 인건비 | 급여, 잡급, 사업주 사회보험 | 인건비 차감 |
| 운영지출 | 임차료, 수도광열비, 수수료, 광고비 | 운영지출 차감 |
| 금융·세금 | 이자, 법인세, 부가세 | 운영순익 아래 별도 표시 |
| 자산·부채 | 비품 자산화, 보증금, 대출 원금 | 손익 제외 |
| 내부이체 | 계좌 간 이동 | 손익 제외 |
| 미분류 | 자동 매핑 실패 | 잠정 운영지출, 경고 표시 |

관리자는 `계정과목 매핑 관리`에서 Granter 계정과목의 손익 버킷을 변경할 수 있다. 변경은 적용 시작일과 변경 이력을 보존한다.

## 8. 계산 규칙

### 8.1 기본 산식

```text
순매출 = 완료 매출 - 취소 - 할인
매입 차감액 = 순매출 - 재료·상품 구매비
추정 운영순익 = 매입 차감액 - 실제 인건비 - 운영지출
운영순익률 = 추정 운영순익 / 순매출 × 100
```

### 8.2 표시 상태

| 상태 | 조건 | 표시 |
|---|---|---|
| 확정 | 매출 마감, 지출 분류·증빙, 급여 확정, 원천 동기화 완료 | `확정 운영순익` |
| 잠정 | 미증빙 카드·미분류 지출이 있지만 금액은 확보 | `잠정 운영순익` |
| 추정 | 급여 초안·예상값 또는 미래 예측 포함 | `추정 운영순익` |
| 불완전 | 매출·지출·급여 핵심 원천 누락 | 금액 옆 경고, 결산 확정 금지 |

### 8.3 완결도 점수

```text
매출 동기화 30점
Granter 지출 동기화 30점
급여 확정 25점
계정과목 분류·증빙 15점
```

- 100점: 확정 가능
- 80~99점: 잠정
- 80점 미만: 불완전

점수 자체보다 누락 금액과 처리 행동을 함께 표시한다.

## 9. 상호작용

- KPI 클릭: 같은 기간을 유지한 채 해당 원장으로 드릴다운
- 차트 날짜 클릭: 매출·지출·인건비 상세를 한 화면에서 비교
- 비용 구간 클릭: Granter 계정과목과 거래처로 필터
- 인건비 클릭: 부서 → 직원 → 근무일 순으로 탐색
- 순익 클릭: 손익 브리지와 산식 패널 표시
- 브라우저 뒤로가기: 기간, 탭, 필터, 스크롤, 선택 행 복원
- `새로고침`: 저장된 스냅샷 재조회
- `외부 데이터 동기화`: Granter·POS 원천 재수집

| `source_system`, `source_type`, `source_id` | 원천과 고유 식별자 |
| `sync_run_id`, `source_revision`, `source_hash` | 동기화·변경 추적 |
| `occurred_on`, `direction`, `amount` | 발생일, 입출금, 금액 |
| `profit_bucket`, `include_in_profit` | 손익 분류와 포함 여부 |
| `is_provisional`, `is_source_included` | 잠정·원천 포함 상태 |
| `source_category_*`, `business_number`, `asset_*` | 분류와 매칭 정보 |

#### `timefit_user_profit_snapshots` — 1단계 구현

| 컬럼 | 설명 |
|---|---|
| `snapshot_key`, `period_start`, `period_end`, `group_by` | 집계 캐시 키 |
| `status`, `calculation_version` | 실제·잠정·불완전 및 계산 버전 |
| `totals`, `series`, `breakdown` | 화면 즉시 표시에 필요한 집계 |
| `completeness`, `source_versions` | 하드 게이트와 원천 버전 |
| `generated_at` | 계산 시각 |

#### `timefit_user_finance_fact_links` — 2단계 예정

| 컬럼 | 설명 |
|---|---|
| `organization_id` | 사업장 |
| `canonical_key` | 하나의 실제 거래를 나타내는 키 |
| `source_system`, `source_type`, `source_id` | 연결된 원천 |
| `match_method` | exact_id, approval_number, amount_date, manual |
| `match_confidence` | 0~100 |
| `is_primary` | 손익 금액 대표 원천 여부 |
| `linked_at`, `linked_by` | 연결 이력 |

#### 결산 필드 확장

`timefit_user_closeouts`와 `timefit_user_closeout_lines`에 다음 값을 저장한다.

- 순매출, 매출원가, 매출총이익
- 실제 인건비, 운영지출
- 운영순익, 운영순익률
- 잠정 금액, 미분류 금액
- 원천 버전, 계산 버전, 완결도 점수

## 11. API 설계

### `GET /api/profit-overview`

입력:

```json
{
  "organizationId": "uuid",
  "from": "2026-11-01",
  "to": "2026-11-30",
  "groupBy": "day",
  "view": "actual"
}
```

응답 주요 항목:

- `totals`: netSales, purchaseCost, grossContribution, laborCost, operatingExpenses, operatingProfit, profitMargin
- `series`: 날짜별 실제·잠정·예상 값
- `breakdown`: 계정과목, 거래처, 부서, 직원
- `completeness`: 원천별 상태, 점수, 누락 금액
- `actions`: 사용자가 처리할 항목
- `sourceVersions`: POS, Granter, payroll 스냅샷 버전

### 성능

- 페이지 진입은 최신 저장 스냅샷을 즉시 반환한다.
- POS·Granter·급여 원천 동기화는 백그라운드로 수행한다.
- 원천 버전이 바뀐 경우에만 손익 스냅샷을 재계산한다.
- 사업장·기간·집계단위별 캐시를 사용한다.
- 화면 이동 후 복귀 시 기간·탭·데이터·스크롤을 복원한다.

## 12. 권한

| 권한 | 가능 범위 |
|---|---|
| `sales.view` | 매출만 조회 |
| `finance.view` | 지출·손익 총액 조회 |
| `payroll.view` | 인건비 총액과 직원별 내역 조회 |
| `finance.close` | 결산 저장·확정 |
| Owner | 계정과목 매핑과 결산 재오픈 |

`payroll.view`가 없는 관리자는 총 인건비만 볼지, 인건비 자체를 숨길지 조직 정책으로 결정한다. 기본값은 인건비와 운영순익을 숨기는 최소권한 정책이다.

## 13. 개발 순서

### 1단계: 실제 손익 통합 — 핵심 구현 완료, 운영 반영 전

- Granter 계정과목 손익 매핑
- 매출·Granter 지출·TimeFit 인건비 서버 집계

- KPI와 손익 브리지 연결
- Granter 사실 데이터 DB 저장과 3시간 배치
- 손익 스냅샷 조회 API와 화면 진입 시 외부 호출 차단

### 2단계: 분석 UX

- 일·주·월·연 추이
- 비용 구성, 거래처·계정과목 드릴다운

- 화면·PDF·Excel 합계 일치
- 화면 이동 후 기간·필터·데이터 유지
- 소유자와 서브관리자 권한 분리
