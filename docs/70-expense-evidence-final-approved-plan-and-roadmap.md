# TimeFit 지출·증빙·법인카드·자동결산 최종 승인 기획 및 개발 로드맵

버전: 1.0  
확정일: 2026-09-10  
상태: 개발 착수 승인안  
제품 범위: 법인카드 자동 연결, 영수증 OCR, 지출 원장, 매출·인건비 연동, 일·주·월·연말 결산

## 1. 최종 제품 정의

> 법인카드를 연결하면 카드와 거래내역이 자동으로 들어오고, 직원이 영수증을 촬영하면 거래와 자동 대조되며, 관리자는 예외만 처리해 매장 운영손익과 결산보고서를 완성하는 서비스

TimeFit은 범용 회계 ERP 전체를 한 번에 구현하지 않는다. 기존의 직원, 스케줄, 출퇴근, 급여, Toss Place 매출 데이터를 지출·증빙과 연결해 매장 관리자의 입력·대조·보고 업무를 최소화한다.

## 2. 출시 핵심 기능

### 법인카드

- 하이픈 또는 금융 데이터 제공자를 통한 실제 카드사 연결
- 사업자 인증 후 보유카드 자동 조회·등록
- 카드별 별칭, 담당 직원, 부서, 기본 계정과목 지정
- 최근 90일 승인·취소·부분취소·매입 내역 자동 수집
- 기본 6시간, 활성 카드 영업시간 중 1시간 자동조회
- 최근 7일 재대조와 월초 전월 매입 대조
- 연결 상태, 최근 성공, 다음 조회, 실패 원인 표시
- 재인증, 오류 기간 재조회, 연결 해제
- CSV/Excel과 승인 이메일을 장애 폴백으로 지원

### 영수증·증빙

- 모바일 후면 카메라 촬영과 갤러리 업로드
- JPG, PNG, HEIC, PDF 지원
- 흐림·반사·잘림·회전·파일 크기 검사
- 비공개 Storage 저장과 signed URL 조회
- Google Vision OCR
- LLM JSON Schema 구조화
- 금액·부가세·날짜·사업자번호의 서버 규칙 검증
- 원본·OCR·추출 결과 비교 및 수정
- 재처리, 제외, 병합, 감사 기록

### 지출 원장

- 카드 API, CSV, 이메일, 영수증을 원천자료로 저장
- 원천자료가 여러 개여도 확정 지출은 한 건
- 승인→취소→매입→청구를 하나의 거래 생명주기로 관리
- 카드와 영수증의 자동 매칭 후보
- 관리자 확정·수정·병합·해제
- 계정과목, 거래처, 태그, 사유, 사용 직원
- 미증빙·미매칭·중복 의심·저신뢰 OCR 예외 업무함

### 보고·결산

- 일간 운영보고
- 주간 경영보고
- 월간 결산보고
- 연말 경영보고
- 매출·지출·인건비·운영순익 차트
- 마감, 잠금, 스냅샷, 버전, 재오픈, 조정
- 웹, PDF, Excel, ZIP 보고서
- 보고서 숫자에서 원장과 원본 영수증까지 추적

## 3. 핵심 산식

```text
순매출 = 총매출 - 매출취소 - 할인

운영순익(추정)
= 순매출 - 확정 운영지출 - 실제 인건비
```

법인세, 감가상각, 금융손익, 완전한 매출원가가 아직 포함되지 않으므로 `당기순이익`이라는 명칭은 사용하지 않는다. 재고·원재료 매출원가가 연동된 조직에서만 `영업이익(추정)`을 제공한다.

### 잠정과 확정

- 카드 승인액: 일간 운영의 잠정 지출
- 카드 매입액: 월마감의 기본 확정 지출
- 미확정 OCR 지출: 합계에서 제외하고 검토 대기
- 예상 인건비: 실제 인건비와 분리
- 증빙 없는 카드 지출: 지출에는 포함하고 증빙률에 경고

## 4. 사용자 흐름

### 사업자 카드 연결

```text
카드사 자동 연결
→ 수집·이용 동의
→ 법인/개인사업자 선택
→ 공동인증서 또는 카드사 인증
→ 보유카드 자동 조회
→ 사용할 카드 선택
→ 담당 직원·기본 분류 지정
→ 90일 내역 자동 수집
→ CSV 일별 합계 대조
→ 자동조회 활성화
```

자동 발견된 카드를 무조건 모두 운영 카드로 만들지 않고 소유자가 사용할 카드를 확인한다. 카드번호 전체, CVC, 비밀번호는 저장하지 않는다.

### 직원 영수증 제출

```text
영수증 촬영
→ 사진 품질 확인
→ 지출 목적 선택/간단 메모
→ 업로드
→ OCR·AI 자동 처리
→ 카드 거래 후보 자동 탐색
→ 제출 완료
```

직원에게 상호, 공급가액, 부가세, 계정과목을 처음부터 모두 입력시키지 않는다. 문제가 있을 때만 수정 요청한다.

### 관리자 처리

```text
확인 필요함
→ 원본·OCR·카드 후보 비교
→ 확정/수정 후 확정/병합/제외
→ 지출 원장 반영
→ 미마감 보고 자동 재계산
```

### 월간 결산보고

- 순매출, 지출, 인건비, 운영순익, 순익률

- 고정비·변동비와 계정과목 구성
- 카드 승인·취소·매입·미매입·결제예정

## 7. 순익 차트

필수 차트:

1. 매출·지출·인건비·운영순익 추이
2. 운영순익률 추이
3. 비용 구성
4. 계정과목별 지출 순위
5. 증빙 완료·미증빙·검토대기
6. 카드 승인·취소·매입·미매입
7. 예상·실제 인건비 비교
8. 월중·연중 누적 운영순익

확정값은 실선, 잠정값은 점선으로 표시한다. 누락 데이터 구간을 정상 선으로 이어 보이지 않는다. 차트의 점과 항목을 누르면 구성 거래와 원본 증빙까지 이동한다.

## 8. 보고서 출력

- 웹: 실시간 탐색과 drill-down
- PDF: 경영보고, 결재, 보관
- Excel: 원장 검토와 세무사 전달
- ZIP: PDF, Excel, 증빙 인덱스, 선택 원본 묶음

화면 KPI, 차트, PDF, Excel은 동일한 집계 API와 `snapshot_version`을 사용한다. 마감된 보고서는 이후 동기화로 변경되지 않으며 재오픈 후 다시 마감하면 버전이 증가한다.

## 9. 기술 환경

| 영역 | 확정 기술 |
|---|---|
| 웹 | React 18 + Vite 5 |
| DB/Auth/RLS | Supabase PostgreSQL/Auth |
| 파일 | Supabase 비공개 Storage |
| 서버 연동 | Vercel Functions |
| 정기 작업 | Vercel Cron + DB 작업 큐 |
| 카드 | Provider Adapter + 하이픈 우선 |
| OCR | Google Cloud Vision |
| 구조화 | JSON Schema 지원 LLM |
| 매출 | 기존 Toss Place 연동 |
| 테스트 | Vitest, React Testing Library, Playwright |
| 배포 | Vercel Preview/Production 분리 |

환경은 Local, Preview, Production을 분리한다. 하이픈·Vision·LLM 키는 서버 환경변수 또는 비밀 저장소에 두고 `VITE_` 접두어를 사용하지 않는다.

## 10. 핵심 데이터 구조

```text
card_connections
└─ connection_assets
   └─ corporate_cards
      ├─ card_sync_runs/cursors
      └─ card_transaction_events
         └─ card_transaction_groups

expense_documents
└─ expense_processing_runs

expense_sources ─ expense_matches ─ expenses
                                      └─ closeouts/closeout_lines
```

### 중요 제약

- 공급자 이벤트: `(organization_id, provider, provider_event_id)` unique
- 파일: SHA-256 unique 검사
- 이메일: Message-ID 중복 검사
- 지출: 조직별 불변 ledger entry ID
- 결산: 확정 지출 ledger entry ID를 한 번만 합산
- 조직별 RLS와 서버 권한 재검증

현재 카드 삭제 시 거래 cascade 삭제 정책은 연결 해제·과거 원장 보존 정책으로 변경해야 한다.

## 13. 개발 로드맵

### Sprint 0 — 외부 조건·설계 고정, 1주

- 하이픈 상품·테스트베드·명세·견적 확보
- 카드사별 인증과 지원 범위 확인
- 개인정보 흐름·보존·파기 정책
- ERD, API contract, wireframe, fixture 확정

완료: 실제 연동을 막는 미확정 사항과 provider 필드가 문서화됨.

### Sprint 1 — 카드 이벤트와 지출 원장, 2주

- connection, asset, sync, event, group, expense, source, match 테이블
- RLS와 감사 로그
- 기존 카드·CSV 데이터 무손실 이관
- 카드 삭제 cascade 제거
- mock provider와 정규화 단위 테스트
- 자동 연결/수동 등록 CTA 분리

완료: 승인→부분취소→매입이 한 거래와 한 지출로 계산됨.

### Sprint 2 — 무료 폴백, 1주

- CSV 컬럼 매핑·미리보기·오류 리포트
- 파일·행 멱등 처리
- 승인 이메일 provider 골격
- 재업로드·부분 실패 복구

완료: 같은 CSV를 세 번 올려도 합계가 변하지 않음.

### Sprint 3 — 법인카드 자동 연결, 3주

- 하이픈 OAuth·provider adapter
- 연결 동의·사업자 인증
- 보유카드 조회·선택·자동 등록
- 최근 90일 백필과 진행률
- 승인·취소·부분취소·매입 자동조회
- 정기 동기화·재인증·연결 해제
- 비용·오류·데이터 신선도 모니터링

완료: 테스트 카드의 거래가 자동 수집되고 CSV 일별 순액과 일치함.

### Sprint 4 — 영수증 촬영·OCR·매칭, 3주

- 모바일 촬영·갤러리·업로드 재시도
- 이미지 품질 검사와 HEIC 처리
- Vision OCR·LLM JSON·결정적 검증
- 원본/추출 비교 검수
- 카드 거래 후보 추천·확정·병합·해제

완료: 대표 영수증 세트가 처리되고 카드 거래와 중복 없이 연결됨.

### Sprint 5 — 예외 업무와 자동화, 2주

- 미증빙·미매칭·중복·저신뢰·동기화 실패 업무함
- 카드/가맹점별 담당자·계정과목 규칙
- 미제출 리마인드와 일간 요약
- 일괄 승인·수정
- 관리자 처리시간 측정

## 15. 테스트·완료 기준

### 필수 E2E

```text
실제 카드 연결
→ 카드 자동 등록
→ 승인·취소·매입 자동조회
→ 영수증 촬영·OCR
→ 카드 거래 자동 추천·확정
→ 지출 원장 1건
→ 일간·주간·월간 보고 반영
→ 순익 차트 표시
→ 마감 PDF·Excel 생성
→ 원본 영수증까지 추적
```

### 출시 게이트

1. API·CSV·이메일·영수증 복수 유입이 한 지출로 수렴한다.
2. 전체취소·부분취소·지연매입의 순액이 정확하다.
3. 같은 동기화 재실행 시 중복이 없다.
4. 화면 KPI·차트·PDF·Excel 합계가 같다.
5. 잠정값·확정값·누락 구간을 구분한다.
6. 마감된 보고서는 이후 동기화로 변경되지 않는다.
7. 모든 숫자를 원장과 원본 증빙까지 추적할 수 있다.
8. 연결 해제 후 인증정보는 파기되고 과거 원장은 유지된다.
9. 다른 조직의 금융·증빙·보고서에 접근할 수 없다.
10. API 장애 중 CSV 운영 후 복구해도 합계가 유지된다.
11. API/CSV 2주 병행에서 오합산 0건이다.
12. 자동 확정은 기본 OFF이고 품질 기준 통과 후에만 활성화된다.

## 18. 최종 승인 결론

기획과 개발 로드맵은 다음 조건으로 확정한다.

- 핵심 기능은 카드 자동 연결과 내역 자동조회다.
- 영수증 촬영·OCR은 카드 거래의 증빙 완결성을 자동화한다.
- 카드와 영수증을 별도 지출로 합산하지 않는다.
- 보고의 핵심 숫자는 운영순익(추정)이다.
- 일간·주간·월간·연말 보고와 PDF·Excel까지 출시 범위다.
- 관리자는 정상 거래 전체가 아니라 예외만 처리한다.
- 외부 연동 실패 중에도 기존 원장·결산과 CSV 폴백을 유지한다.
- 2주 병행 운영에서 오합산 0건을 확인해야 출시한다.

첫 구현 목표는 다음 한 문장으로 관리한다.

> 실제 테스트 카드 한 장을 연결해 카드와 거래내역을 자동 수집하고, 촬영한 영수증을 중복 없이 연결한 뒤 동일한 운영순익이 화면·차트·PDF·Excel에 나타나게 한다.
