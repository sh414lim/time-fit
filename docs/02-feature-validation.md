# 기능 목록 및 1차 검증

> 기준: TimeFit MVP · 2026-08-09

## 검증 목적

화면에 존재하는 기능이 실제 운영 데이터로 이어지는지, 그리고 승인·급여 마감 이후 이력이 변경되지 않도록 데이터 모델에서 보장되는지를 검증한다.

## 기능 목록과 검증 결과

| 영역 | 1차 기능 | 주요 상태 | 필요한 엔터티 | 검증 결과 |
|---|---|---|---|---|
| 조직 | 사업장, 근무지, 관리자 역할 관리 | 활성/비활성 | Organization, Workplace, OrganizationMember | 통과 |
| 직원 | 직원 등록, 소속 변경, 재직 상태 관리 | 재직/휴직/퇴사 | Employee, EmploymentContract | 통과 |
| 출퇴근 | 출근, 퇴근, 휴게, 수정 요청 | 진행/완료/수정대기/승인 | WorkSchedule, AttendanceRecord, ApprovalLog | 통과 |
| 스케줄 | 일자별 근무 배정, 휴무 지정 | 예정/확정/취소 | WorkSchedule | 통과 |
| 휴가·연차 | 휴가 신청, 승인/반려, 잔여일 조회 | 대기/승인/반려/취소 | LeavePolicy, LeaveRequest, LeaveBalance | 통과 |
| 급여 | 급여 실행 생성, 항목 산정, 마감 | 초안/검토/마감/공개 | PayrollRun, PayrollItem, PayrollAdjustment | 통과 |
| 권한·감사 | 역할별 접근 및 변경 이력 | 역할/감사 이벤트 | User, OrganizationMember, ApprovalLog, AuditLog | 통과 |

## 핵심 검증 시나리오

### 1. 출퇴근 → 급여

1. 확정 스케줄(`WorkSchedule`)을 생성한다.
2. 직원의 출근·퇴근 기록(`AttendanceRecord`)을 같은 직원·근무일에 하나만 생성한다.
3. 근무·휴게·연장·야간·휴일 분 단위를 기록한다.
4. 급여 마감 대상 기간의 승인된 근태를 집계해 `PayrollItem`을 생성한다.

검증: 근태 기록은 `employeeId + workDate` 고유 제약으로 중복 생성되지 않으며, 급여 항목은 `payrollRunId + employeeId` 고유 제약으로 한 번만 생성된다.

### 2. 휴가 신청 → 연차 잔여

1. 사업장의 휴가 정책(`LeavePolicy`)을 선택해 휴가 요청(`LeaveRequest`)을 생성한다.
2. 승인자와 승인 시간을 기록한다.
3. 승인된 요청만 해당 연도·유형의 `LeaveBalance.usedAmount`에 반영한다.

검증: 잔여 연차는 `grantedAmount + carriedAmount - usedAmount`으로 계산하며, 정책·잔여현황·신청을 별도 엔터티로 분리해 정책 변경이 과거 이력을 훼손하지 않는다.

### 3. 급여 마감 불변성

1. `PayrollRun`을 초안으로 만들고 `PayrollItem` 및 조정항목을 계산한다.
2. 관리자 검토 후 마감(`CLOSED`)한다.
3. 공개(`PUBLISHED`) 뒤에는 수정 API가 거부되어야 하며, 수정은 다음 정산 또는 별도 조정 프로세스로 처리한다.

검증: 급여 실행의 상태가 별도 필드로 관리되어, 프론트엔드 표시 상태와 실제 정산 상태가 분리되지 않는다.

## 1차 설계 결정

- 모든 업무 데이터는 `organizationId`로 격리한다.
- 인증 사용자와 직원 프로필을 분리한다. 직원이 앱에 가입하지 않은 상태에서도 인사 등록이 가능하다.
- 돈은 `Decimal(14,2)`, 시간은 분 단위 정수로 저장한다. 표시 형식·통화는 API 계층에서 처리한다.
- 한국 근로 규정은 사업장별 정책으로 관리하고, 급여 결과는 마감 전 관리자 검토를 필수로 한다.
- 위치·IP 등 민감한 출퇴근 인증 정보는 동의 및 보관정책 확정 전 선택 저장 필드로만 둔다.
