# TimeFit 하이픈 법인카드 연동 사전검토

작성일: 2026-09-10  
판정: **조건부 도입 가능(Yellow)**

## 1. 결론

하이픈은 TimeFit이 요구하는 보유카드, 승인, 매입, 청구, 한도, 결제예정금액 조회 기능을 제공한다. 하지만 법인카드 조회는 공식 상품 설명상 스크래핑 기반이며, 기업자금정보 패키지는 TR시그니처 계약형 상품이다. 따라서 현재 TimeFit 코드에 임의의 URL과 API 키를 넣어 즉시 운영하는 방식은 불가능하다.

운영 연결 전 필수 조건은 다음과 같다.

1. 하이픈 상담 및 상품 계약
2. 사용할 카드사와 법인/개인사업자 지원 범위 확인
3. 테스트베드 권한, User ID, HKey 발급
4. 카드사별 인증 방식과 인증정보 보관 책임 확인
5. 실제 API 명세와 오류코드 수령
6. 개인정보·신용정보 처리 계약과 보존정책 확정

## 2. 공식 확인 정보

- 기업자금정보 패키지는 법인카드의 보유카드, 한도, 결제예정금액, 승인, 청구서, 매입, 카드번호 조회를 제공한다.
- API 방식, Local Scraping, Server Scraping 방식을 안내한다.
- 기업자금정보 패키지는 TR시그니처 요금제로만 사용할 수 있고 상담·계약 후 사용한다.
- TR시그니처는 월 기본사용료와 초과 호출 요금의 후불 구조다.
- 인증서 정보가 필요한 상품은 계약담당자가 안내하는 인증서정보 추출 파일 설치 과정이 있다.
- 공개 API 인증은 OAuth 2.0을 권장한다.
- `POST https://api.hyphen.im/oauth/token`에 User ID와 HKey를 보내 토큰을 발급한다.
- Access Token은 7일 유효하며 서버에서 재사용하고 만료 시 재발급해야 한다.
- 무료 테스트베드는 일반적으로 일 100건, 월 100건을 안내하지만 일부 상품은 별도 제한될 수 있다.

## 3. TimeFit에 필요한 API

### 필수

- 법인카드 보유카드조회
- 법인카드 승인내역조회
- 법인카드 매입내역조회

### 2차

- 법인카드 청구서조회
- 법인카드 결제예정금액조회
- 법인카드 한도조회

카드번호조회 API는 TimeFit에서 우선 사용하지 않는다. 전체 카드번호를 저장하지 않고 하이픈/카드사 식별자와 마스킹 값만 유지하는 것이 안전하다.

## 4. 목표 연결 흐름

```text
사업장 소유자
  → 하이픈/카드사 인증 시작
  → 카드사 선택
  → 인증정보 또는 인증서 등록
  → 보유카드 조회
  → TimeFit에서 사용할 카드 선택
  → 최초 90일 승인/매입 내역 동기화
  → 카드 토큰과 마지막 동기화 커서 저장
  → 주기적 증분 동기화
  → 영수증 자동 매칭
  → 지출 원장 1회 반영
```

하이픈 서비스 인증(User ID/HKey)과 각 사업장의 카드사 인증정보는 서로 다르다. 전자는 TimeFit 서버 비밀값이고, 후자는 사업장별 암호화 데이터 또는 하이픈이 제공하는 안전한 참조 토큰으로 관리해야 한다.

## 5. 권장 서버 구조

### 비밀정보

- `HYPHEN_USER_ID`, `HYPHEN_HKEY`: Supabase/Vercel 서버 환경변수
- OAuth Access Token: 서버 캐시 또는 암호화 테이블, 만료 시각 포함
- 카드사 인증정보: 브라우저·일반 DB 평문 저장 금지
- 로그에 HKey, 토큰, 인증서, 카드번호, 비밀번호 출력 금지

### 서버 함수

- `hyphen-token`: 토큰 발급, 캐시, 만료 10분 전 갱신
- `hyphen-card-connect`: 카드사 인증 검증과 보유카드 조회
- `hyphen-card-sync`: 승인/매입/취소 증분 동기화
- `hyphen-card-health`: 인증 만료, 카드사 점검, 마지막 성공 시각 조회
- `hyphen-card-disconnect`: 자동 동기화 중지와 인증정보 파기

### 동기화

- 최초 연결: 최근 90일을 작은 기간으로 나눠 백필
- 정기: 1~3시간 간격 승인내역 증분 조회
- 야간: 최근 7일 재조회해 지연 매입·승인 취소 보정
- 월초: 전월 청구/매입 전체 대조
- 실패: 지수 백오프, 최대 재시도 후 관리자 예외함

스크래핑 상품이므로 카드사 점검, 로그인 정책 변경, 추가 인증 요청으로 실패할 수 있다. `실시간`이라는 문구보다 `최근 동기화 시각`과 데이터 신선도를 화면에 명확히 표시해야 한다.

## 6. 데이터 정규화

하이픈 원문 응답은 별도 `raw_payload`에 암호화 또는 최소화해 저장하고 다음 공통 모델로 변환한다.

- provider transaction ID
- 카드사/카드 식별자/끝 4자리
- 승인번호
- 승인일시
- 매입일시
- 가맹점명/사업자번호
- 승인금액/통화
- 국내·해외
- 일시불·할부
- 승인·취소·부분취소
- 매입·미매입
- 청구 상태

카드사마다 필드와 응답 형식이 다를 수 있으므로 UI가 하이픈 응답 필드를 직접 사용하지 않고 정규화 계층을 거쳐야 한다.

## 7. 중복과 정합성

우선순위별 멱등 키:

1. 하이픈/카드사의 고유 거래 ID
2. 카드 식별자 + 승인번호 + 승인일시 + 금액 + 거래종류
3. 카드 + 정규화 가맹점 + 승인일시 + 금액

승인내역과 매입내역은 별도 지출로 만들지 않는다. 하나의 카드 거래가 `승인 → 매입 → 청구` 상태로 발전하도록 병합한다. 취소는 원거래를 삭제하지 않고 원승인과 연결된 반대 거래로 저장한다. 영수증 또한 동일 지출의 증빙 원천으로 연결하며 결산은 확정 지출을 한 번만 합산한다.

| 영역 | 현재 | 실연동 목표 | 판정 |

## 10. 실제 연동 전 검증 질문

하이픈에 다음 내용을 서면으로 받아야 한다.

1. TimeFit 고객 사업장 단위로 제공 가능한 카드사 목록
2. 법인카드와 개인사업자 사업용 카드 지원 차이
3. 카드사별 ID/PW, 공동인증서, 추가 인증 방식
4. 인증정보를 하이픈이 보관하는지 TimeFit이 전달해야 하는지
5. 승인내역의 평균 지연시간과 조회 가능 과거기간
6. 승인/매입/청구 데이터의 고유키와 취소 연결키
7. 다중 카드·다중 법인·복수 사업자 지원 방식
8. 호출 한도, 동시 호출 제한, 타임아웃, 재시도 정책
9. 테스트베드에서 실제 카드사 인증 흐름 제공 여부
10. 이용료, 최소 약정, 초기비, 초과 호출 단가
11. IP 화이트리스트, 전용선/VPN, 암호화 요구사항
12. 장애 SLA와 카드사 사이트 변경 대응 시간
13. 데이터 재판매/최종고객 제공 허용 범위
14. 해지 시 인증정보와 조회 데이터 파기 절차

## 11. Go/No-Go 기준

### Go

- 핵심 카드사 지원이 확인됨
- 테스트베드에서 보유카드→승인→취소→매입 흐름 검증
- 안정적인 고유 거래키 제공
- 인증정보를 TimeFit이 평문으로 보관하지 않아도 됨
- 예상 사업장 수 기준 비용이 허용 범위
- 장애/재인증 상태를 API로 판별 가능

### No-Go 또는 대안 검토

- 카드사 비밀번호·인증서 비밀번호를 TimeFit이 복호화 가능한 형태로 장기 보관해야 함
- 거래 고유키나 취소 연결정보가 없어 중복 방지가 불가능함
- 핵심 카드사 미지원
- 카드사 변경 시 장기 장애에 대한 SLA 없음
- 데이터의 고객 제공 또는 결산 활용이 계약상 제한됨

## 14. 공개 요금 확인

2026-09-10 하이픈 법인카드 조회 상품 페이지에서 확인되는 공개 가격은 다음과 같다.

| 요금제 | 공개 기본료 | 과금 방식 | 계약 |
|---|---:|---|---|
| TR슬림 | 월 멤버십 100,000원 | 비즈머니 선불 + API 정상응답 건별 요금 | 계약서 없음 |
| TR시그니처 | 월 기본료 300,000원부터 | 상품별 기본 건수 + 초과분 협의, 후불 | 계약 필요 |

법인카드 조회 개별 상품은 화면상 TR슬림과 TR시그니처 라벨을 모두 제공한다. 반면 법인계좌까지 포함하는 기업자금정보 패키지는 TR시그니처 전용으로 안내된다. 카드만 먼저 검증할 경우에는 개별 `법인카드 조회` 상품의 TR슬림 신청 가능 여부를 하이픈 계정에서 확인하는 것이 가장 저렴한 시작 경로다.

공개 페이지에는 법인카드 조회의 **건당 정상요금**, TR시그니처의 **포함 호출량**, **초기 도입비**가 표시되지 않는다. 이 세 항목은 로그인 후 상품 신청 또는 상담 견적이 필요하므로 공개 정보만으로 정확한 월 총액을 산출할 수 없다.

## 15. TimeFit 예상 호출량

승인내역 API를 카드마다 호출한다고 보수적으로 가정한 계산이다. 실제 과금 단위가 사업자/카드사/카드/조회요청 중 무엇인지는 명세 확인이 필요하다.

| 운영 규모 | 카드 수 | 6시간 간격(월) | 3시간 간격(월) | 1시간 간격(월) |
|---|---:|---:|---:|---:|
| 시험 사업장 1곳 | 3 | 약 360회 | 약 720회 | 약 2,160회 |
| 사업장 10곳 | 30 | 약 3,600회 | 약 7,200회 | 약 21,600회 |
| 사업장 100곳 | 300 | 약 36,000회 | 약 72,000회 | 약 216,000회 |

여기에 최초 보유카드 조회, 과거내역 백필, 야간 재대조, 매입/청구 조회 호출이 추가된다. MVP는 6시간 주기와 사용자가 누르는 수동 동기화를 결합해 비용을 억제하고, 카드 사용이 잦은 사업장만 주기를 줄이는 것이 적합하다.

월 총비용 공식은 다음과 같다.

```text
TR슬림 = 100,000원 + (정상응답 호출 수 × 법인카드 API 건당 단가)
TR시그니처 = 300,000원 이상 + 기본 건수 초과요금 + 선택적 구축/연동 비용
```

현재 공개 정보로 확정할 수 있는 최저 고정비는 카드 조회 단품 TR슬림의 월 10만원이며, 계약형 운영의 공개 시작가는 월 30만원이다. 부가세 포함 여부와 실제 건당 단가는 견적에서 확인해야 한다.
