# TimeFit 최종 출시 점검 시나리오

대상: `https://timefit-omega.vercel.app/`  
태블릿: `https://timefit-omega.vercel.app/tablet?organization={organizationId}`

## 1. 통과 기준

- 모든 등록·출퇴근·휴가 변경은 Supabase에 저장되고 새로고침 후에도 유지된다.
- 관리자와 직원, 서로 다른 사업장 간 데이터는 권한에 맞게 분리된다.
- 태블릿의 PIN·전화번호 입력은 자체 숫자 키패드 모달로만 처리되며 기기 기본 키보드가 노출되지 않는다.
- 처리 중에는 중복 제출할 수 없고 성공·실패 안내가 표시된다.

## 2. 테스트 역할

| 역할 | 목적 |
| --- | --- |
| 관리자 A | 기존 사업장 운영, 직원 등록, 출퇴근·휴가 확인/승인 |
| 직원 A1 | 초대 수락형 직원 로그인과 개인 정보 범위 확인 |
| 직원 A2 | 같은 사업장 직원 간 개인 정보 격리 확인 |
| 직접 등록 직원 M1 | 계정 없이 태블릿 출퇴근·휴가 신청 |
| 관리자 B | 다른 사업장 데이터 격리 확인 |
| 신규 관리자 C | 회원가입과 사업장 자동 생성 확인 |

## 3. 관리자 회원가입·온보딩

### A-01. 관리자 가입과 사업장 생성

1. 로그인 화면에서 `회원가입`을 누른다.
2. `관리자`를 선택하고 이름, 사업장명, 이메일, 8자 이상 비밀번호를 입력한다.
3. `회원가입`을 누른다.
4. 관리자 홈으로 이동하고 상단에 입력한 사업장명과 관리자 이름이 보이는지 확인한다.
5. 로그아웃 후 같은 계정으로 다시 로그인한다.

기대 결과:

- 이메일 인증 없이 가입·로그인이 완료된다.
- 새 `timefit_user_organizations` 사업장과 관리자 역할이 생성된다.
- 재로그인 후에도 동일 사업장·관리자 권한이 유지된다.

### A-02. 운영 설정

1. `운영 설정`에서 사업장명, 주소, 기본 휴게시간, 태블릿 PIN 4자리, 태블릿 활성화 상태를 저장한다.
2. 새로고침 후 저장값과 태블릿 URL을 확인한다.

기대 결과: 설정은 해당 사업장에만 저장되며, 태블릿은 활성화와 PIN 설정을 적용한다.

## 4. 직원 관리

### B-01. 직접 직원 등록

1. 홈 `직원 등록하기`를 누른다.
2. 이름, 휴대전화, 부서, 직책, 급여 형태, 시급/월급, 입사일을 입력한다.
3. 저장 후 `직원 관리` 목록에서 해당 직원을 검색한다.

기대 결과:

- 등록 완료 안내가 표시되고 목록에 이름·부서·직책·급여 형태·재직 상태가 보인다.
- 전화번호 끝 4자리/8자리는 태블릿 인증에 사용할 수 있다.

### B-02. 직원 상세 화면

1. 직원 관리 목록에서 `상세`를 누른다.
2. 이름, 부서, 직책, 오늘 근무 상태, 최근 출퇴근, 휴가 내역을 확인한다.

기대 결과: 실제 등록·근태·휴가 데이터가 표시된다.

판정 기준: 상세의 입사일·근무시간·스케줄·연차·예상 급여가 샘플 데이터이면 **FAIL(출시 보완 필요)** 로 기록한다.

### B-02A. 관리자 데이터 노출 점검

직접 등록 직원 M1을 기준으로 아래 데이터가 관리자 화면에 실제 저장값으로 보이는지 점검한다. 각 항목은 저장 직후 새로고침하여 다시 확인한다.

| 관리자 화면 | 확인 데이터 | 기대 결과 |
| --- | --- | --- |
| 홈 | 오늘 출근·근무 중 인원, 승인 대기 휴가 | 실제 근태·휴가 데이터와 일치하며 다른 사업장 데이터가 섞이지 않는다. |
| 직원 관리 목록 | 이름, 부서, 직책, 급여 형태, 재직 상태 | 직접 등록 시 입력한 값과 일치한다. |
| 직원 상세 | 이름, 입사일, 전화번호, 근무 상태, 최근 출퇴근, 휴가 내역 | 해당 직원의 실제 CRUD 데이터만 표시된다. 샘플 값이면 FAIL이다. |
| 출퇴근 관리 | 직원명, 상태, 출근/퇴근 시각, 근무 시간 | 태블릿에서 생성한 최신 출퇴근 기록과 일치한다. |
| 휴가 · 연차 | 신청자, 날짜, 종류, 일수, 상태, 승인 메모 | 태블릿/직원 화면에서 만든 요청과 관리자 승인 결과가 일치한다. |
| 운영 설정 | 사업장명, 주소, 휴게시간, PIN, 태블릿 활성화 | 마지막으로 저장한 해당 사업장 설정값과 일치한다. |
| 급여 관리 | 직원별 급여 형태·기초 금액·집계 기준 | 실제 저장 데이터만 표시하며, 급여 정책 미확정 값은 `예상` 또는 `준비 중`으로 명확히 표시한다. |

기대 결과: 관리자 A는 자기 사업장에 속한 직원·출퇴근·휴가·운영 설정만 조회할 수 있으며, 각 화면의 값은 Supabase에 저장된 실제 데이터와 일치한다.

### B-03. 초대 수락형 직원

1. 직원 계정에서 고유번호를 확인한다.
2. 관리자가 `직원 초대`에서 고유번호와 부서·직책을 입력한다.
3. 직원이 로그인하여 초대를 수락한다.

기대 결과: 직원 계정이 해당 사업장에 `linked` 상태로 연결되고 본인 화면만 접근한다.

## 5. 태블릿 출퇴근

### C-01. 숫자 키패드 모달 UI

1. 태블릿 `출퇴근` 탭을 연다.
2. 기본 화면에 `태블릿 PIN`, `전화번호 뒷 4자리`, `직원 확인`이 표시되는지 확인한다.
3. PIN 입력칸을 누른다.
4. 숫자 0~9, 한 자리 삭제, 입력 완료 버튼이 있는 모달을 확인한다.
5. 모달 외 기본 화면에 숫자 키패드가 없고, 기기 기본 키보드가 열리지 않는지 확인한다.
6. 전화번호 입력칸에서도 동일 동작을 확인한다.

기대 결과: 입력 필드는 유지되며, 숫자 입력은 자체 모달 키패드만으로 이뤄진다.

### C-02. 출근·퇴근 저장

1. 올바른 PIN과 직접 등록 직원 M1 전화번호 끝 4자리를 입력한다.
2. `직원 확인`을 누르고 직원 실명과 출근/퇴근 버튼을 확인한다.
3. `출근하기`를 누른다.
4. 관리자 `출퇴근` 화면과 해당 직원 상세에서 근무 중·출근 시각을 확인한다.
5. 같은 직원으로 재인증해 `퇴근하기`를 누른다.

기대 결과: 출근 1건과 퇴근 시각이 저장되며 중복 출근 기록은 생성되지 않는다.

### C-03. 실패·보안 케이스

| 케이스 | 기대 결과 |
| --- | --- |
| 잘못된 PIN | 인증 거부, 직원 이름·근태 미노출 |
| 없는 전화번호 끝자리 | 직원 확인 실패 안내 |
| 태블릿 비활성화 | 출퇴근·휴가 모두 차단 |
| 다른 사업장 직원 번호 | 인증 실패, 기록 미생성 |

## 6. 휴가 신청·관리자 승인

### D-01. 태블릿 휴가 신청

1. 태블릿 `휴가 신청` 탭에서 PIN과 전화번호 끝 8자리를 숫자 키패드로 입력한다.
2. 미래 날짜를 선택하고 연차, 오전 반차, 오후 반차를 각각 신청한다.
3. 성공 안내와 알림 대기열 안내를 확인한다.

기대 결과: 연차는 1일, 반차는 0.5일, 상태는 `pending`, 출처는 `tablet`으로 저장된다.

### D-02. 관리자 승인·반려

1. 관리자 홈의 승인 요청 또는 `휴가 · 연차`를 연다.
2. D-01의 신청자가 실제 이름과 날짜·휴가 종류로 보이는지 확인한다.
3. 한 건은 메모와 함께 승인하고, 한 건은 사유와 함께 반려한다.
4. 대기 건수가 즉시 바뀌는지 확인한다.

기대 결과: 상태, 검토자, 시각, 메모가 저장되고 해당 직원에게만 노출된다.

## 7. 권한과 데이터 격리

### E-01. 직원 A1/A2 개인정보 분리

1. A1로 휴가 신청 또는 출퇴근 기록을 만든다.
2. A2로 로그인해 휴가·출퇴근·스케줄을 확인한다.

기대 결과: A2는 A1의 이름, 전화번호, 근태, 휴가 사유·승인 결과를 볼 수 없다.

### E-02. 사업장 A/B 분리

1. 관리자 B로 로그인한다.
2. 직원 관리, 출퇴근, 휴가, 운영 설정을 확인한다.
3. 사업장 A 직원과 기록이 보이지 않는지 확인한다.
4. 사업장 B 태블릿에서 사업장 A 직원 번호를 입력한다.

기대 결과: 사업장 A 데이터는 사업장 B 관리자·태블릿에서 조회·생성되지 않는다.
