# TimeFit 법인카드 Provider 조사·비용 검토

조사 기준일: 2026-09-12

목표: 국내 법인카드 보유카드·승인·취소·매입 내역을 멀티테넌트 SaaS TimeFit에서 자동 수집

## 1. 결론

견적 수령 전 잠정 권고안은 다음과 같다.

1. 빠른 Pilot: Hyphen TR슬림
2. 상용 주 Provider 후보: CODEF와 Hyphen을 실제 fixture·견적으로 최종 비교
3. 데이터 품질 우선 Enterprise 후보: 쿠콘 법인카드 EDI
4. 저비용·리셀러 대안 후보: 바로빌
5. 장기 전략: 금융결제원 이용기관 또는 카드사 직접계약은 고객·거래량 증가 후 재검토

지금 즉시 하나를 선택해야 한다면 Hyphen이 가장 현실적이다. 공개 진입비가 명확하고 법인카드 승인·매입·보유카드 API와 테스트베드를 제공하며 현재 TimeFit에 Adapter 골격도 있기 때문이다. 다만 스크래핑 기반이고 건당 단가와 SaaS 재제공 권한이 공개되지 않았으므로 Pilot 계약 전 최종 확정으로 보아서는 안 된다.

상용 Provider는 가격만으로 결정하지 않는다. TimeFit의 핵심은 승인·전체취소·부분취소·매입의 정확한 연결이므로 실제 카드 fixture와 CSV 대사 결과를 가격보다 우선한다.

## 2. 필수 평가 기준

| 항목 | 가중치 | 탈락 조건 |
|---|---:|---|
| 승인·취소·부분취소·매입 정확성 | 25 | 원승인 연결키 없음 |
| 멀티테넌트 SaaS 제공 권리 | 15 | 최종 고객 재제공 금지 |
| 인증정보 처리 안전성 | 15 | 비밀번호·인증서를 TimeFit DB에 장기 보관 요구 |
| 지원 카드사·법인 유형 | 10 | Pilot 핵심 카드사 미지원 |
| 페이지·고유 ID·증분조회 | 10 | 멱등 수집 불가능 |

| 개발환경·문서·지원 | 5 | 테스트베드/fixture 없음 |

## 3. 후보별 검토

### 3.1 Hyphen

공식 공개 범위:

- 스크래핑 방식 법인카드 조회
- 보유카드, 승인, 매입, 결제예정, 카드번호, 한도 등 6종
- TR슬림: 월 멤버십 100,000원, 선불 비즈머니, 정상응답 건별 과금, 계약 없음
- TR시그니처: 월 기본료 300,000원부터, 계약형, 상품별 기본 건수
- 두 플랜 모두 테스트베드 제공

장점:

- 가장 낮은 공개 진입비
- 승인·매입을 개별 API로 제공
- 소량 Pilot을 시작하기 쉬움
- 현재 TimeFit Hyphen Adapter 골격 재사용 가능

약점:

- 카드사 화면에 의존하는 스크래핑 방식
- 정상응답 건당 단가 비공개
- 공동인증서/ID·PW 처리 방식이 상품·카드사별로 다를 수 있음
- 부분취소와 원승인 연결 필드, 페이지 규칙을 실제 명세로 검증해야 함
- 계약 없는 TR슬림이 멀티테넌트 SaaS 재제공을 허용하는지 서면 확인 필요

판정: Pilot 1순위, 상용은 계약 검증 후 조건부.

공식 자료: https://www.hyphen.im/product/view?seq=55

### 3.2 CODEF

공식 공개 범위:

- 개인·법인 카드 보유카드, 승인, 청구, 한도, 결제예정 등 제공
- End User 인증수단 등록 후 Connected ID 발급 구조
- 데모·정식 서비스와 공식 SDK 제공
- 인증서 relay는 별도 문의

장점:

- 금융·공공 데이터를 위한 개발 플랫폼과 SDK가 비교적 명확함
- Connected ID 방식이 TimeFit의 Provider token/reference 구조와 잘 맞음
- 카드 외 계좌·세금·보험으로 확장 가능
- 데모에서 실제 응답 계약 검증 가능

약점:

- 법인카드 매입·부분취소 필드의 구체 명세는 로그인/계약 후 확인 필요
- 공개 법인카드 단가를 확인할 수 없음
- 인증서 relay와 멀티테넌트 재제공 조건 별도 협의
- 최종 비용은 호출량·상품 묶음·지원 방식에 따라 달라짐

판정: 상용 주 Provider 유력 후보. Hyphen과 반드시 병행 견적·fixture 비교.

공식 자료: https://codef.io/assets/pdf/202307_CODEF_API_%EC%86%8C%EA%B0%9C%EC%84%9C.pdf

### 3.3 쿠콘 법인카드 EDI

공식 공개 범위:

- 국내 전 카드사 대상이라고 안내
- 카드사에서 승인·매입·청구·한도 정보를 직접 수신해 제공
- ERP·경비관리 적용 사례 공개

장점:

- 스크래핑보다 카드사 직접 수신 EDI가 데이터 품질·안정성 측면에서 유리
- 승인·매입·청구 등 TimeFit 결산에 필요한 범위가 명확함
- 대규모 기업 ERP 운영 사례 존재

약점:

- 공개 가격 없음
- 도입비·월 기본료·초과 수수료 형태의 기업 계약 가능성이 높음
- 스타트업 Pilot 규모에서 계약·비용이 과할 수 있음
- 고객사·카드사 등록 절차와 리드타임 확인 필요

판정: 정확성과 대규모 운영의 최우선 후보. 초기 Pilot보다 성장 단계의 주 Provider 또는 프리미엄 플랜에 적합.

공식 자료: https://www.coocon.net/dataService_corpData.act

### 3.4 바로빌

공식 공개 범위:

- 10개 카드사 개인·법인 카드 내역
- 카드 등록, 승인내역, 매입내역
- 승인 수집 주기 24시간 또는 6시간
- 매입 수집 주기 24시간
- 승인과 매입은 각각 별도 서비스로 과금
- 회원사 결제와 파트너 결제, 재판매형 구조 제공

장점:

- TimeFit 같은 솔루션/파트너 구조를 공식적으로 안내
- 카드사 데이터가 바로빌에 적재된 뒤 조회되어 TimeFit의 호출 횟수를 줄일 가능성
- 자동수집 주기가 명시적
- 테스트 환경과 다양한 SDK 제공

약점:

- 공개 단가 확인 불가
- 승인+매입을 사용하면 카드당 두 서비스 과금 가능
- 최대 6시간 승인 수집으로 빠른 알림에는 제약
- API·회원 구조가 현재 REST 중심 TimeFit Adapter와 다를 수 있음
- 부분취소·원승인 연결 데이터 검증 필요

판정: 리셀러/파트너 비용이 유리하면 강력한 대안. 반드시 카드 수×승인/매입 이중 과금으로 견적 계산.

공식 자료: https://dev.barobill.co.kr/services/card

### 3.5 금융결제원 오픈뱅킹

공식 공개 범위:

- 이용계약과 승인을 받은 핀테크사업자/참가기관 대상
- 카드목록, 카드기본정보, 카드청구 기본·상세정보 API 안내
- 개인·법인 계좌 거래내역 API 제공

장점:

- 표준 금융 인프라와 직접 연결하는 장기적 구조
- 중간 수집사업자 의존도를 낮출 가능성

약점:

- TimeFit이 핵심으로 삼는 법인카드 승인·부분취소·매입 API 범위는 공개 자료만으로 확정 불가
- 이용기관 심사·계약·보안·통합테스트 필요
- 빠른 MVP에 적합하지 않음
- 금융인증 계약과 카드정보 이용계약은 별도로 확인해야 함

판정: 현재 MVP Provider가 아니라 중장기 전략.

공식 자료: https://openapi.kftc.or.kr/service/openBanking

### 3.6 카드사 직접계약

장점:

- 원천 데이터와 직접 연결
- 중간 Provider 호출비 절감 가능
- 카드사 고유 기능 활용 가능

약점:

- 카드사마다 계약·보안심사·API·인증·운영이 다름
- 여러 카드사를 지원하려면 Connector와 장애 대응이 선형 증가
- 초기 TimeFit 규모에서 협상력과 개발비가 불리함

판정: 특정 카드사의 고객 비중이 매우 높거나 Provider 비용이 직접 연동비를 초과할 때만 검토.

## 5. 비용 구조

### 5.1 공개 확정 비용

| Provider | 공개 비용 | 추가 비용 |
|---|---:|---|
| Hyphen TR슬림 | 월 100,000원 | 정상응답 TR 건별 단가 |
| Hyphen TR시그니처 | 월 300,000원부터 | 기본 건수 초과 협의 |
| CODEF | 비공개 | API 호출·상품·relay 견적 |
| 쿠콘 | 비공개 | 도입비·월 기본료·초과 수수료 견적 |
| 바로빌 | 비공개 | 카드별 승인/매입 서비스 요금 |
| 금융결제원 | 비공개 | 계약·API·보안 구축비 |

부가세, 초기 구축비, 최소 계약기간, 지원비는 별도 확인한다.

### 5.2 월 비용 계산식

Hyphen:

```text
월 비용
= 플랜 기본료
+ 보유카드 조회 정상건수 × 단가
+ 승인 조회 정상건수 × 단가
+ 매입 조회 정상건수 × 단가
+ 재인증·백필·재대조 정상건수 × 단가
```

바로빌:

```text
월 비용
= 활성 카드 수 × 승인서비스 카드당 요금
+ 활성 카드 수 × 매입서비스 카드당 요금
+ 파트너/회원 기본료 또는 기타 이용료
```

CODEF·쿠콘:

```text
월 환산비
= 초기 도입비 ÷ 계약 개월
+ 월 기본료
+ 기본량 초과 호출료
+ 인증서 relay/VPN/IP/기술지원 비용
```

### 5.3 견적용 사용량 시나리오

호출 과금 단위가 카드·카드사·사업자·페이지 중 무엇인지 확정되지 않았으므로 다음 수치는 비용이 아니라 견적 입력값이다.

| 단계 | 고객사 | 평균 카드 | 총 카드 | 승인 조회/일 | 매입 조회/일 |
|---|---:|---:|---:|---:|---:|
| Pilot | 1 | 3 | 3 | 4회 | 1회 |
| 초기 | 10 | 3 | 30 | 4회 | 1회 |
| 성장 | 100 | 3 | 300 | 4회 | 1회 |
| 확장 | 1,000 | 3 | 3,000 | 4회 | 1회 |

카드별 호출로 가정한 단순 상한:

| 단계 | 승인 월 호출 | 매입 월 호출 | 기본 정기 호출 합계 |
|---|---:|---:|---:|
| Pilot | 360 | 90 | 450 |
| 초기 | 3,600 | 900 | 4,500 |
| 성장 | 36,000 | 9,000 | 45,000 |
| 확장 | 360,000 | 90,000 | 450,000 |

여기에 최초 90일 백필, 페이지 추가 호출, 최근 7일 재대조, 보유카드 조회, 재인증이 더해진다. Provider가 사업자 또는 카드사 로그인 한 번으로 여러 카드를 반환하면 실제 호출은 크게 줄어든다.

### 5.4 Provider 견적 비교용 단위 원가

```text
고객사당 월 Provider 원가
= 월 총 Provider 비용 ÷ 활성 고객사

카드당 월 원가
= 월 총 Provider 비용 ÷ 활성 카드

거래 1,000건당 원가
= 월 총 Provider 비용 ÷ 수집 거래건수 × 1,000
```

TimeFit 고객 플랜의 금융 기능 원가율 목표를 정한 뒤 `고객사당 월 Provider 원가`가 허용 범위 안인지 판단한다. 공개 단가가 없는 현재는 손익분기 가격을 확정하지 않는다.

## 7. 권장 검증 절차

### 1차: 서류

- Hyphen, CODEF, 쿠콘, 바로빌에 동일한 사용량 표로 견적 요청
- 재판매가 아니라 TimeFit SaaS 기능으로 최종 고객에게 가공 데이터를 제공한다고 명시
- 고객사 1/10/100/1,000곳 가격 구간 요청

### 2차: Sandbox

- 보유카드 조회
- 승인·전체취소·부분취소·매입 fixture
- 원승인 연결키와 고유 event ID
- 페이지네이션·오류코드·재인증
- credential 전달·저장 방식

### 3차: 실카드 Pilot

- 카드 1~3장, 최근 90일
- 같은 기간 세 번 수집
- 카드사 CSV와 일별 건수·순액 비교
- 2주 이상 증분 동기화
- 장애·재인증·복구 테스트

## 8. 최종 선택 규칙

견적 수령 후 다음 순서로 결정한다.

1. 법적·계약상 SaaS 제공 가능 여부
2. PAN·인증서·비밀번호 비보관 가능 여부
3. 승인·취소·매입 정확도와 CSV 일치
4. 안정 event ID·페이지·cursor 제공 여부
5. 핵심 카드사 커버리지
6. 장애·재인증 운영성
7. 고객사당 총원가

최종 추천 구조:

```text
Pilot
→ Hyphen TR슬림 또는 가장 먼저 Sandbox가 열린 업체

상용 전환
→ CODEF vs Hyphen fixture·대사·견적 점수 비교

고객 100곳 이상
→ 쿠콘 EDI와 Provider 이중화 비용 재검토

대규모
→ 금융결제원/주요 카드사 직접계약의 손익분기 재평가
```

현재 확정할 수 있는 최소 예산은 Hyphen TR슬림의 월 10만 원과 실제 정상응답 건별 비용이다. 정확한 상용 월비용과 최적 Provider는 네 업체의 동일 조건 견적 및 Sandbox 결과가 있어야 확정할 수 있다.
