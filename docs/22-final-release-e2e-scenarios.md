# TimeFit 최종 출시 전 E2E 테스트 시나리오

대상 환경: `https://timefit-omega.vercel.app/`  
태블릿: `https://timefit-omega.vercel.app/tablet?organization={organizationId}`

## 1. 최종 통과 기준

- 관리자·직원·태블릿 핵심 플로우가 실제 Supabase 데이터로 저장·조회된다.
- 다른 사업장과 다른 직원의 개인정보·근태·휴가가 노출되지 않는다.
- 직접 등록 직원도 계정 없이 태블릿 인증이 가능하다.
- 브라우저 콘솔 오류가 없고, 실패 시 사용자에게 이해 가능한 안내가 보인다.

## 2. 테스트 역할

| 역할 | 용도 |
| --- | --- |
| 관리자 A | 사업장 설정, 직접 등록, 초대, 근태·휴가 승인 |
| 직원 A1 | 초대 수락형 직원, 태블릿 출퇴근·휴가 신청 |
| 직원 A2 | 같은 사업장 내 개인정보 분리 검증 |
| 직접 등록 직원 M1 | 계정 없는 현장 직원, 전화번호 기반 태블릿 인증 |
| 관리자 B | 사업장 A/B 데이터 격리 검증 |

## 3. 사전 준비

1. 관리자 A에서 `운영 설정`을 열어 태블릿 PIN과 활성화 상태를 저장한다.
2. 관리자 A와 A1, M1의 테스트 전화번호를 서로 다른 값으로 준비한다.
3. 태블릿 URL을 실제 태블릿 또는 별도 브라우저에 연다.
4. 테스트 휴가 날짜는 오늘 이후 날짜로 정한다.

## 4. 관리자 운영 시나리오

### F-01. 로그인 및 설정

1. 관리자 A로 로그인한다.
2. 관리자 메뉴(직원 관리, 운영 설정, 급여 관리)가 표시되는지 확인한다.
3. 사업장명, 주소, 기본 휴게시간, 태블릿 PIN을 저장한다.
4. 새로고침 후 설정값이 유지되는지 확인한다.

기대 결과: 설정은 해당 사업장에만 저장되고 태블릿이 PIN으로 보호된다.

### F-02. 직접 직원 등록

1. 홈의 `직원 등록하기`를 누른다.
2. 이름, 전화번호, 부서, 직책, 급여 형태, 시급 또는 월급, 재직 시작일을 입력한다.
3. `직원 등록 완료`를 누른다.
4. 직원 관리 목록에서 이름·직책·급여 형태가 표시되는지 확인한다.

기대 결과:

- `timefit_user_staff`에 `registration_type=manual` 직원 행이 생성된다.
- 계정 없이도 전화번호 뒷 4자리·8자리가 저장된다.
- 저장 성공 후 모달이 닫히고 성공 안내가 표시된다.

### F-03. 초대 수락형 직원 등록

1. 직원 A1이 직원 계정으로 회원가입해 고유번호를 확인한다.
2. 관리자 A가 `직원 관리 → 직원 초대`에서 고유번호·부서·직책을 입력한다.
3. A1이 로그인해 초대를 수락한다.
4. 관리자 A 목록과 A1 내 화면에서 사업장 연결을 확인한다.

기대 결과: 직원 A1은 `linked` 상태로 연결되며 본인 데이터만 조회한다.

### F-04. 직접 등록 직원 계정 연동 (보류)

DB 구조는 `manual → linked` 전환을 지원한다. 다만 현재 관리자 UI에 직접 등록 직원의 고유번호를 입력해 초대하는 버튼이 없으므로, 이 항목은 **UI 구현 후 최종 테스트**로 수행한다.

1. 직접 등록 직원 M1이 직원 계정으로 가입해 고유번호를 확인한다.
2. 관리자 A가 M1 상세에서 고유번호로 초대한다.
3. M1이 초대를 수락한다.
4. 기존 M1 직원 행의 전화번호·급여·입사일이 유지되면서 계정만 연결됐는지 확인한다.

## 5. 태블릿 출퇴근 시나리오

### F-05. 직접 등록 직원 출근·퇴근

1. 태블릿의 `출퇴근` 탭을 연다.
2. PIN과 M1 전화번호 뒷 4자리를 입력해 `직원 확인`을 누른다.
3. 직원 실명이 표시되는지 확인하고 `출근하기`를 누른다.
4. 관리자 출퇴근 화면에서 M1의 `근무 중`과 출근 시각을 확인한다.
5. 같은 번호로 다시 확인해 `퇴근하기`를 누른다.

기대 결과: 당일 출근 1건과 퇴근 시각 1건이 저장되고 중복 기록은 생성되지 않는다.

### F-06. 태블릿 실패 케이스

| 입력/행동 | 기대 결과 |
| --- | --- |
| 잘못된 PIN | 직원 이름·기록 미노출, 인증 거부 |
| 없는 전화번호 뒷 4자리 | 직원 확인 실패 |
| 태블릿 비활성화 | 출퇴근·휴가 신청 모두 차단 |
| 다른 사업장 직원 번호 | 인증 실패 |

## 6. 휴가 신청·승인 시나리오

### F-07. 태블릿 연차·반차 신청

1. 태블릿 `휴가 신청` 탭을 연다.
2. PIN, M1 전화번호 뒷 8자리, 미래 날짜를 입력한다.
3. 버튼 방식으로 `연차`, `오전 반차`, `오후 반차`를 각각 선택해 신청한다.
4. 성공 안내와 알림 대기열 안내를 확인한다.

기대 결과: 연차는 `amount=1`, 반차는 `amount=0.5`, 출처는 `tablet`, 상태는 `pending`으로 저장된다.

### F-08. 관리자 승인·반려

1. 관리자 A가 `휴가 · 연차`에서 요청을 확인한다.
2. 한 요청은 메모와 함께 승인한다.
3. 다른 요청은 사유와 함께 반려한다.
4. 직원 A1/M1의 본인 화면에서 결과를 확인한다.

기대 결과: 승인·반려 상태와 검토자·시각·메모가 저장되며, 해당 직원에게만 노출된다.

## 7. 개인정보·사업장 격리

### F-09. 직원 A1/A2 분리

1. A1로 휴가 신청을 만든다.
2. A2로 로그인해 휴가·출퇴근·스케줄을 확인한다.
3. A1 이름, 휴가 일자·사유·승인 결과, 전화번호가 A2에 보이는지 확인한다.

기대 결과: A2는 A1의 데이터에 접근할 수 없고, 본인 데이터만 보인다.

### F-10. 사업장 A/B 분리

1. 관리자 B로 로그인한다.
2. 직원 관리, 출퇴근, 휴가·연차, 운영 설정을 확인한다.
3. 사업장 A 직원·직접 등록 M1·휴가 요청·전화번호가 노출되는지 확인한다.
4. 사업장 B 태블릿 URL에 A 직원 번호를 입력한다.

기대 결과: 사업장 A 데이터는 관리자 B와 사업장 B 태블릿에서 확인·저장되지 않는다.

## 9. 출시 보류 항목

- 카카오 알림톡 실제 발송: 공급사·발신 프로필·템플릿·키 설정 후 별도 통합 테스트 필요
