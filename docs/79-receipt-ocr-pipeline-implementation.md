# 영수증 촬영·OCR·카드 매칭 1차 구현

## 사용자 흐름

지출·증빙의 파일 선택에서 모바일 카메라로 영수증을 촬영하거나 이미지 파일을 선택할 수 있다. 이미지가 업로드되면 원본을 먼저 비공개 저장소에 보관한 뒤 Google Vision OCR을 실행한다.

OCR 결과에서 다음 항목을 구조화한다.

- 상호
- 거래일
- 결제금액
- 사업자등록번호
- 승인번호
- 카드번호 끝 4자리

## 중복 방지

영수증은 즉시 확정 지출로 합산하지 않고 `review_required` 상태로 저장한다. 같은 날짜의 카드 거래를 조회해 다음 점수로 후보를 만든다.

- 금액 일치: 45점
- 거래일 일치: 25점
- 승인번호 일치: 25점
- 카드 끝 4자리 일치: 5점

영수증 원본은 `expense_sources`로 지출 초안에 한 번만 연결되고 카드 거래는 `expense_matches` 후보가 된다. 따라서 영수증과 카드내역이 각각 확정 지출로 자동 합산되지 않는다.

## 운영 안전장치

- 원본 업로드가 성공한 뒤 OCR이 실패해도 파일은 삭제하지 않는다.
- OCR 실행 이력과 오류 코드를 별도 테이블에 보존한다.
- 관리자 권한과 조직 범위를 서버에서 재검증한다.
- OCR 원문은 화면 표시용 구조화 결과와 분리해 저장한다.
- Google Vision API 키는 브라우저에 노출하지 않고 서버 환경변수로만 사용한다.

## 배포 전 준비

1. `20260910000500_receipt_ocr_pipeline.sql` 적용
2. 제한된 서버용 `GOOGLE_VISION_API_KEY` 등록
3. Vision API 키의 API 제한을 Cloud Vision API로 한정
4. 대표 영수증 이미지로 상호·날짜·금액 추출 검증
5. 카드 거래 일치·불일치·부분취소 케이스 검증

HEIC 영수증은 브라우저와 Vision 처리 호환성을 실기기에서 확인하고, 문제가 있으면 업로드 전에 JPEG 변환 단계를 추가한다.
