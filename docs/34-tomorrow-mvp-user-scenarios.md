# TimeFit 내일 MVP 사용자 시나리오

목적: 실제 매장 운영 흐름을 기준으로 TimeFit MVP의 핵심 기능이 끊김 없이 동작하는지 검증한다.  
대상 환경: [TimeFit 프로덕션](https://timefit-omega.vercel.app)  
참여자: 관리자 1명, 직원 2명, 태블릿 1대  
권장 소요: 설정 15분 + 태블릿 15분 + 관리자 확인 20분 + 회귀 10분

## 1. 테스트 전 준비

| 역할 | 준비 사항 |
| --- | --- |
| 관리자 | 테스트 사업장 관리자 계정으로 로그인한다. |
| 직원 A | 전화번호가 등록된 직원. 출근·퇴근·휴가 신청 담당. |
| 직원 B | 비교용 직원. 스케줄 및 연차 확인 담당. |
| 태블릿 | 매장 태블릿 URL을 고정하고 인터넷 연결을 확인한다. |

테스트 원칙:

- 실제 운영 데이터와 분리된 테스트 직원/사업장을 사용한다.
- 생성한 휴가·연차 부여·스케줄은 이름 또는 사유에 `MVP 테스트 YYYY-MM-DD`를 남긴다.
- 화면의 성공 알림 뒤 새로고침하여 실제 데이터가 유지되는지 확인한다.
- P0 실패 시 출시 보류, P1 실패는 수정 여부를 관리자와 결정한다.

## 2. 시나리오 A — 관리자의 아침 운영 준비

**사용자 목표:** 관리자가 매장 운영 기준과 오늘 근무자를 준비한다.

1. 관리자가 로그인한다.
2. 홈에서 사업장명, 직원 수, 승인 대기 건, 오늘 출근 요약을 확인한다.
3. `운영 설정`에서 태블릿 출퇴근 활성화, PIN, 기본 휴게시간을 확인한다.
4. `연차 · 월차 · 휴일 계산`에서 아래 항목을 확인 또는 설정한다.
   - 연차 부여 일수와 재직 개월 조건
   - 월차 자동 발생 여부, 월차 일수, 최소 등록 근무일
   - 정기 휴일 요일과 공휴일 직접 등록
5. 설정을 저장한 뒤 새로고침하여 값이 유지되는지 확인한다.
6. `스케줄`에서 직원 A·B의 오늘 근무를 등록하거나 수정한다.
7. 월간 보기에서 오늘 날짜와 등록 근무 인원이 표시되는지 확인한다.

**성공 기준:** 설정값과 스케줄이 새로고침 후 유지되고, 태블릿 URL이 현재 사업장으로 생성된다.

## 3. 시나리오 B — 직원의 태블릿 출근·퇴근

**사용자 목표:** 직원 A가 매장 태블릿에서 개인정보를 남기지 않고 출퇴근한다.

1. 태블릿에서 출퇴근 화면을 연다.
2. `태블릿 PIN`을 누른다.
3. 화면 내 숫자 키패드로 PIN을 입력하고 완료한다.
4. `전화번호 뒷 4자리`를 누른 뒤 숫자 키패드로 입력한다.
5. `직원 확인`을 누르고 표시된 이름이 직원 A인지 확인한다.
6. `출근하기`를 누른다.
7. 성공 알림을 닫고 입력된 전화번호가 초기화되는지 확인한다.
8. 퇴근 시 같은 절차를 반복해 `퇴근하기`를 누른다.

**성공 기준:** 출근과 퇴근은 같은 날짜의 하나의 근태 기록으로 저장되며, 태블릿에 전화번호가 남지 않는다.

## 4. 시나리오 C — 직원의 태블릿 휴가 신청

**사용자 목표:** 직원 A가 연차/반차를 신청하고 관리자가 확인할 수 있게 한다.

1. 태블릿에서 `휴가 신청` 탭을 누른다.
2. PIN과 전화번호 뒤 8자리를 숫자 키패드로 입력한다.
3. 미래의 평일 날짜를 선택하고 `오전 반차`를 선택한다.
4. `휴가 신청하기`를 누른다.
5. 완료 알림의 신청자 이름과 안내를 확인한다.
6. 정기 휴일 또는 운영 설정에 등록한 공휴일 날짜로도 신청을 시도한다.

**성공 기준:**

- 평일 반차는 0.5일로 승인 대기 요청이 생성된다.
- 휴일 제외 설정이 켜진 경우 정기 휴일·공휴일 신청은 차단된다.
- 잘못된 PIN/전화번호에서는 직원 정보가 노출되지 않는다.

## 5. 시나리오 D — 관리자의 승인과 연차 반영

**사용자 목표:** 관리자가 휴가 요청을 검토하고 직원의 연차 잔여를 확인한다.

1. 관리자 웹에서 홈의 승인 대기 카드 또는 `휴가 · 연차`로 이동한다.
2. 직원 A의 요청자, 날짜, 유형, 일수가 태블릿 입력값과 일치하는지 확인한다.
3. 관리자 메모에 `MVP 테스트 승인`을 입력하고 승인한다.
4. 직원 A 상세 페이지를 열어 승인 휴가가 표시되는지 확인한다.
5. 연차 잔여가 승인 일수만큼 감소했는지 확인한다.
6. 별도 요청을 하나 더 생성해 반려하고, 승인 사용/잔여가 감소하지 않는지 확인한다.

**성공 기준:** 승인 상태와 사용 연차·잔여 연차가 즉시 같은 데이터로 반영된다.

## 6. 시나리오 E — 직원 개인정보 수정 및 추가 연차 부여

**사용자 목표:** 관리자가 직원 정보를 바로 수정하고 특별 연차를 부여한다.

1. `직원 관리`에서 직원 B 상세로 이동한다.
2. `정보 수정`을 누른다.
3. 전화번호, 부서, 직책, 급여 정보, 입사일 중 한 개 이상을 수정하고 저장한다.
4. 새로고침 후 수정값이 상세·직원 목록에 유지되는지 확인한다.
5. `+ 연차 부여`를 누른다.
6. `1일`, 사유 `MVP 테스트 특별 부여`를 입력하고 부여한다.
7. 직원 상세의 연차 잔여, `추가 부여` 수치, 부여 이력을 확인한다.
8. 수정된 전화번호 뒤 4자리로 태블릿 직원 확인을 수행한다.

**성공 기준:** 개인정보 수정은 즉시 영속화되고, 추가 연차는 자동 발생 연차와 구분되어 잔여 연차에 합산된다.

## 7. 시나리오 F — 관리자 데이터 확인 및 권한 분리

**사용자 목표:** 관리자가 전 데이터가 현재 사업장에만 표시되는지 확인한다.

1. 홈에서 오늘 출퇴근, 승인 대기, 이번 주 스케줄을 확인한다.
2. `출퇴근 관리`에서 직원 A의 출근·퇴근 시각과 상태를 확인한다.
3. `휴가 · 연차`에서 직원 A 승인 내역, 직원 B 추가 연차 부여 결과를 확인한다.
4. 직원 상세에서 전화번호, 근무시간, 연차 이력, 스케줄이 표시되는지 확인한다.
5. 가능하면 다른 사업장 관리자 계정으로 로그인한다.

**성공 기준:** 현재 사업장 데이터만 보이며 다른 사업장의 직원·전화번호·근태·휴가·운영 설정은 노출되지 않는다.

## 8. 출시 판단 체크리스트

| 구분 | 출시 가능 기준 |
| --- | --- |
| 인증 | 관리자 로그인 후 올바른 사업장 데이터만 표시 |
| 태블릿 | PIN/전화번호 인증, 출근·퇴근, 휴가 신청 모두 성공 |
| 데이터 | 새로고침 후 스케줄·근태·휴가·연차 부여가 유지 |
| 계산 | 휴일 제외, 반차 0.5일, 승인 후 잔여 연차 변화가 정확 |
| 관리자 | 개인정보 수정과 연차 추가 부여 이력이 확인 가능 |
| 보안 | 다른 사업장·다른 직원 개인정보가 노출되지 않음 |
| UX | 모든 저장 작업에서 로딩/성공/오류 안내가 보이고 화면이 잘리지 않음 |
