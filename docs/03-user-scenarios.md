# TimeFit 사용자 시나리오 기획서

> 문서 버전: v0.1 · 대상: 관리자/직원 웹·모바일 사용자 · 작성일: 2026-08-09

## 1. 목적과 전제

TimeFit은 매장·소규모 사업장이 근태, 스케줄, 휴가·연차, 급여를 하나의 흐름으로 관리하도록 돕는다. 현재 테스트 버전은 상단 `관리자 / 직원` 전환으로 역할을 체험하며, 정식 버전에서는 회원가입 후 역할 기반 권한(RBAC)으로 같은 범위를 제한한다.

### 공통 원칙

- 직원은 자신의 정보와 본인에게 허용된 요청만 조회·수정할 수 있다.
- 관리자는 소속 사업장의 직원·스케줄·승인·정산 현황을 조회하고 처리한다.
- 급여와 연차 결과는 확정 전까지 `예상`으로 표시하고, 모든 승인·마감 동작은 이력을 남긴다.
- 모바일에서는 오늘 해야 할 한 가지 행동(출퇴근, 승인, 일정 확인)을 가장 먼저 보여 준다.

## 2. 관리자 사용 시나리오

### A-01. 하루를 시작하며 매장 현황 확인

| 항목 | 내용 |
|---|---|
| 사용자 | 사업주, 점장, 매니저 |
| 시작 조건 | 관리자 로그인 및 사업장 선택 완료 |
| 진입 화면 | 관리자 홈 대시보드 |
| 목표 | 출근 누락·지각·승인 대기 건을 빠르게 처리한다. |

**기본 흐름**

1. 관리자는 상단 모드가 `관리자`인지 확인한다.
2. 대시보드에서 오늘 출근 수, 근무 중 인원, 확인 필요 건, 월 인건비 예상액을 확인한다.
3. `확인 필요` 또는 실시간 출퇴근 목록에서 지각·미출근 직원을 선택한다.
4. 직원 상세 화면에서 오늘 스케줄, 실제 출근 시각, 최근 근무 기록을 확인한다.
5. 필요하면 출퇴근 수정 요청을 승인·반려하거나 직원에게 확인한다.

**완료 기준**

- 당일 미출근·지각 대상이 목록으로 확인된다.
- 직원 행을 누르면 어느 관리자 화면에서든 동일한 직원 상세로 이동한다.
- 처리 뒤 대시보드의 상태·대기 건 수가 갱신된다.

**예외 처리**

- 스케줄이 없는 직원: `스케줄 미등록` 상태로 표기하고 출근 여부를 자동 판단하지 않는다.
- 퇴근 누락: `퇴근 확인 필요` 상태로 분리해 다음 날 자동 결근 처리하지 않는다.
- 관리 권한 없는 근무지: 해당 직원의 개인정보·급여 항목을 열지 않는다.

### A-02. 주간 근무 스케줄 작성과 공지

| 항목 | 내용 |
|---|---|
| 사용자 | 관리자, 매니저 |
| 시작 조건 | 직원과 근무지, 근무유형이 등록됨 |
| 목표 | 인력 수요에 맞는 근무표를 작성하고 직원에게 알린다. |

**기본 흐름**

1. 관리자는 `스케줄`로 이동해 주간 또는 일간 보기를 선택한다.
2. 날짜 스트립에서 대상 날짜를 선택하고, 근무 인원·휴무·연차 수를 확인한다.
3. `근무 추가`를 누른다.
4. 직원, 근무지, 시작·종료 시각, 휴게시간, 근무유형을 입력한다.
5. 저장 전 중복 근무와 휴가 승인 일정을 확인한다.
6. 스케줄을 `게시`하고 직원에게 변경 알림을 발송한다.

**완료 기준**

- 한 직원·한 날짜에 중복되는 확정 근무가 경고된다.
- 게시된 일정은 직원 모드의 `내 스케줄`에서 바로 보인다.
- 스케줄을 누르면 해당 직원 상세 화면으로 이동해 근무 이력을 함께 확인할 수 있다.

**예외 처리**

- 승인된 연차와 충돌: 관리자가 대체 근무 배정 또는 휴가 조정 중 하나를 선택한다.
- 이미 출근한 날짜: 시작·종료 시각 수정 시 근태 수정 요청과 연결한다.
- 반복 근무: 한 번의 설정으로 반복 일정을 미리보기 후 생성한다.

### A-03. 휴가·연차 요청 검토

| 항목 | 내용 |
|---|---|
| 사용자 | 관리자, 매니저 |
| 시작 조건 | 직원이 휴가 요청을 제출함 |
| 목표 | 운영 공백과 연차 잔여를 고려해 요청을 처리한다. |

**기본 흐름**

1. 대시보드의 승인 대기 카드 또는 `휴가·연차` 메뉴로 진입한다.
2. 요청한 직원을 선택해 직원 상세의 잔여 연차, 해당 주 스케줄, 이전 요청을 확인한다.
3. 요청 기간·유형·사유와 대체 인력 필요 여부를 검토한다.
4. `승인` 또는 `반려`를 선택하고 필요 시 메모를 입력한다.
5. 승인 시 휴가 요청 상태, 연차 사용량, 해당 날짜의 스케줄 상태를 함께 갱신한다.
6. 직원에게 결과를 알린다.

**완료 기준**

- 승인된 요청만 연차 사용량에 반영된다.
- 반려된 요청은 잔여 연차를 차감하지 않는다.
- 요청·검토자·검토 시각·메모가 이력으로 남는다.

### A-04. 월 급여 예상액 검토와 마감

| 항목 | 내용 |
|---|---|
| 사용자 | 사업주, 급여 담당자 |
| 시작 조건 | 대상 월의 근태와 휴가가 입력됨 |
| 목표 | 근태 기반 예상 급여를 검토하고 지급 전 마감한다. |

**기본 흐름**

1. `급여 관리`에서 대상 월을 선택한다.
2. 총 예상 인건비, 산정 완료 인원, 근태 확인 필요 인원을 확인한다.
3. 확인 필요 직원 행을 눌러 직원 상세의 근무 시간·출퇴근 누락·휴가 상태를 검토한다.
4. 시급/월급, 연장·야간·휴일 시간, 수당·공제 조정 항목을 확인한다.
5. 오류가 없으면 급여 실행을 검토 상태로 변경한 뒤 마감한다.
6. 마감 후 직원별 명세서를 공개한다.

**완료 기준**

- 직원별 급여 항목은 하나의 월 급여 실행에 한 번만 생성된다.
- 마감 뒤에는 급여를 직접 수정할 수 없고 별도 조정 흐름을 사용한다.
- 실제 지급 전에는 `예상` 또는 `검토 중` 상태가 명확히 구분된다.

## 3. 직원 사용 시나리오

### E-01. 오늘 출근 전 일정 확인

| 항목 | 내용 |
|---|---|
| 사용자 | 직원 |
| 시작 조건 | 직원 계정이 사업장에 연결되고 스케줄이 게시됨 |
| 진입 화면 | 직원 홈 |
| 목표 | 오늘의 근무 시간·장소를 확인하고 출근 준비를 한다. |

**기본 흐름**

1. 직원은 상단 모드에서 `직원`을 선택한다. 정식 버전에서는 로그인 역할에 따라 자동 진입한다.
2. 홈 상단의 오늘 근무 카드에서 근무지, 시작·종료 시각, 예상 근무시간, 휴게시간을 확인한다.
3. `스케줄 보기`를 눌러 이번 주와 월간 개인 일정을 확인한다.
4. 일정이 잘못됐거나 근무가 어려우면 휴가 신청 또는 관리자 문의를 선택한다.

**완료 기준**

- 직원은 다른 직원의 스케줄·급여·휴가 정보를 볼 수 없다.
- 휴무와 연차 승인 일정은 일반 근무와 시각적으로 구분된다.
- 변경된 게시 스케줄은 홈과 내 스케줄에 동일하게 반영된다.

### E-02. QR 출근 및 퇴근

| 항목 | 내용 |
|---|---|
| 사용자 | 직원 |
| 시작 조건 | 해당일 근무 스케줄이 있고, 근무지 QR이 제공됨 |
| 목표 | 매장 QR로 본인의 출퇴근 시각을 남긴다. |

**기본 흐름**

1. 직원은 `출퇴근` 메뉴를 연다.
2. `QR 출근` 또는 `QR 퇴근` 버튼을 누른다.
3. 브라우저가 카메라 권한을 요청하면 허용한다.
4. 매장 QR 코드를 스캔 프레임에 맞춘다.
5. 시스템은 QR, 직원, 근무지, 현재 시각을 확인한 뒤 출근 또는 퇴근을 기록한다.
6. 완료 화면에서 기록 시각과 현재 누적 근무시간을 보여 준다.

**완료 기준**

- 한 근무일에는 출근 기록과 퇴근 기록을 각각 한 번만 확정한다.
- 출근 완료 뒤 버튼은 `QR 퇴근`으로 바뀐다.
- 기록 결과가 이번 주 근무 내역에 반영된다.

**예외 처리**

- 카메라 권한 거부: 권한 설정 안내와 관리자에게 출퇴근 수정 요청을 보인다.
- QR 인식 미지원 브라우저: 테스트 버전에서는 사진 인증으로 진행하고, 정식 버전에서는 QR 전용 스캐너 또는 수기 요청으로 대체한다.
- 이미 출근한 경우: 중복 기록 대신 기존 기록 시각과 수정 요청 버튼을 보여 준다.
- 스케줄 없는 출근: 관리자 정책에 따라 기록을 보류하거나 예외 근무로 요청한다.

### E-03. 휴가·연차 신청

| 항목 | 내용 |
|---|---|
| 사용자 | 직원 |
| 시작 조건 | 연차/휴가 정책 및 잔여 수량이 설정됨 |
| 목표 | 가능한 날짜의 휴가를 빠르게 신청하고 결과를 확인한다. |

**기본 흐름**

1. 직원은 `휴가` 메뉴에서 잔여 연차와 승인 대기 건을 확인한다.
2. `휴가 신청`을 누른다.
3. 휴가 유형, 시작일, 종료일, 필요 시 사유를 입력한다.
4. 시스템은 이미 등록된 근무와 다른 휴가 요청의 중복 여부를 보여 준다.
5. 직원이 신청을 전송한다.
6. 신청 상태는 `승인 대기`로 표시되고, 관리자 처리 후 `승인 완료` 또는 `반려`로 갱신된다.

**완료 기준**

- 신청 전후에 잔여 연차와 사용 예정량을 구분해 보여 준다.
- 반려 사유가 있으면 직원이 확인할 수 있다.
- 승인된 휴가는 내 스케줄에서 휴무 상태로 보인다.

### E-04. 내 근무·급여 정보 확인

| 항목 | 내용 |
|---|---|
| 사용자 | 직원 |
| 시작 조건 | 근태 기록 및 급여 실행이 생성됨 |
| 목표 | 월간 근무시간과 공개된 급여 정보를 신뢰할 수 있게 확인한다. |

**기본 흐름**

1. 직원은 홈에서 이번 주 누적 근무시간을 확인한다.
2. 출퇴근 메뉴에서 일자별 출근·퇴근·실근무시간을 확인한다.
3. 오류가 있으면 해당 기록에서 수정 요청을 보낸다.
4. 급여가 공개된 뒤 내 급여명세에서 기본급, 수당, 공제, 실지급액을 확인한다.

**완료 기준**

- 직원에게는 본인의 근태·급여 정보만 표시된다.
- 급여가 미공개이면 금액 대신 `관리자 검토 중` 상태를 표시한다.
- 근태 수정 요청은 승인 처리 전 원본 기록과 변경 요청 내용을 함께 보인다.

## 4. 역할별 화면·행동 매핑

| 화면 | 관리자 | 직원 |
|---|---|---|
| 홈 | 전체 출근, 승인 대기, 인건비, 전체 스케줄 | 오늘 근무, 내 근무시간, 잔여 연차 |
| 스케줄 | 전체 직원 배정, 생성·수정·게시 | 본인 일정 조회 |
| 출퇴근 | 전 직원 상태 조회, 수정 요청 검토 | QR 출퇴근, 본인 기록 확인 |
| 휴가·연차 | 요청 승인, 직원별 잔여일 확인 | 본인 휴가 신청·이력 확인 |
| 급여 | 전체 급여 산정·마감·공개 | 본인 공개 명세 확인 |
| 직원 상세 | 직원 정보, 근태, 휴가, 급여 요약 | 제공하지 않음 |

## 5. 정식 권한 분리 전환 기준

테스트 모드 전환은 UI 검증용이다. 회원가입을 도입할 때는 다음을 적용한다.

1. 로그인 사용자(`User`)와 직원 프로필(`Employee`)을 연결한다.
2. 조직 멤버십의 역할(`OWNER`, `ADMIN`, `MANAGER`, `EMPLOYEE`)을 API 미들웨어에서 검증한다.
3. 직원 역할의 모든 조회 API에 `employeeId = currentUser.employeeId` 조건을 강제한다.
4. 관리자 화면의 직원 행·상세 페이지는 담당 근무지 범위만 반환한다.
5. QR 기록에는 로그인 사용자, 근무지, QR 토큰 만료 시각을 함께 검증한다.

## 6. 다음 사용성 검증 항목

- 직원이 10초 안에 오늘 근무 시작 시각을 찾을 수 있는가.
- 직원이 카메라 권한 거부 상황에서 출퇴근 수정 요청까지 도달할 수 있는가.
- 관리자가 승인 대기 요청을 세 번 이내의 탭으로 처리할 수 있는가.
- 작은 화면에서 스케줄의 날짜·직원·근무시간이 겹치거나 잘리지 않는가.
