# 지출·증빙·운영순익 UI/UX 사용자 시나리오

버전: 1.0  
작성일: 2026-09-12  
참조: TimeFit 운영 화면, Granter 대시보드·매출‧정산·국내 매입 증빙

## 1. 검토 목적

관리자가 별도 교육 없이 다음 질문에 답하고 업무를 완료할 수 있는지 검증한다.

- 이번 달 실제 운영순익은 얼마인가?
- 운영순익이 변한 원인은 매출, 지출, 인건비 중 무엇인가?
- 처리하지 않은 증빙이나 카드 내역이 있는가?
- 카드 외 지출을 빠르고 정확하게 작성할 수 있는가?
- 입력한 금액이 그래프, 손익표, 원장에 일관되게 반영되는가?

평가는 기능 존재 여부가 아니라 사용자가 발견하고 이해하고 완료하는 데 필요한 시간과 실수를 기준으로 한다.

## 2. Granter 참조 결과

Granter는 좌측 메뉴를 `데이터 / 분석 / 업무 / 인사관리`로 구분하고, `매출‧정산` 내부를 `분석 / 판매 채널 / 국내 매출 증빙 / 국내 매입 증빙 / 해외 증빙` 탭으로 나눈다.

참조할 장점:

- 원천 데이터와 분석 화면의 위치가 구분된다.
- 기간 선택과 이전·다음 이동이 항상 같은 위치에 있다.
- 증빙 목록에서 검색, CSV, 테이블 설정을 상단 도구로 제공한다.
- 매출 증빙과 매입 증빙을 명칭으로 명확하게 구분한다.
- 빈 화면에서도 사용자가 보고 있는 데이터 종류와 표의 열 구조가 유지된다.

TimeFit에 그대로 적용하지 않을 부분:

- 국내·해외 증빙 분리는 현재 식당 운영 범위에 비해 복잡하다.
- 회계 중심 메뉴보다 `대시보드 / 지출 원장 / 증빙 검토 / 법인카드 / 정산 문서`가 매장 관리자에게 이해하기 쉽다.
- 관리자에게는 분석보다 `오늘 처리할 일`과 `간편 작성`이 더 중요하다.

## 3. 사용자 유형

### 사업장 소유자

- 목표: 매출과 비용을 비교하고 결산 가능 여부를 판단한다.
- 관심 정보: 운영순익, 순익률, 누락 데이터, 기간 비교, 결산 상태.
- 위험: 잠정값을 확정 실적으로 오해하거나 누락 지출을 놓침.

### 서브 관리자

- 목표: 발생한 지출을 기록하고 증빙 예외를 처리한다.
- 관심 정보: 작성 버튼, 필수 입력, 담당자, 중복 여부, 처리 완료 피드백.
- 위험: 회계 용어를 이해하지 못하거나 저장 후 반영 위치를 찾지 못함.

### 증빙 담당자

- 목표: 미증빙 카드와 OCR 실패만 빠르게 처리한다.
- 관심 정보: 남은 건수, 긴급도, 카드 후보, 원본 영수증.
- 위험: 정상 항목까지 반복 검토하거나 잘못된 카드 거래와 연결함.

## 4. 핵심 사용자 시나리오

### S1. 소유자가 이번 달 운영순익을 확인한다

상황: 출근 후 이번 달 매장 성과를 확인한다.

1. `지출 · 증빙` 상위 메뉴를 선택한다.
2. 기본 `대시보드`에 진입한다.
3. 월간 기간과 기준월을 확인한다.
4. 순매출, 운영지출, 인건비, 운영순익 KPI를 왼쪽에서 오른쪽으로 읽는다.
5. 운영순익 그래프와 기간별 손익표를 비교한다.
6. 데이터 상태가 마감·확정·잠정·불완전 중 무엇인지 확인한다.

성공 기준:

- 10초 안에 운영순익과 순익률을 말할 수 있다.
- 운영순익 산식이 `매출 - 지출 - 인건비`임을 이해한다.
- 숫자가 잠정인지 확정인지 구분한다.

현재 편의성: 상위 메뉴가 독립되어 접근이 쉽다. 4개 KPI가 한 줄로 연결되어 산식을 이해하기 쉽다.

현재 가시성: 흑자와 적자가 색상으로 구분되고 그래프와 표를 함께 확인할 수 있다.

현재 불편함:

- 비용 구성 카드가 KPI보다 먼저 보이는 배치에서는 핵심 숫자 탐색이 늦어질 수 있다.
- 경고가 여러 개면 그래프가 화면 아래로 밀린다.
- 운영순익 그래프가 현재 한 개 선 중심이라 매출 증가와 비용 증가를 즉시 비교하기 어렵다.

개선안: KPI → 핵심 경고 요약 → 복합 그래프 → 손익표 → 비용 구성 순서를 고정한다.

### S2. 운영순익이 낮아진 이유를 찾는다

상황: 지난 기간보다 운영순익이 감소했다.

1. KPI의 이전 기간 증감률을 확인한다.
2. 그래프에서 적자 또는 급락 날짜를 찾는다.
3. 같은 날짜의 손익표 행에서 매출·지출·인건비를 비교한다.
4. 해당 행을 선택해 지출 원장으로 이동한다.
5. 거래와 증빙 원본을 확인한다.

성공 기준:

- 30초 안에 감소 원인을 매출·지출·인건비 중 하나로 분류한다.
- 손익표 금액에서 원장과 증빙까지 두 번 이내의 선택으로 이동한다.

현재 편의성: 표가 그래프 값을 숫자로 설명한다.

현재 가시성: 운영순익 열의 막대 길이와 적자 색상으로 이상 기간을 찾기 쉽다.

현재 불편함: 손익표 행과 그래프 점이 아직 상세 원장으로 연결되지 않는다.

개선안: 그래프 점과 표 행을 같은 선택 상태로 연결하고 `이 날짜 원장 보기` drawer를 제공한다.

### S3. 서브 관리자가 카드 외 지출을 작성한다

상황: 현금 또는 계좌이체로 식자재를 구매했다.

1. `지출 · 증빙 > 대시보드`로 이동한다.
2. `+ 직접 지출 등록`을 선택한다.
3. 거래일, 사용처, 총금액, 분류를 입력한다.
4. 필요하면 담당 직원과 사유를 입력한다.
5. `확정 지출로 등록`을 선택한다.
6. 성공 메시지를 확인하고 원장으로 이동한다.

성공 기준:

- 필수 항목만으로 30초 안에 등록한다.
- 공급가액과 부가세를 몰라도 저장할 수 있다.
- 저장 결과와 원장 반영 위치를 즉시 이해한다.

실제 검증 결과:

- `[UI테스트] 강릉식자재`, 재료비, 최병주, 187,500원 등록 성공.
- 원장 합계와 확정 지출에 즉시 반영됨.
- 운영순익은 -187,500원으로 계산됨.

현재 편의성: 필수 필드가 일반적인 매장 용어로 작성되어 있다. 세액은 선택 입력이다.

현재 가시성: 등록 성공 메시지는 명확하지만 대시보드의 숫자가 자동 갱신되지는 않는다.

현재 불편함:

- 간편 입력이 대시보드 하단에 있어 처음 방문한 관리자가 발견하기 늦다.
- 저장 후 원장 탭을 직접 선택해야 한다.
- 작성 중 공급가액·부가세 같은 선택 필드가 필수 필드와 같은 비중으로 보인다.

개선안:

- 대시보드 상단에 `지출 등록` 주 행동 버튼을 둔다.
- 기본 폼은 거래일·사용처·금액·분류 네 항목만 표시한다.
- 담당자·사유·세액은 `상세 입력`으로 접는다.
- 저장 후 `원장에서 보기`와 `계속 등록` 버튼을 제공한다.
- 저장 이벤트로 KPI, 그래프, 손익표를 자동 갱신한다.

### S4. 중복 지출을 방지한다

상황: 동일 영수증을 다른 관리자가 다시 작성하려 한다.

1. 같은 날짜·사용처·금액을 입력한다.
2. 시스템의 중복 경고를 확인한다.
3. 기존 지출을 보거나 별도 지출임을 확인한다.

성공 기준:

- 중복 항목을 조용히 저장하지 않는다.
- 기존 항목과 새 입력을 비교할 수 있다.
- 별도 지출 등록은 명시적인 추가 행동을 요구한다.

현재 불편함: 경고는 제공되지만 기존 항목 상세를 바로 볼 수 없다.

개선안: 경고 영역에 기존 거래일·사용처·금액과 `기존 지출 보기`를 표시한다.

### S5. 증빙 담당자가 오늘 처리할 일을 확인한다

상황: 마감 전에 미증빙·OCR 실패를 처리한다.

1. 대시보드의 예외 업무함에서 긴급·주의 건수를 확인한다.
2. `증빙 검토` 탭으로 이동한다.
3. 미증빙 카드, 영수증 검토, OCR 실패 중 하나를 선택한다.
4. 원본과 카드 후보를 비교하고 확정·반려한다.

성공 기준:

- 정상 항목은 목록에 노출되지 않는다.
- 긴급 건이 가장 위에 표시된다.
- 처리 후 남은 건수가 즉시 감소한다.

현재 편의성: Granter의 전체 증빙표보다 예외 중심이라 일상 업무량이 적다.

현재 불편함: 대시보드 예외 카드와 증빙 검토 탭의 필터 상태가 이어지지 않는다.

개선안: 예외 건수 카드를 선택하면 해당 필터가 적용된 증빙 검토 탭으로 이동한다.

### S6. 소유자가 월말 결산 가능 여부를 판단한다

1. 데이터 상태와 증빙률을 확인한다.
2. 미대사 카드, 미처리 영수증, 카드 연결, 급여 초안을 확인한다.
3. 모든 필수 조건이 충족되면 결산 저장을 선택한다.
4. 확정 전 기간·운영순익·version을 재확인한다.

성공 기준:

- 결산 불가 이유를 한 화면에서 이해한다.
- 소유자가 아닌 관리자는 결산 확정 버튼을 볼 수 없다.
- 마감 후 숫자가 조용히 변경되지 않는다.

현재 불편함: 경고가 개별 문장으로 나열되어 전체 완료율을 판단하기 어렵다.

개선안: `결산 준비 3/5 완료` 체크리스트와 미완료 항목 바로가기를 제공한다.

### S7. 모바일에서 지출과 손익을 확인한다

1. 모바일에서 `지출 · 증빙`을 연다.
2. KPI를 두 열로 확인한다.
3. 내부 탭을 가로 스크롤한다.
4. 손익표를 가로 이동하며 금액을 확인한다.
5. 간편 지출을 작성한다.

성공 기준:

- 주요 버튼의 높이가 44px 이상이다.
- 가로 스크롤이 필요한 영역임을 사용자가 인지한다.
- 입력 중 저장 버튼과 오류 메시지가 화면에서 사라지지 않는다.

현재 불편함: 손익표의 가로 스크롤 가능 여부가 시각적으로 약하다.

개선안: 우측 fade와 `옆으로 밀어 전체 금액 보기` 안내를 첫 방문에 표시한다.

## 5. 발견된 주요 문제

| 우선순위 | 문제 | 영향 | 권장 개선 |
|---|---|---|---|
| P0 | 운영 DB 설정 컬럼 누락 시 그래프·표 전체 실패 | 손익 확인 불가 | 스키마 보정 및 API 부분 실패 허용 |
| P1 | 작성 후 대시보드 자동 갱신 없음 | 반영 여부 불확실 | 저장 이벤트 기반 재조회 |
| P1 | 그래프·표에서 원장 drill-down 없음 | 원인 파악 지연 | 날짜 drawer와 필터 연결 |
| P1 | 월간 최근 10개가 미래 날짜를 표시 | 실제 데이터 가려짐 | 오늘까지 최근 기간 우선 표시 |
| P1 | 서브 관리자 조회·작성 권한의 API 강제 미완료 | 보안·역할 혼란 | 서버에서 권한 코드 검증 |
| P2 | 핵심 경고가 여러 문장으로 분산 | 결산 상태 판단 지연 | 단일 준비도 체크리스트 |
| P2 | 간편 작성의 선택 필드 비중이 큼 | 입력 부담 | 필수 4개 + 상세 펼치기 |
| P2 | 모바일 손익표 스크롤 안내 부족 | 열 누락 오해 | fade·스크롤 힌트 |
| P3 | 그래프가 운영순익 중심 | 변화 원인 비교 제한 | 매출·지출·인건비 범례 토글 |

P0의 운영 DB 누락 문제와 미래 날짜 우선 노출 문제는 실제 테스트 중 발견되어 보정 완료했다.

## 6. 사용성 평가표

테스트 참여자는 각 시나리오 완료 후 1~5점으로 평가한다.

| 평가 항목 | 질문 |
|---|---|
| 발견성 | 원하는 메뉴와 버튼을 바로 찾았는가? |
| 이해성 | 용어와 숫자의 의미를 설명 없이 이해했는가? |
| 효율성 | 불필요한 이동이나 반복 입력이 없었는가? |
| 가시성 | 중요한 숫자, 경고, 상태가 먼저 보였는가? |
| 확신성 | 저장·반영·결산 결과를 확신할 수 있었는가? |
| 오류 회복 | 실수했을 때 원인과 해결 방법을 알 수 있었는가? |

목표 기준:

- 핵심 시나리오 성공률 90% 이상
- 간편 지출 등록 중앙값 30초 이하
- 운영순익 확인 중앙값 10초 이하
- 원인 추적 중앙값 30초 이하
- 치명적 오류와 권한 우회 0건
- 항목별 평균 4.0점 이상

## 7. 권장 화면 순서

```text
지출 · 증빙
├─ 기간·데이터 상태
├─ 핵심 KPI 4개
├─ 결산 준비도·긴급 예외 요약
├─ 운영손익 복합 그래프
├─ 기간별 손익표
├─ 비용 구성
├─ 빠른 작업
│  ├─ 지출 등록
│  ├─ 영수증 검토
│  └─ 미대사 카드 확인
└─ 결산 이력
```

작성 업무는 대시보드의 주 행동 버튼에서 시작하되, 긴 폼이 핵심 분석을 밀어내지 않도록 drawer 또는 modal로 제공한다.

## 9. 최종 판단

현재 구조는 Granter처럼 분석과 증빙을 목적별 탭으로 분리하면서도 매장 관리자 업무에 맞게 단순화되어 있다. 독립 메뉴, KPI, 그래프, 표, 예외 업무함은 전체 방향이 적절하다.

다만 사용자가 `숫자를 확인하는 경험`은 갖춰졌지만 `숫자의 원인을 찾아 바로 처리하는 경험`은 아직 연결이 부족하다. 다음 개선의 중심은 화면을 더 추가하는 것이 아니라 대시보드의 숫자, 예외 업무, 작성 폼, 원장을 같은 선택 상태로 연결하는 것이다.
