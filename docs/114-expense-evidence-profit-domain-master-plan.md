# 지출·증빙·운영순익 도메인 통합 설계

버전: 1.0  
작성일: 2026-09-12  
상태: 구현 기준안

## 1. 목표

매출, 지출, 증빙, 카드, 인건비를 하나의 운영손익 흐름으로 연결한다. 소유자는 숫자의 정확성과 결산 상태를 확인하고, 서브 관리자는 회계 지식 없이도 발생한 지출과 증빙을 빠르게 입력할 수 있어야 한다.

공식 지표명은 `운영순익(추정)`으로 사용한다. 세무상 당기순이익과 혼동되는 `순이익`, `세후순이익`은 사용하지 않는다.

## 2. 정보 구조

상위 메뉴에서 `지출 · 증빙`을 독립 업무영역으로 제공한다.

1. 대시보드: 간편 지출 작성, 예외 업무함, 운영손익 KPI·차트·표
2. 지출 원장: 확정 지출 검색, 상태·분류 필터, 원천 추적
3. 증빙 검토: OCR 결과, 카드 후보, 중복·예외 처리, 미제출 알림
4. 법인카드: 연결, 동기화, 승인·취소·매입 상태
5. 정산 문서: 세금계산서·매출전표 보관, 세무사 전달, 월말 결산

기본 진입점은 대시보드다. 가장 자주 하는 작성 업무와 가장 중요한 예외를 손익 차트보다 먼저 보여준다.

## 3. 대시보드 UI

### 3.1 상단 제어

- 기간: 일간, 주간, 월간, 연간
- 기준일과 조회 범위
- CSV, PDF·인쇄
- 소유자 전용 결산 저장
- 데이터 상태: 마감, 확정 기준, 잠정, 불완전

### 3.2 요약과 시각화

- KPI: 순매출, 운영지출, 인건비, 운영순익·순익률
- 보조 지표: 주방 구매비, 홀 구매비, 기타 지출, 카드수수료, 매출연동 임대료, 주문단가
- 차트: 기간별 운영순익과 0원 기준선
- 손익표: 기간, 주문 수, 순매출, 운영지출, 인건비, 운영순익, 순익률
- 기본 10개 기간을 표시하고 전체 펼치기를 제공한다.

차트와 표는 반드시 같은 API 응답을 사용한다. 화면에서 별도로 재집계하지 않는다.

## 4. 서브 관리자 작성 UX

`지출·증빙 작성` 권한이 있는 서브 관리자에게 대시보드 첫 화면의 `카드 외 지출` 입력을 제공한다.

필수 입력:

- 거래일
- 사용처
- 총금액
- 분류

선택 입력:

- 공급가액과 부가세
- 담당 직원
- 지출 사유

UX 원칙:

- 기본값은 오늘 날짜다.
- 회계 계정과목 대신 재료비, 소모품비, 교통비, 접대비, 공과금, 임차료, 기타를 사용한다.
- 공급가액과 부가세는 둘 다 비워도 된다. 입력한 경우 합계가 총금액과 같아야 한다.
- 같은 날짜·사용처·금액이 존재하면 중복 경고 후 명시적으로 별도 등록하게 한다.
- 등록자는 결산을 확정할 수 없다. 결산 저장·확정·재오픈은 소유자에게만 제공한다.
- 성공 후 원장에서 확인하도록 안내하고 감사 로그에 작성자를 보관한다.

향후 2차 개선에서는 입력 폼을 2단계로 단순화한다. 1단계에서 날짜·사용처·금액·분류만 받고, 세금·담당자·메모는 `상세 입력`에서 펼친다.

## 5. 역할과 권한

| 역할/권한 | 대시보드·원장 조회 | 지출 작성 | 증빙 검토 | 카드 연결 | 결산 확정 |
|---|---:|---:|---:|---:|---:|
| 소유자 | 가능 | 가능 | 가능 | 가능 | 가능 |
| 지출·손익 조회 | 가능 | 불가 | 불가 | 불가 | 불가 |
| 지출·증빙 작성 | 가능 | 가능 | 가능 | 운영 정책에 따라 제한 | 불가 |
| 일반 직원 | 본인 제출 내역만 | 불가 | 불가 | 불가 | 불가 |

권한 코드는 `finance.view`와 `expense.manage`로 분리한다. 프런트 표시뿐 아니라 API에서도 동일 권한을 검증하는 것을 최종 완료 조건으로 한다.

## 6. 데이터 상태

- 마감: snapshot으로 고정된 기간
- 확정 기준: 현재 수집된 확정 매출·지출·인건비로 계산
- 잠정: 미처리 영수증 또는 급여 초안 누락 등으로 변경 가능
- 불완전: 카드·매출 원천 연결 장애로 정상 집계 여부를 보장할 수 없음

누락값을 0원으로 조용히 표시하지 않는다. 경고와 상태를 함께 표시하며, 불완전한 날짜를 정상 차트 선으로 이어서는 안 된다.

## 7. 산식과 추적성

```text
운영순익(추정) = 순매출 - 운영지출 - 실제/예상 인건비
운영순익률 = 운영순익 ÷ 순매출 × 100
```

모든 손익표 행은 매출 주문, 지출 원장, 카드 이벤트, 영수증 원본, 급여 초안까지 역추적 가능해야 한다. 마감 기간은 snapshot version과 기준 시각을 표시한다.

## 8. 완료 기준

- 지출·증빙이 다른 정산 메뉴와 분리된 독립 영역으로 동작한다.
- 기본 진입 시 간편 작성, 예외, KPI, 차트, 손익표 순서로 확인할 수 있다.
- 차트와 표의 운영순익 합계가 원 단위로 일치한다.
- 서브 관리자에게 조회와 작성 권한을 별도로 부여할 수 있다.
- 작성자는 중복·세액 합계 검증을 통과해야 지출을 저장할 수 있다.
- 소유자가 아닌 사용자는 결산을 확정하거나 재오픈할 수 없다.
- 데스크톱과 모바일에서 기간 탭과 손익표를 사용할 수 있다.

## 9. 후속 우선순위

1. API 권한을 `finance.view`, `expense.manage` 단위로 강제
2. 지출 저장 후 대시보드·손익표 자동 재조회
3. 차트 행 선택 시 해당 날짜 원장 drawer 연결
4. 매출 취소·할인·환불과 카드 승인 잠정액을 별도 series로 제공
5. 확정·잠정 구간의 실선·점선 및 불완전 구간 단절
6. 비용 구성과 운영순익률 보조 차트
7. 화면·CSV·PDF·Excel snapshot version 통일
