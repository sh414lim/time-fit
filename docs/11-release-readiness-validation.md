# TimeFit 출시 전 검증 결과

- 검증 일시: 2026-08-10
- 대상: https://timefit-omega.vercel.app/
- 환경: Codex 인앱 브라우저, 프로덕션 소스·Supabase Edge Function 점검

## 1. 다중 사용자 데이터 영속화

**결과: 미통과 (출시 차단 항목)**

확인 결과, 인증·사업장 생성·직원 초대 수락은 Supabase Auth 및 `timefit_user_*` 테이블을 사용합니다. 그러나 업무 데이터는 아직 브라우저 로컬 저장소 기반입니다.

- `employees`, `schedules`, `leave-requests`, `checked-in`은 `usePersistedState`로 저장됩니다.
- 스케줄 저장, 휴가 신청/승인, 직원 등록은 React 상태 변경만 수행합니다.
- 급여 표와 CSV 원본 데이터는 화면에 하드코딩되어 있습니다.
- 따라서 다른 사용자·다른 기기에서 변경 사항을 즉시 확인할 수 없으며, 계정·사업장 단위 데이터 격리도 보장되지 않습니다.

Supabase에는 `work_schedules`, `leave_requests`, `payroll_runs`, `payroll_items`, `attendance_records` 스키마가 준비되어 있으나, 현재 화면의 CRUD와 연결되어 있지 않습니다.

## 2. QR 출퇴근

**결과: 조건부 통과**

- 직원 계정에서 `QR 출근`을 눌러 스캐너 UI가 열리고 `QR 코드를 찾는 중…` 상태를 확인했습니다.
- 프로덕션 `qr-attendance` Edge Function에 인증 없는 무효 요청을 전송한 결과 HTTP `401`을 반환하여 인증 보호가 동작함을 확인했습니다.
- 코드상 유효 QR 토큰은 `record_qr_attendance` RPC로 전달되어 출퇴근 기록을 처리하도록 구현되어 있습니다.

실제 통과로 판정하려면 아래가 추가로 필요합니다.

1. 실매장 또는 테스트용 유효 QR 토큰을 생성한다.
2. 모바일 실기기 HTTPS 환경에서 카메라 권한을 허용한다.
3. 출근·퇴근 각각을 촬영하고 `attendance_records`에 생성·갱신되는지 확인한다.
4. 권한 거부, 만료 QR, 다른 사업장 QR, 중복 출근 등 실패 케이스를 확인한다.

## 3. CSV 다운로드

**결과: 구현 정적 검증 통과 / 실제 다운로드 미검증**

- 급여 화면은 UTF-8 BOM이 포함된 CSV Blob을 생성하고 `timefit-2026-08-payroll.csv` 파일명으로 다운로드하도록 구현되어 있습니다.
- 실제 파일 다운로드는 브라우저의 다운로드 확인 동작을 발생시키므로, 사용자 승인 없이 실행하지 않았습니다.
- 또한 CSV 데이터가 현재 하드코딩된 샘플 급여 목록이므로, 운영 급여 데이터가 아닌 MVP 샘플 파일만 생성됩니다.

## 출시 판정

현재 버전은 **인증·초대·화면 프로토타입 데모** 용도로는 확인 가능하지만, 실제 사업장 운영 MVP로 출시하기에는 업무 데이터 CRUD 영속화가 선행되어야 합니다. QR 실촬영과 CSV 파일 실다운로드도 그 이후 최종 승인 테스트로 진행해야 합니다.
