## 1. 실제 날짜 기준 휴일 근무 보상

운영 설정에서 일요일을 정기휴일로 지정하고, 2026-08-30을 공휴일로 등록했다.

| 분기 | 설정 | 실제 태블릿 기록 | 관리자 데이터 검증 |
| --- | --- | --- | --- |
| 공휴일 우선 | 공휴일: 대체휴무 1일 / 정기휴일: 추가 유급휴가 1일 | `UAT 주방직원` 실제 출근·퇴근 | `공휴일 근무 보상 2026-08-30`, 추가 부여 `+1일` 저장 |
| 정기휴일 단독 | 2026-08-30 공휴일 등록 제거 / 일요일: 추가 유급휴가 1일 | `ㄹㅇ` 실제 출근·퇴근 | `정기휴일 근무 보상 2026-08-30`, 추가 부여 `+1일` 및 연차 잔여 1일 저장 |

공휴일과 정기휴일이 겹칠 때는 공휴일 정책이 우선한다. 공휴일 정책이 `보상 없음`이어도 공휴일 우선 규칙 때문에 정기휴일 보상으로 대체하지 않는 동작을 확인했다. 이는 정책 우선순위가 명확히 적용된 결과다.

## 2. Toss Place 주문 동기화와 DB 캐시

- 실제 `지금 동기화` 호출 결과: Toss Place API 인증 실패(HTTP 401).
- 서버는 이를 `toss_auth_failed`로 처리하고, 사업장 연결 상태 및 동기화 상태의 `last_error`에 저장한다.
- 현재 연결은 플랫폼 서버 인증정보를 사용하는 구성이다. 서비스 코드/판매점 ID는 연결 정보로 저장되지만, 주문 API 조회에는 별도의 유효한 Access Key·Secret이 필요하다.
- 인증이 실패했으므로 원본 주문 upsert와 `timefit_user_tossplace_daily_sales` 일별 캐시 생성은 실행되지 않았다. 임의 매출을 만들지 않고 검증을 보류한다.

필요 조치: 버터빌라 판매점 주문 조회 권한이 있는 Toss Place 개발자 앱의 Access Key·Secret을 Vercel Production `TOSSPLACE_ACCESS_KEY`, `TOSSPLACE_ACCESS_SECRET`에 갱신하거나, 운영 설정에서 해당 사업장 전용 인증정보로 암호화 저장한다. 갱신 후 `지금 동기화` 1회 → 주문 행 저장 → 일별 캐시 및 매출 대시보드 수치 반영 순서로 재검증한다.

## 3. 설정 저장 뒤 화면 핸들

- 설정 저장 시 전체 사업장 데이터를 전역 로딩으로 다시 읽던 콜백을 제거했다.
- 이제 각 설정 화면은 저장 결과 모달을 유지하며, 사용자가 보고 있던 화면과 입력 흐름을 강제로 홈/로딩 화면으로 바꾸지 않는다.
- 브라우저 자동화에서는 저장 직후 기존 페이지 핸들이 간헐적으로 빈 문서 상태가 되는 현상을 재현했다. 같은 세션의 새 탭에서는 저장된 정책과 정상 화면을 즉시 확인했다.
- 따라서 DB 저장/웹 렌더 결과는 정상이나, 자동화 드라이버의 저장 완료 모달(포털) 이후 핸들 재사용 문제는 별도 자동화 안정성 항목으로 남긴다. 실제 운영 브라우저에서는 신규 탭·재진입 시 저장값이 정상적으로 유지됨을 확인했다.
