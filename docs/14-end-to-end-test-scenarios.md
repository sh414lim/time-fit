# TimeFit 전체 E2E 테스트 시나리오

## 목적 및 환경

- 대상: `https://timefit-omega.vercel.app/`
- 태블릿: `https://timefit-omega.vercel.app/tablet?organization={사업장ID}`
- 역할: 관리자 1명, 직원 2명 이상
- 공통 전제: 테스트용 관리자와 직원은 서로 다른 이메일·전화번호 뒷 4/8자리를 사용한다.
- 현재 알림톡은 발송 로그 생성 단계이며, 실제 수신 검증은 딜러사 키·승인 템플릿 등록 후 수행한다.

## A. 가입·사업장·직원 초대

### A-01. 관리자 가입 및 사업장 생성

1. 로그인 화면에서 `회원가입`을 누른다.
2. `관리자`를 선택한다.
3. 이름, 사업장명, 이메일, 비밀번호를 입력해 가입한다.
4. 로그인 후 관리자 홈으로 이동하는지 확인한다.
5. 좌측 하단 사업장명이 가입 시 입력한 값과 일치하는지 확인한다.

기대 결과: 관리자 역할과 사업장·관리자 멤버십이 Supabase에 생성된다.

### A-02. 직원 가입 및 고유번호 발급

1. 관리자 로그아웃 후 `직원`으로 회원가입한다.
2. 직원 홈에서 직원 고유번호를 확인한다.

기대 결과: 직원은 사업장 연결 전에도 고유번호를 확인할 수 있다.

### A-03. 관리자 초대 및 직원 수락

1. 관리자로 로그인해 `직원 관리` → `직원 초대`를 선택한다.
2. 직원 고유번호, 부서, 직책을 입력해 초대한다.
3. 직원 계정으로 로그인해 초대 카드를 확인하고 `초대 수락하기`를 누른다.
4. 다시 로그인한 뒤 사업장 이름이 표시되는지 확인한다.

기대 결과: 직원 멤버십과 업무용 직원 레코드가 생성된다.

## B. 관리자 운영 설정

### B-01. 운영 설정 저장

1. 관리자 메뉴에서 `운영 설정`을 연다.
2. 사업장 표시명, 주소, 기본 휴게시간, 태블릿 PIN을 입력한다.
3. 태블릿 출퇴근 활성화 상태를 켠 뒤 저장한다.
4. 새로고침 후 입력값이 유지되는지 확인한다.

기대 결과: 설정이 사업장 단위로 Supabase에 저장된다.

### B-02. 태블릿 URL 확인

1. 운영 설정의 태블릿 주소를 복사한다.
2. 별도 태블릿/브라우저에서 주소를 연다.

기대 결과: 로그인 없이 태블릿 전용 출퇴근/휴가 신청 화면이 나타난다.

## C. 태블릿 전화번호 출퇴근

### C-01. 직원 확인 → 출근

사전 조건: 직원 레코드에 전화번호 뒷 4자리가 등록돼 있다.

1. 태블릿에서 `출퇴근` 탭을 선택한다.
2. 태블릿 PIN과 직원 전화번호 뒷 4자리를 입력해 `직원 확인`을 누른다.
3. 이름 확인 모달이 표시되는지 확인한다.
4. `출근하기`를 누른다.

기대 결과: 성공 메시지가 표시되고 `timefit_user_attendance_records`에 오늘 출근 시각과 `tablet_phone_last4` 출처가 저장된다.

### C-02. 퇴근 처리

1. 동일 직원으로 다시 확인한다.
2. 모달의 버튼이 `퇴근하기`로 표시되는지 확인한다.
3. 퇴근하기를 누른다.

기대 결과: 같은 오늘 기록의 퇴근 시각이 갱신된다.

### C-03. 실패 케이스

- 잘못된 태블릿 PIN → 접근 거부 안내
- 존재하지 않는 전화번호 뒷 4자리 → 직원 없음 안내
- 퇴근 완료 후 재퇴근 → 중복 처리 방지
- 비활성화된 태블릿 설정 → 접근 거부

## D. 관리자 출퇴근 조회

### D-01. 태블릿 기록 반영

1. 관리자 웹에서 `출퇴근 관리`를 연다.
2. C-01 수행 직후 새로고침한다.
3. 해당 직원이 `근무 중`과 출근 시각으로 표시되는지 확인한다.
4. C-02 수행 뒤 새로고침한다.

기대 결과: 해당 직원은 `퇴근 완료`으로 표시되고 근태 기록은 유지된다.

## E. 태블릿 휴가 신청

### E-01. 연차 신청

사전 조건: 직원 레코드에 전화번호 뒷 8자리가 등록돼 있다.

1. 태블릿에서 `휴가 신청` 탭을 선택한다.
2. PIN과 전화번호 뒷 8자리를 입력한다.
3. 미래 날짜를 캘린더에서 선택한다.
4. `연차`를 선택하고 신청한다.

기대 결과: `timefit_user_leave_requests`에 `source=tablet`, `status=pending`으로 저장된다.

### E-02. 반차 신청

1. E-01과 동일한 절차로 다른 미래 날짜를 선택한다.
2. `오전 반차`, `오후 반차`를 각각 신청한다.

기대 결과: 각 신청의 휴가 일수는 `0.5일`로 저장된다.

### E-03. 휴가 신청 실패 케이스

- 과거 날짜 선택 불가
- 잘못된 PIN/전화번호 뒷 8자리 거부
- 동일 날짜 중복 신청 시 정책에 따른 차단 또는 경고
- 알림 발송 실패가 휴가 신청 저장 자체를 실패시키지 않는지 확인

## F. 관리자 휴가 검토·알림 로그

### F-01. 휴가 목록 확인

1. 태블릿에서 휴가 신청을 완료한다.
2. 관리자 웹 `휴가 · 연차 관리`를 새로고침한다.
3. 신청 직원·일자·유형·승인 대기 상태를 확인한다.

기대 결과: 태블릿 신청이 관리자 목록에 표시된다.

### F-02. 승인 및 반려

1. 관리자에서 신청을 선택한다.
2. 승인 메모를 입력해 `승인하기`를 누른다.
3. 다른 신청은 `반려`한다.
4. 직원 계정의 휴가 내역에서 결과를 확인한다.

기대 결과: 상태와 검토 시각·검토자가 Supabase에 저장되고 직원에게 반영된다.

### F-03. 카카오 알림톡 전환 검증

현재: 신청 시 `timefit_user_notification_logs`에 `queued` 또는 관리자 번호 미등록 시 `disabled` 로그가 생성된다.

실제 연동 후 추가 확인:

1. 관리자 직원의 수신 번호가 등록돼 있는지 확인한다.
2. 태블릿 휴가 신청 후 알림 로그가 `sent`가 되는지 확인한다.
3. 관리자 카카오톡에서 승인된 템플릿 메시지가 1회 수신되는지 확인한다.
4. 공급사 오류 시 `failed` 로그·재시도 정책을 확인한다.

## G. 관리자 웹 어드민 확인·승인 상세 시나리오

### G-01. 어드민 로그인과 사업장 범위 확인

1. 관리자 계정으로 로그인한다.
2. 좌측 메뉴에 `홈`, `출퇴근`, `스케줄`, `휴가 · 연차`, `급여 관리`, `직원 관리`, `운영 설정`이 보이는지 확인한다.
3. 사이드바의 사업장명과 로그인한 관리자 이름을 확인한다.
4. 직원 계정으로 재로그인해 관리자 메뉴가 노출되지 않는지 확인한다.

기대 결과: 역할에 따라 관리자 전용 메뉴가 분리되고, 현재 사업장 데이터만 보인다.

### G-02. 태블릿 출퇴근 기록 확인

사전 조건: 직원이 태블릿에서 출근 또는 퇴근을 처리했다.

1. 관리자 웹에서 `출퇴근` 메뉴를 연다.
2. 직원 이름, 상태, 출근 시각, 근무 상태를 확인한다.
3. `근무 중`, `미출근`, `휴가` 필터를 각각 선택한다.
4. 태블릿에서 직원 퇴근을 처리한 후 관리자 화면을 새로고침한다.

기대 결과:

- 출근 후: `근무 중` 및 실제 출근 시각 표시
- 퇴근 후: `퇴근 완료` 표시
- 다른 사업장 직원 기록은 노출되지 않음

### G-03. 태블릿 휴가 신청 확인

사전 조건: 직원이 태블릿에서 연차 또는 반차를 신청했다.

1. 관리자 웹에서 `휴가 · 연차 관리`를 연다.
2. `승인 대기 중인 휴가` 건수와 목록을 확인한다.
3. 신청 행을 선택해 휴가 요청 검토 모달을 연다.
4. 직원명, 휴가 종류, 날짜, 일수, 태블릿 신청 여부를 확인한다.

기대 결과: 태블릿 신청은 승인 대기 상태로 관리자에게 표시된다.

### G-04. 휴가 승인

1. G-03의 신청 상세에서 관리자 메모를 입력한다.
2. `승인하기`를 누른다.
3. 모달이 닫히고 목록 상태가 `승인 완료`로 변경되는지 확인한다.
4. 페이지를 새로고침해 승인 상태가 유지되는지 확인한다.
5. 직원 계정으로 로그인해 내 휴가 내역이 승인 완료인지 확인한다.

기대 결과: `timefit_user_leave_requests`에 `approved`, 검토자, 검토 시각, 메모가 저장된다.

### G-05. 휴가 반려

1. 새 태블릿 휴가 신청을 만든다.
2. 관리자에서 해당 신청을 열고 반려 사유를 입력한다.
3. `반려`를 누른다.
4. 관리자·직원 화면을 각각 새로고침한다.

기대 결과: 상태가 `반려`로 일관되게 표시되고 승인 대기 건수에서 제외된다.

### G-06. 중복·정책 검토

1. 직원이 같은 날짜에 같은 유형의 휴가를 다시 신청한다.
2. 관리자 목록에서 중복 신청의 표시·정책 처리 결과를 확인한다.
3. 이미 승인된 휴가 날짜에 스케줄을 추가하려고 시도한다.
4. 연차 잔여보다 큰 신청을 시도한다.

기대 결과: 현재 정책이 경고 또는 차단으로 일관되게 동작해야 한다. 연차 잔여 자동 차감 정책이 도입되기 전에는 관리자 검토 화면에 명확한 안내가 표시돼야 한다.

### G-07. 알림 발송 로그 확인

1. 관리자로 휴가 요청 상세를 확인한다.
2. 신청 이후 `timefit_user_notification_logs`의 상태를 확인한다.
3. 관리자 직원의 수신 전화번호가 미등록이면 `disabled`와 사유가 남는지 확인한다.
4. 딜러사 연동 후에는 `queued → sent` 전환과 공급사 메시지 ID를 확인한다.
5. 강제 실패 테스트 후 `failed` 및 오류 메시지, 재시도 횟수를 확인한다.

기대 결과: 휴가 신청 데이터와 알림 발송 성공/실패가 분리되어 추적된다.

### G-08. 관리자 권한 및 감사 확인

1. 직원 계정으로 휴가 요청 상태 변경 API를 호출하거나 화면 조작을 시도한다.
2. 다른 사업장 관리자로 현재 사업장 휴가·근태를 조회하려고 한다.
3. 승인/반려 후 DB의 `reviewed_by`, `reviewed_at`, `review_comment` 값을 확인한다.

기대 결과: RLS가 권한 없는 읽기·수정 요청을 차단하고, 관리자 승인 이력이 남는다.

## H. 권한·회귀

- 직원이 관리자 운영 설정·급여 관리에 접근할 수 없는지 확인한다.
- 다른 사업장 태블릿 URL과 PIN/전화번호를 사용해도 기록이 생성되지 않는지 확인한다.
- 로그아웃·로그인·새로고침 후 스케줄, 휴가, 근태 조회가 유지되는지 확인한다.
- 모바일 화면에서 메뉴·모달·하단 내비게이션이 가려지지 않는지 확인한다.
- 콘솔 오류와 Edge Function 오류 로그가 없는지 확인한다.

## 최종 통과 기준

- A~F의 정상·실패 시나리오가 모두 통과
- Supabase 데이터가 다른 계정·다른 기기에서 일관되게 보임
- 태블릿 출퇴근·휴가 신청이 중복 없이 저장됨
- 알림톡 실연동 후 관리자 수신 및 실패 재시도 검증 완료
