# 무인 리뷰 수집 아키텍처

## 1. 최상위 제품 원칙

이 기능의 핵심은 **리뷰 관리를 위해 사용자의 반복 리소스가 들어가지 않는 것**이다.

- 사용자는 채널별 최초 연결과 사업장 매핑만 한 번 수행한다.
- 이후 수집, 중복 제거, 갱신, 분석, 분류, 대시보드 반영, 장애 재시도는 서버가 수행한다.
- CSV 다운로드, 텍스트 붙여넣기, 화면 캡처, 매일 동기화 버튼 클릭은 정상 운영 경로에 포함하지 않는다.
- 플랫폼의 공식 허가가 없는 로그인 자동화, 비공개 API 호출, 화면 크롤링, CAPTCHA 우회는 사용하지 않는다.
- 공식 연동이 확인되지 않은 채널은 `연동 가능`으로 표시하지 않는다.

사용자가 전혀 개입하지 않는다는 뜻은 **초기 소유권 확인까지 생략한다는 의미가 아니다**. 외부 사업장 데이터 접근에는 최소 한 번의 계정 승인 또는 제휴사 측 사업장 등록이 필요하다. 정상 연결 이후의 목표가 반복 입력 0회다.

## 2. 현재 가능성 판정

| 수집 방식 | 사용자 반복 작업 | 운영 안정성 | 정책 적합성 | 채택 여부 |
|---|---:|---:|---:|---|
| 플랫폼 공식 API/OAuth | 없음 | 높음 | 높음 | 핵심 경로 |
| 플랫폼 제휴 데이터 피드/웹훅 | 없음 | 높음 | 높음 | 핵심 경로 |
| 승인된 데이터 파트너 | 없음 | 중~높음 | 계약에 따름 | 대안 경로 |
| CSV/붙여넣기/OCR | 계속 필요 | 낮음 | 높음 | 비상 복구 전용 |
| 브라우저 로그인·화면 크롤링 | 없음처럼 보임 | 매우 낮음 | 위험 | 제외 |
| 모바일 알림 자동 추출 | 사용자 기기 의존 | 낮음 | 불명확 | 제외 |

2026-09-30 공개 문서 기준으로 네이버 스마트플레이스 및 캐치테이블의 **사업주 리뷰 원문을 외부 서비스가 자동 조회할 수 있는 공개 API**는 확인되지 않았다. 따라서 두 채널 모두 공식 제휴/API 권한을 확보하기 전에는 완전 자동 수집이 가능하다고 약속하거나 운영 크롤러를 배포하지 않는다.

네이버 스마트플레이스 자체의 리뷰 알림, 답글, AI 리뷰 통계 기능은 점주가 네이버 안에서 사용하는 기능이다. 이것만으로 TimeFit 서버가 리뷰 원문을 자동 수신할 수 있다는 의미는 아니다.

## 3. 목표 사용자 경험

### 최초 1회

1. 소유자가 `리뷰 채널 연결`을 누른다.
2. 공식 OAuth 또는 제휴 승인 화면에서 데이터 접근을 승인한다.
3. 연결할 사업장을 선택한다.
4. 초기 동기화 범위와 개인정보 안내를 확인한다.
5. 연결이 완료되면 서버가 과거 허용 범위를 자동 동기화한다.

### 이후 상시 운영

1. 스케줄러가 채널별 증분 동기화를 실행한다.
2. 신규·수정·삭제된 리뷰를 정규화한다.
3. 외부 ID로 중복을 제거한다.
4. 감성, 주제, 긴급도, 담당 업무 후보를 자동 분석한다.
5. 대시보드와 업무함을 갱신한다.
6. 실패하면 지수 백오프로 자동 재시도한다.
7. 일시 장애에는 알리지 않고, 재인증이나 장기 장애처럼 사용자 행동이 필요한 경우에만 알린다.

사용자는 매일 파일을 받거나 데이터를 붙여넣지 않는다.

## 4. 시스템 구조

```text
공식 API / 제휴 웹훅 / 승인된 데이터 피드
                    ↓
        source adapter (채널별)
                    ↓
 cursor 기반 증분 수집 → 원본 이벤트 보관 → 정규화
                    ↓
 external_id 중복 제거 및 수정·삭제 병합
                    ↓
 timefit_user_feedback_items
                    ↓
 분석 작업 큐 → 감성·테마·긴급도·업무 후보
                    ↓
 리뷰 현황 / 전체 리뷰 / 조치 업무함 / 연동 상태
```

### 채널 어댑터 계약

```ts
type ReviewSourceAdapter = {
  source: 'naver' | 'catchtable';
  connect(input: ConnectInput): Promise<ConnectionResult>;
  refreshCredential(connectionId: string): Promise<void>;
  pullChanges(input: {
    connectionId: string;
    cursor?: string;
    limit: number;
  }): Promise<{
    reviews: SourceReview[];
    nextCursor?: string;
    hasMore: boolean;
  }>;
  verifyWebhook?(request: Request): Promise<VerifiedEvent>;
};
```

공통 도메인은 공급자의 로그인 방식이나 응답 형식을 알지 않는다. 공식 연동 계약이 확보되면 해당 어댑터만 추가한다.

## 5. 서버 동기화 규칙

- 기본 실행: 채널별 4시간 간격. 공식 API 호출 제한에 맞게 조정한다.
- 증분 기준: 공급자 cursor 우선, 없으면 `source_updated_at`과 겹침 구간을 함께 사용한다.
- 멱등 키: `(organization_id, source, external_id)`.
- 수정 판정: 원본 `updated_at` 또는 정규화 본문의 SHA-256 변화.
- 삭제 처리: 실제 삭제 대신 `source_deleted_at`을 기록해 감사 이력을 유지한다.
- 재시도: 1분, 5분, 30분 간격으로 3회 후 degraded 상태로 전환한다.
- 재인증: 토큰 폐기·권한 회수처럼 자동 복구 불가한 경우에만 소유자에게 알린다.
- 비밀정보: 서버 암호화 저장소에 저장하고 브라우저 및 로그에 노출하지 않는다.
- 사용자 세션 쿠키와 비밀번호는 저장하지 않는다.

## 6. 연결 상태 UI

채널 카드는 다음 상태만 사용한다.

- `제휴 준비 중`: 공개/승인 API가 없어 아직 연결할 수 없음
- `연결 가능`: 공식 연동이 준비됨
- `동기화 중`: 최초 또는 증분 동기화 진행 중
- `정상`: 최근 동기화 성공
- `일시 지연`: 자동 재시도 중이며 사용자 행동 불필요
- `재인증 필요`: 사용자가 한 번 다시 승인해야 함
- `연동 중단`: 관리자가 의도적으로 연결 해제

각 카드에는 마지막 성공 시각, 다음 예정 시각, 최근 가져온 건수만 표시한다. 수동 `가져오기` 버튼을 기본 화면의 핵심 행동으로 두지 않는다. 운영 관리자 전용 `지금 다시 시도`는 장애 진단용으로만 둔다.

## 7. 구현 단계

### A. 즉시 구현 가능한 공통 기반

1. `review_source_connections` 테이블
2. 암호화된 credential 참조와 사업장 매핑
3. `review_sync_runs` 및 cursor 저장
4. adapter 인터페이스와 mock adapter
5. Cron 기반 증분 동기화 worker
6. 멱등 upsert, 수정·삭제 병합
7. 분석 큐와 자동 분류
8. 연결 상태·마지막 성공·오류 상태 UI
9. 운영 로그, 자동 재시도, 알림 억제 정책

### B. 외부 승인이 있어야 구현 가능한 채널 어댑터

1. 네이버 사업자용 리뷰 데이터 제공 여부 및 제휴 절차 확인
2. 캐치테이블 사업주/파트너용 리뷰 데이터 제공 여부 및 제휴 절차 확인
3. 데이터 범위, 보존 기간, 호출 제한, 답글 권한 계약 확인
4. 샌드박스 credential과 문서 수령 후 adapter 구현
5. 실제 사업장 승인 후 운영 전환

공통 기반 개발은 외부 승인과 병행할 수 있지만, 실제 리뷰 자동 수집 완료 조건은 B 단계의 공식 접근 권한이다.

## 8. 완료 기준

- 채널당 최초 연결은 10분 이내에 완료된다.
- 정상 연결 후 주간 반복 입력과 업로드는 0회다.
- 공식 소스에 생긴 리뷰가 합의된 SLA 안에 자동 반영된다. 기본 목표는 6시간 이내다.
- 같은 리뷰가 재수집되어도 중복 생성되지 않는다.
- 리뷰 수정·삭제가 다음 동기화에서 반영된다.
- 일시 오류는 자동 복구하며 사용자에게 불필요한 알림을 보내지 않는다.
- 사용자 행동이 필요한 오류는 원인과 해결 행동을 한 문장으로 제공한다.
- 공식 연동이 없는 채널은 준비 중으로 명확하게 표시한다.

## 9. 제품 결정

CSV, 텍스트 붙여넣기, OCR을 이용한 가져오기는 핵심 제품이 아니다. 필요하다면 운영 장애 시 과거 자료를 한 번 복구하는 관리자 도구로만 남긴다.

네이버와 캐치테이블 모두 공식 API 또는 계약된 데이터 피드가 확보되지 않는다면, TimeFit 안에서 두 채널의 완전 자동 리뷰 수집 기능은 출시하지 않는다. 그 상태에서 제공할 수 있는 것은 연결 대기 화면과 공통 자동화 기반까지다. 이는 사용자의 반복 리소스를 요구하는 반자동 기능을 완성품처럼 제공하지 않기 위한 결정이다.
