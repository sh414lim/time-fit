# E2E QA 계정 기반 전체 기능·플로우 테스트 시나리오

## 테스트 계정 구성

| 구분 | 표시 이름 | 사업장 | 역할 |
| --- | --- | --- | --- |
| QA 관리자 | E2E 관리자 | E2E 테스트 사업장 | 관리자 |
| QA 직원 | E2E 직원 | E2E 테스트 사업장 | 직원 |

계정 비밀번호와 이메일은 보안상 이 문서에 기록하지 않는다. 테스트 시작 전 각 계정으로 로그인 가능한 상태인지 확인한다.

## 0. 공통 준비

1. 관리자 웹, 직원 웹, 태블릿 화면을 각각 다른 브라우저 세션 또는 기기에서 연다.
2. 관리자 운영 설정에서 태블릿 출퇴근을 활성화하고 PIN을 설정한다.
3. QA 관리자와 QA 직원의 전화번호 뒷 4자리·8자리를 각각 등록한다.
4. 태블릿 URL에 QA 사업장의 `organization` 값이 포함됐는지 확인한다.

통과 기준: 모든 테스트 화면이 동일한 `E2E 테스트 사업장` 데이터를 사용한다.

## 1. 인증·역할·사업장 연결

### 1-01. 관리자 로그인

1. QA 관리자로 로그인한다.
2. 관리자 홈과 사업장명을 확인한다.
3. `직원 관리`, `운영 설정`, `급여 관리` 메뉴가 노출되는지 확인한다.

기대 결과: 관리자만 관리자 전용 메뉴와 사업장 데이터를 확인한다.

### 1-02. 직원 로그인

1. QA 직원으로 로그인한다.
2. `E2E 테스트 사업장` 연결 상태를 확인한다.
3. 내 홈, 내 스케줄, 출퇴근, 휴가 메뉴만 보이는지 확인한다.

기대 결과: 직원에게는 관리자 메뉴·설정·급여 메뉴가 보이지 않는다.

### 1-03. 세션 유지

1. 관리자와 직원 화면을 각각 새로고침한다.
2. 로그아웃되지 않고 역할·사업장 연결 상태가 유지되는지 확인한다.

## 2. 관리자 운영 설정

### 2-01. 태블릿 설정 저장

1. QA 관리자 → `운영 설정`으로 이동한다.
2. 사업장 표시명, 주소, 기본 휴게시간, 태블릿 PIN을 입력한다.
3. 저장 후 새로고침한다.

기대 결과: 모든 설정이 유지되고 태블릿 URL이 표시된다.

### 2-02. 태블릿 차단

1. 태블릿 출퇴근을 비활성화한다.
2. 태블릿에서 출퇴근 및 휴가 신청을 시도한다.
3. 관리자에서 다시 활성화한 뒤 재시도한다.

기대 결과: 비활성화 상태에서는 요청이 거부되고, 활성화 후에는 정상 진행된다.

## 3. 태블릿 출퇴근 → 관리자 조회

### 3-01. 직원 확인과 출근

1. 태블릿 `출퇴근` 탭에서 PIN과 QA 직원 전화번호 뒷 4자리를 입력한다.
2. `직원 확인` 후 표시된 이름을 확인한다.
3. `출근하기`를 누른다.

기대 결과: QA 직원의 출근 기록이 `tablet_phone_last4` 출처로 저장된다.

### 3-02. 관리자 출근 확인

1. QA 관리자 → `출퇴근 관리`를 새로고침한다.
2. QA 직원 상태와 실제 출근 시각을 확인한다.
3. `근무 중` 필터에서 QA 직원이 보이는지 확인한다.

기대 결과: QA 직원은 `근무 중`으로 표시된다.

### 3-03. 퇴근

1. 태블릿에서 동일 직원 정보를 입력한다.
2. 이름 확인 모달의 CTA가 `퇴근하기`인지 확인한다.
3. 퇴근한 뒤 관리자 화면을 새로고침한다.

기대 결과: 동일 날짜의 레코드에 퇴근 시각이 추가되고 관리자는 `퇴근 완료`로 확인한다.

### 3-04. 실패 시나리오

- 잘못된 PIN
- 존재하지 않는 전화번호 뒷 4자리
- 이미 퇴근한 직원 재퇴근
- 다른 사업장 URL에서 동일 번호 사용

기대 결과: 근태 기록이 생성·변경되지 않고 명확한 오류 안내가 표시된다.

## 4. 태블릿 휴가 신청 → 관리자 승인

### 4-01. 연차 신청

1. 태블릿 `휴가 신청` 탭을 연다.
2. PIN과 QA 직원 전화번호 뒷 8자리를 입력한다.
3. 미래 날짜를 선택하고 `연차`를 선택한다.
4. 신청을 완료한다.

기대 결과: QA 직원의 휴가 요청이 `tablet` 출처, `pending` 상태, `1일`로 저장된다.

### 4-02. 반차 신청

1. 다른 미래 날짜를 선택한다.
2. `오전 반차`, `오후 반차`를 각각 신청한다.

기대 결과: 각 요청이 `0.5일`로 저장된다.

### 4-03. 관리자 신청 확인

1. QA 관리자 → `휴가 · 연차 관리`를 연다.
2. 승인 대기 건수와 QA 직원 신청 항목을 확인한다.
3. 신청 행을 클릭해 상세 모달을 연다.

기대 결과: 직원명·휴가 유형·날짜·일수·승인 대기 상태가 일치한다.

### 4-04. 승인

1. 승인 메모를 입력한다.
2. `승인하기`를 누른다.
3. 관리자 화면을 새로고침한다.
4. QA 직원으로 로그인해 휴가 내역을 확인한다.

기대 결과: 양쪽 화면에서 `승인 완료`가 동일하게 표시되며 검토 이력이 저장된다.

### 4-05. 반려

1. 새 휴가 요청을 생성한다.
2. 관리자에서 반려 메모를 입력하고 `반려`한다.
3. QA 직원 휴가 내역을 새로고침한다.

기대 결과: 양쪽 화면에서 `반려`가 표시되고 승인 대기 건수에서 제외된다.

## 5. 알림 로그 및 카카오 알림톡

### 5-01. 발송 로그

1. 태블릿에서 휴가 신청을 완료한다.
2. Supabase `timefit_user_notification_logs`에서 해당 휴가 요청 로그를 확인한다.

기대 결과: 관리자 직원 수신 번호가 등록되어 있다면 `queued`, 미등록이면 `disabled`와 사유가 기록된다.

### 5-02. 실제 알림톡 연동 후

1. 승인된 카카오 알림톡 템플릿과 공식 딜러사 발송 키를 Edge Function Secret에 등록한다.
2. 새 휴가 신청을 만든다.
3. 로그가 `queued → sent`로 바뀌는지 확인한다.
4. QA 관리자 수신 번호의 카카오톡에서 템플릿 메시지를 확인한다.

기대 결과: 동일 요청에 알림톡이 한 번만 도착하고 메시지 ID가 기록된다.

## 6. 스케줄·직원·급여 화면 회귀

### 6-01. 스케줄

1. 관리자에서 QA 직원의 근무 일정을 추가한다.
2. 새로고침 후 일정이 유지되는지 확인한다.
3. QA 직원 `내 스케줄`에서 일정이 보이는지 확인한다.

### 6-02. 직원 상세

1. 관리자 `직원 관리`에서 QA 직원을 선택한다.
2. 부서·직책·근무·휴가 요약을 확인한다.

### 6-03. 급여

1. 관리자만 `급여 관리`에 접근 가능한지 확인한다.
2. 직원 계정에서 직접 URL 또는 메뉴 접근을 시도한다.

기대 결과: 직원은 급여 정보를 볼 수 없다. 급여 계산·CSV 실제 데이터 연동은 별도 범위로 기록한다.

## 7. 최종 판정

아래가 모두 충족되면 QA 계정 기반 1차 E2E 통과로 판정한다.

- [ ] 관리자·직원 역할과 사업장 분리가 유지된다.
- [ ] 태블릿 출근·퇴근이 관리자 화면에 반영된다.
- [ ] 태블릿 휴가 신청이 관리자 확인·승인/반려와 직원 화면에 동기화된다.
- [ ] 오류 입력·중복 처리·비활성 태블릿이 안전하게 차단된다.
- [ ] 알림 로그가 정확히 생성된다.
- [ ] 실제 알림톡은 딜러사 연동 완료 후 별도 최종 통과한다.
